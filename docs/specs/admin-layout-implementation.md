## 1. 全体原則 — Workspace と Form の2系統

写真は「本文」ではなく **作業面**。読みやすい行長のために幅を絞る原則は文章にだけ当てはまる。
写真一覧に当てはめると作業面が痩せるだけ。逆に設定の入力欄を全幅へ伸ばしても読みやすくならない。

**同じ PageShell を両方に使うのをやめる。** Shell（外枠）は共有し、その内側で
Workspace と Form の2系統に分ける。

### 適用画面一覧

| 画面 | 系統 | 理由と注意 |
|---|---|---|
| Library | Workspace | 基準となる画面。詳細欄・並べ替え帯・一括操作帯のすべてを持つ |
| ヒーロー（Gallery配置） | Workspace | 並べ替えが主目的。Library と同じ下部帯・同じ対象指定を使う |
| シリーズ / カテゴリ | **個別判断**（Workspace 寄り） | 一覧管理＋編集の混合。機械的に当てはめない。現時点の見立ては「一覧は Workspace の規則、1件の編集は Form の本文幅を持つ右または全画面の編集面」 |
| 設定（Settings） | Form | 節が多く画面が長い。左目次あり |
| プロフィール | Form | 目次は付けない（節が少なく画面が短い） |
| 料金プラン | Form | プラン項目が増えて4節を超えたら目次を検討。既定は目次なし |
| サービス | Form | 同上。項目の並べ替えを持つ場合、**その節だけ** Workspace の対象指定＋下部帯を借りる |

### 混合画面の判定基準（3つ以上当てはまれば Workspace）

1. 一覧の件数が画面1枚に収まらないことが常態か。
2. 並べ替え・一括操作・絞り込みのいずれかが主要な作業か。
3. 写真やサムネイルが判断材料になるか（文字だけで判断できないか）。
4. 1件あたりの編集項目が5項目以下で、その場編集が自然か。

逆に、1件の編集に文章・長文入力・複数の依存設定が含まれるなら Form 側の面を用意する。

## 2. 共通 Shell と各レイアウトの責務

### Admin Shell が持つもの

サイドバー（3グループのナビ・言語・ログアウト）／ヘッダー1行（現在地の見出し・件数・
画面外へ出る操作）／認証と読み込み失敗の扱い／アクセントと意味色のトークン供給／
未保存離脱の警告。

**Shell は本文の幅を決めない。** 最大幅・段組み・スクロール領域はレイアウト側の責務。

### Workspace の責務

- 全幅の作業面（**最大幅なし**）
- 作業帯1行（モード・検索・絞り込み・表示）
- **右＝見る**（詳細欄、文脈で開閉）。**閉じる手段は画面幅に関係なく必ず出す**
  — ×ボタン（分かる `aria-label`）と Esc の2経路。1200px 以上で詳細欄が
  静的な列になっても同じ。閉じたら選択中の写真を解除し、**空いた幅は作業面へ返す**。
  未保存の編集がある時だけ確認を出し、無言で捨てない。
  入力欄・select の操作中の Esc は詳細を閉じない（編集破棄の事故を防ぐ）
  （オーナー確定 2026-07-30、本番で閉じられない状態を確認）
- **下＝する**（一括操作・並べ替え、対象があるときだけ出現）
- グリッドのスクロール領域の所有
- **空の枠を常設しない**
- ツールはヘッダー1行＋作業帯1行の2階層のみ。**3段目を作らない**
- 1024px ではサイドバーを 64px に畳む。写真は 900px を下回らせない

### Form の責務

- 本文幅の管理（基準 720px）
- 節の開閉
- 変更検出（**節単位**）
- 保存・破棄・保存失敗の表示
- 長い画面のみ左目次（sticky）
- **Workspace と幅・段組みを共有しない**
- 右側の余白は空けたままにする（埋めない）

### 既存 PageShell の扱い

PageShell は**廃止せず、Form 用の部品として残す**。現在の dual-width のうち
広い側（＝Workspace 用の分岐）を削り、狭い側だけを Form の本文幅として使う。
**Workspace は PageShell を通さない。**

移行中に両方を通す画面が出ないよう、**1画面につき必ずどちらか一方を選ぶ**。

## 3. ツールバーの4層再編（Library）

現状は「いまどこにいるか」「何をするモードか」「画面を出る操作」が同じ見た目で混ざる。
役割で4層に分け、見た目を層ごとに変える。

| 層 | 内容 | 見せ方 |
|---|---|---|
| 1層 | 現在地・件数（`Library` / `462 photos / 非公開 18`） | **見出しの大きさ**で示す。ボタンにしない |
| 2層 | 作業モード（閲覧・選択・並べ替え） | 作業帯の左端。画面内で唯一の切替器 |
| 3層 | 探す（検索・絞り込み・表示） | 作業帯の右。文字主体、枠は検索だけ |
| 4層 | 画面を出る操作（取り込み・サイトを見る） | ヘッダー右端。作業帯に混ぜない |

ゴミ箱・Table・保存した視点は「絞り込み／表示」の中へ畳み、**常設をやめる**。
検索は折りたたみの中から出して常設する。

**モード名は「閲覧｜選択｜並べ替え」を採用**（現行の「通常／選択／並べる」から変更）。

## 4. Library の状態遷移

モードは3つ。並べ替えモードだけが内部に2状態を持つ。
**選択（`selectedIds`）と並べ替え対象（`reorderTargetId`）は別の状態として保持し、
互いに書き換えない。**

| 状態 | 画面 | 入る／出る |
|---|---|---|
| 閲覧 | 下部帯なし。写真クリックで右の詳細欄が開く | 既定。他モードから戻ると必ずここ |
| 選択 | 丸のチェックが出る。1件以上選ぶと下部帯（一括操作）が出る。詳細欄は閉じる | モード切替器。0件になると帯は消えるがモードは維持 |
| 並べ替え・**対象なし** | 台紙が一段深くなる。写真上はつまみ1つ。下部帯なし（PCは案内文を作業帯に、スマホは 54px の案内1行） | モード切替器で入る。抜けるときは確認なし（順序は移動時に保存済み） |
| 並べ替え・**対象あり** | 対象に外枠＋順位＋ピル。下部帯が出る。移動は即時適用で対象は保持 | 写真クリック／Enter で入る。Esc・「選び直す」・別の写真クリックで対象が移る |

### 遷移の規則

- **選択 → 並べ替え**: `selectedIds` はそのまま保持し、表示しない。戻ると選択が復帰する。
- **並べ替え → 他モード**: `reorderTargetId` と `lastMove` を破棄。保存待ちがあれば
  完了を待ってから切り替える。
- **並べ替え中の画面遷移**: サイドバーの他項目は無効。ブラウザバックは未保存があれば警告。
- **並べ替えモードでは複数選択を行えない。** 対象は常に0または1件。

### 4-1. 【修正】絞り込み中の並べ替え — 全面禁止にしない

> **オーナー確定 2026-07-29。Claude Design 版の「絞り込みが有効なときは並べ替えに入れない」を
> この節で置き換える。現行の承認済み挙動を維持する。**

Claude Design の実装仕様は「絞り込みが有効なときは並べ替えに入れない」と書いているが、
これは**採用しない**。現行実装（`admin-shared.ts` の `reorderLockReason`、
`admin.tsx` の `publicReorderLockCause`）が持つ **シリーズ単独絞り込みの例外を維持する**。

#### 並べ替えを禁止する条件（ロック）

1. 検索中
2. **複数条件**の絞り込み中
3. 表示順が手動以外（`librarySort !== "manual"`）
4. 公開ギャラリーの並び順が手動以外（`gallerySortOrder !== "manual"`）、
   および設定の読み込み中・読み込み失敗
5. ゴミ箱や特殊表示
6. **表示集合と保存対象の対応を安全に確定できない状態**
   （`reconstructManualPhotoOrder` が `ok: false` を返す場合を含む）

ロック時は理由を作業帯に文字で出す（「絞り込みを解除してください」等）。
**理由は1箇所にまとめる。**現行のように複数の帯へ重複表示しない。

#### 例外 — シリーズ単独の絞り込みでは並べ替え可能

- シリーズだけを1つ絞り込んでいる状態（`onlySeriesFilter`）は**並べ替えできる**。
- そのとき **前へ／後へ／先頭へ／末尾へ／番号指定は「シリーズ内順位」として扱う。**
  「07 / 462 番目」の表示も、シリーズ単独時は**表示中シリーズ内の順位／シリーズ内総数**を出す。
- **保存時は既存の全体順への差し込み規則を維持する。**
  `lib/reorder.ts` の `moveRelativeToViewNeighbor` 系（表示中の隣接／端に対して移動を表現し、
  全ID順へ適用する）をそのまま使う。**表示中のシリーズだけを0番から振り直さない。**
  振り直すと他の写真と順位が重なる。
- **`lib/reorder.ts` を二重実装しない。** 下部帯のボタンもドラッグも、同じ関数を通す。

#### 壊してはいけない回帰テスト

`reorderLockReason` の4状態（手動以外 / 複合フィルター / シリーズ単独例外 / リセット後）を
固定している既存テストを壊さない。ロック条件を増やす場合も、
**シリーズ単独例外が `null`（ロックなし）を返すことを変えない。**

### 4-2. 保存中・保存失敗時に安全に終了する規則

- **保存中に「終了」を押した場合**: 即座に閉じず、上部に「保存しています…」を出して
  ボタンを保存待ちにする。完了したら閉じる。**2秒を超えたら**「このまま待つ／中止して残る」を
  選べるようにする。
- **保存に失敗した状態で「終了」**: 閉じずに引き止める。「保存できていない移動が n 件あります」
  ＋「もう一度保存／変更を取り消して終了」の2択。取り消しは**楽観更新のロールバックと同じ経路**を使う。
- **通信が復帰しない場合**: 3回失敗で自動再試行をやめ、上部の帯を danger の線1本＋文字にする。
  **全画面を赤く染めない。**
- **失敗した移動**は元の位置へ戻したうえで、その写真に danger の細枠を残す（どれが戻ったか分かるように）。
- **スマホでは「終了」が唯一の戻り道**なので、上記の引き止めはシートではなく上部帯に出し、
  写真領域を塞がない。
- **未保存離脱の警告と二重に出さない。片方に寄せる。**

## 5. 並べ替えの表示層

### 5-0. 状態

```
reorderTargetId: number | null   // selectedIds とは別に持つ
lastMove: { id, from, to } | null // 「直前の移動」と Undo が読む
```

- 並べ替えモードに入っても `selectedIds` は保持し、**表示しない**。
- 並べ替えモードを抜けるとき `reorderTargetId` と `lastMove` を破棄する。
- 順序の保存は**既存の楽観更新＋競合検出＋ロールバックのまま**。

### 5-1. 写真の上に残すもの／載せないもの

| 区分 | 内容 |
|---|---|
| **残す** | ドラッグのつまみ **1つだけ**（PC 24px／スマホ 28px、左上 6px、白82%地）。対象のときだけアクセント色 |
| **対象のときだけ載せる** | 外側枠 2.5px（offset +2px、写真を隠さない）／右下の順位チップ（塗りアクセント・白文字）／右上の「動かす写真」ピル／元の位置に破線の空枠 |
| **載せない（撤去）** | 常時の順位帯・4方向ボタン・番号ボタン・Undo |

- hover した写真だけに順位と「クリックで動かす写真に」を出す（**タッチでは出さない**）。
- 位置は**行の先頭の開始番号**（`001 —` / `006 —` / `011 —`）で掴む。
- 「選択」と「並べ替え対象」を形と枠の位置で区別する:
  **選択＝内側の枠＋丸のチェック／並べ替え対象＝外側の枠＋角の番号。**
- 上部に「07 番の写真を動かしています」を文字で重複させ、色が見えない人にも伝える。

### 5-2. 下部帯の確定仕様

| 項目 | 仕様 |
|---|---|
| **出現条件** | 並べ替えモードで `reorderTargetId !== null` のときだけ。**対象なしでは描画しない**（空の帯を置かない） |
| **重ならない扱い** | 写真の上に重ねない。グリッドのスクロール領域の高さを帯の分だけ縮め（PC 68px／スマホ 150px、いずれも基準）、最後の行まで見えるようにする。実装は「通常フロー」でも「fixed＋同じ高さの padding-bottom」でも可。**条件は、帯の下に写真が隠れないこと** |
| **中身（順序固定）** | ① 対象のサムネイル（PC 64×44px）② タイトルまたはファイル名（1行・省略記号）③ 現在順位「07 / 462 番目」④ 先頭へ・前へ・後へ・末尾へ ⑤ 番号指定（入力＋「動かす」）⑥ 直前の移動の文＋元に戻す ⑦ 選び直す。**スマホも同じ順序で、⑥⑦は下段へ** |
| **詳細欄との関係** | 並べ替え中は詳細欄を**閉じる**（初期実装）。識別は帯のサムネイル＋タイトル＋順位のみ |
| **押した後の挙動** | 移動は即時適用（楽観更新＋失敗時ロールバック）。**対象の選択は保持し、連続で押せる。** 移動後は対象が画面内に留まるようスクロールを追随（`scrollIntoView` は使わず、必要量だけスクロール位置を加算） |
| **端・範囲外** | 先頭／末尾では該当ボタンを無効化し、理由を `aria-disabled` と文字で示す。番号指定は 1〜総数の外なら入力欄の下に静かな注意を出し、ボタンを無効化。**全画面を染めない** |
| **現れ方** | 120ms で下から入る。`prefers-reduced-motion` では即時表示。帯が出たことを**作業帯の文でも重複して示す**（案Cの弱点「気づきにくさ」への対処） |
| **ドラッグの併存** | 写真上のつまみは残す。**近距離はドラッグ、長距離は帯。** 帯はドラッグの代替ではなく併存。挿入位置はアクセント色の細い縦帯で示す |

### 5-3. 選択モードの下部帯（同じ器を使う）

一括操作（公開・非公開・カテゴリ変更・ゴミ箱へ）も**同じ下部帯**に出す。
中身は「n 件を選択中」＋操作＋「選択を解除」。
場所と現れ方を並べ替えと共通にすることで、**下＝する**の規則が学習される。

### 5-4. キーボードと読み上げ

- グリッドは `role="listbox"`、写真は `option`。
- `Enter` / `Space` で対象指定、`Esc` で解除。
- 対象があるとき `←` `→` で前後、`Home` / `End` で端へ。フォーカスは対象に追随する。
- 移動のたびに `aria-live="polite"` で「9番目から7番目へ移動しました」を通知。
- 帯を開閉してもフォーカスを失わない。閉じたら元の写真へフォーカスを戻す。

## 6. レイアウト規則（PC / 1024px / 768px / 390px）

「決定」＝この値で進める。「基準」＝実画面で調整可。

| 幅 | Workspace | Form |
|---|---|---|
| **≥1200px** | サイドバー 236px（基準）。作業面は残り全幅、内側余白 32px（基準）。詳細欄 400px（基準）を右に**重ねず並べる** | 目次 208px＋間隔 40px＋本文 720px（基準）。右の余白は空けたまま |
| **1024–1199px** | サイドバーを **64px の記号列に畳む（決定）**。作業面は **900px を下回らせない**。詳細欄を開くときは**重ねる**（並べない） | 目次 184px＋本文 640px（基準） |
| **768–1023px** | サイドバーは 64px のまま。詳細欄は全画面のシートへ。下部帯は横1段のまま | 目次を本文の上へ移し、横スクロールの1行にする。本文は全幅（左右余白 24px） |
| **<768px（390px 基準）** | サイドバーなし。下部3グループナビ 62px。**並べ替え中はナビを完全に隠す（決定）。** グリッドは2列、余白 12px | 上部固定1行の節表示＋一覧シート。本文は全幅。保存バーは下に浮かせる |

### 6-1. 1024px の 64px サイドバー

- **記号だけにしない。** 44×44px の当たり判定の中に記号（20px）＋10px のラベルを縦に置く。
  「写真 / 見せ方 / サイト」の3語は 64px 幅に収まる。
- **グループの見出しだけを常時表示**し、子項目（Library・ヒーロー…）は畳む。
  子が2つ以上あるグループは、押すとその場に展開せず、**右へ 200px のポップオーバー**を出す
  （作業面を押しやらないため）。
- **ツールチップはラベルの言い換えを出さない。** 同じ語を繰り返す吹き出しは付けない。
  ポップオーバー内は通常のリストで、ツールチップ不要。
- キーボード: Tab でグループ間、矢印でポップオーバー内を移動。フォーカスリングはアクセント色2px。
- 現在地は左端の3px の縦線＋背景 8%（1440px と同じ表現）。**畳んでも示し方を変えない。**
- 畳む／開くの状態は保存し、次回も維持する。**1200px 未満では常に畳む**
  （ユーザーが開いた場合は一時的に重ねて開く）。

### 6-2. Form 本文 720px を広げてよい場合

720px は基準。次の節は本文幅を超えて広げられる（**節単位で `wide` を指定**）。

1. 画像の配置・トリミング・焦点位置を扱う節（最大 1040px）
2. プレビューを横に並べる節（本文 720px＋プレビュー 320px）
3. 表形式の項目が5列以上になる節

**広げるのはその節だけで、前後の節は 720px に戻す。目次の位置と幅は変えない。**

## 7. スマホ専用の並べ替えワークスペース（<768px）

**下部ナビを薄く残す案は採らない。並べ替え中は完全に隠す（決定）。**
薄いナビは「押せるのか押せないのか」が曖昧なまま残る。隠せば迷いが消える。

| 部位 | 高さ | 中身 |
|---|---|---|
| 上部 | 52px | 「並べ替え」／未保存件数・元に戻す・**終了** |
| 下部・対象なし | 54px | 案内1行（「動かす写真を1枚タップしてください」）。**ボタンを置かない** |
| 下部・対象あり | 150px（基準） | §5-2 の中身。⑥⑦は下段。**押せる要素はすべて 44px 以上** |
| 下部ナビ | **0（非表示）** | 並べ替えモードの間だけ完全に隠す |

- 未選択 54px → 選択済み 150px は**高さだけが変わる**。別要素の出し入れにしない。
- グリッドは**2列に固定**（現行の判断を維持）。
- **戻り道は「終了」だけ。** だから §4-2 の引き止めが必要になる。
- **390px で下部帯の操作が1つも欠けないこと**を自動テストで固定する。
  現行の「実効幅が狭いと先頭へ・末尾へが消える」挙動は、帯へ移すことで解消する。

## 8. Settings 目次と保存状態

| 項目 | 仕様 |
|---|---|
| **目次を出す基準** | 独立した節が**5つ以上**、かつ画面の高さが1画面の**2倍を超える** Form。Settings は該当。プロフィール・料金プラン・サービスは既定で目次なし（節が増えたら基準で再判定） |
| **目次の中身** | 節名／現在地（3px の縦線＋背景8%）／変更ありの点（accent）／保存できなかった節の点（danger）。点は 6px の丸で、節名の右端に揃える |
| **保存バーの位置** | **PC は目次の下に同居（浮かせない）。**「未保存の変更 n 件」＋節名の列挙＋保存／破棄。失敗時は danger の点＋「原因の節へ移動」。スマホは従来どおり下に浮かせる |
| **本文の中身** | **目次で選んだ1節の入力欄だけ**（§8-1 で確定）。節名の一覧を本文へ並べない |
| **変更の検出単位** | **節。** 節の中のどれか1項目でも初期値と異なれば「変更あり」。**本文に出ていない節の印は目次（PCは左列・スマホは上部1行と節一覧シート）に出し**、開かずに場所が分かるようにする |
| **保存の状態** | 未保存 → 保存中（ボタンを保存待ちに、破棄を無効）→ 成功（success の点＋時刻を残す。**トーストで消さない**）／失敗（失敗した節を**自動で本文へ出し**、原因の項目に danger の枠。バーに「どこが」「次に何を押すか」）。**全画面を染めない** |
| **読み込み失敗** | 現行の `SettingsLoadError` を**構造・文言ともそのまま維持**。色だけ Tailwind の琥珀から `--admin-warning` に置換。**編集を許さない判断も維持** |
| **スマホの目次** | 上部固定1行に「節名＋現在地の点＋他の節の警告点」を集約。「切り替え」で全節の一覧シート（節名＋変更あり／保存できず）。**スクロールせずに問題箇所が分かり、1タップで飛べる**ことが要件 |

### 8-1. 【修正】本文は目次で選んだ1節だけを出す

> **オーナー確定 2026-07-30（本番確認後）。この節が、同じ文書内の

本番の Settings は、左に19節の目次があり、右の本文にも同じ節名＋「n項目を設定」が
19行並んでいた。**同じメニューが二重に見え、本文の幅も狭い。**採用する形は次の1つ。

- 左の19節目次は**そのまま維持**する（ナビゲーションはここだけ）。
- **本文は、目次で選んだ1節の実際の入力欄だけを描く。** 節名と要約を並べた

- 節を切り替える器は目次だけ。PCは左列、スマホは上部固定1行＋節一覧シート。
- **変更ありと保存できなかった節の印は目次に残す。** 本文に出ていない節の状態も
  目次で分かることが要件（表の「変更の検出単位」を参照）。

- `SettingsLoadError` の**編集させない判断と文言は維持**（この節は変えない）。
- グループ見出し（General / Integrations / Design）は、**現在の節を含むものだけ**描く。

  390px で目次が本文を押し下げないことを Playwright で固定する。

**不採用**: 19節を開いたまま縦に積む案（本文が極端に長くなり、スマホで

## 9. アクセントカラーと意味色の分離

**意味色（danger / warning / success / info）はアクセントから完全に独立し、
アクセント設定の影響を受けない。**

### 9-1. トークン

| 変数 | 役割 | 現状 |
|---|---|---|
| `--admin-accent` | Admin の差し色。**Admin 専用キー（`adminAccentColor`）から引き、未設定なら公開サイトの `--accent-color` にフォールバック** | あり／要分離 |
| `--admin-accent-rgb` | 透過用。8%＝現在地の面、12%＝ホバー、16%＝文字選択、30%＝focus の輪 | あり |
| `--admin-accent-line` | 線・枠・挿入位置。**既定 2.5px**（灰色プリセットでも見えるように 2px から引き上げ） | **新設** |
| `--admin-accent-fill` | 順位チップ・ピル（白文字が乗る濃さ） | **新設** |
| `--admin-danger` | 取り消せない操作・保存失敗。アクセントと無関係に固定 | あり |
| `--admin-warning` | 注意（ゴミ箱の期限、欠番、読み込み失敗の案内） | **新設** |
| `--admin-success` | 保存済み・完了 | **新設** |
| `--admin-info` | 情報 | **新設** |

**初期アクセントは `#5b7fa0`（淡いくすみ青）。** 紙色に対して約 4.6:1 で、文字にも使える。

### 9-2. アクセントを出す場所／出さない場所

**出す（線と小面積のみ）**
写真の選択枠（2pxの輪・**未配線**）／並べ替えの挿入位置（**未配線**）／移動対象の印（**未配線**）／
現在地（配線済み）／focus の輪（配線済み）／入力欄の focus 境界（配線済み）／
文字選択の下地（配線済み）／変更ありの点・変更した節の左端2px／リンクとホバー。

**出さない**
大面積の背景・帯／本文の文字／写真に被る色面（**選択の塗りつぶしは不可、輪のみ**）／
**すべての主動作ボタン（保存・終える・取り込みは墨のベタのまま）**／
危険・警告・成功の意味色／ゴミ箱・完全削除の面。

### 9-3. 撤去するもの

- `styles.css` の `[class*="bg-red"]` → アクセント色への一括変換を**撤去**。
  これが「完全に削除ボタンの背景が淡い青になる」原因。
- 緑・琥珀の重複系統（暗背景用と明背景用が同居）を各1つへ寄せる。
- 写真の選択枠 `ring-[#aaa]`、サービスの `bg-[#ddd]`、`#666` / `#888` の直書きをトークンへ。
- ドロップ表示の `shadow-[0_0_10px_rgba(255,255,255,0.75)]`（白い発光）を削除。

### 9-4. 設定画面での選ばせ方

**自由なカラーピッカーを出さない。** コントラスト基準（線と小面積は 3:1、文字にも使うなら 4.5:1）を
満たす候補を数点だけ出す形にする。自由入力を許すと必ず読めない設定が生まれる。

**`settings` の新規キーは4箇所を同期する**（`AGENTS.md` の不変条件）:
`settings-preview.ts` の台帳 / API `/settings` の default /
`provider.tsx` のDB適用 `useEffect` / 同ファイルの `handlePreviewMessage`。

## 11. 壊してはいけない既存挙動

| 守るもの | 理由・注意（壊れたときの症状） |
|---|---|
| **順序変更の楽観更新＋失敗時ロールバック** | 下部帯へ移しても**経路は同じものを使う。二重実装しない**。壊すと画面と保存結果が食い違う |
| **API の完全性検査と競合拒否** | 重複・未知ID・抜け・古いタブの上書きを拒否している。外すと複数タブで順序が壊れる |
| **`sortOrder` からの手動順の再構成** | 受け取り配列をそのまま信じない。外すと撮影日順が `sort_order` として保存されうる |
| **公開順ロック（`gallerySortOrder` が手動以外なら禁止／読込中・失敗を区別）** | 外すと公開側に出ない無駄な並べ替えができてしまう |
| **シリーズ単独例外と全体順への差し込み**（`lib/reorder.ts`） | 表示中のシリーズだけを0番から振り直すと、他の写真と順位が重なる |
| **直接 Undo（トーストを待たずに戻せる）** | 位置が帯／上部へ移るだけ。**機能は削らない** |
| **番号を指定して移動** | 462枚では不可欠。**撤去せず帯へ移すだけ** |
| **保存中の連打拒否** | 外すと古い順序を元にした保存が後勝ちする |
| **大一覧の描画範囲を絞る仕組み**（`computeVirtualGridWindow`） | 外すと462枚を同時描画して重くなる。**帯の高さぶんスクロール領域が縮む点を計算に入れる** |
| **「今回追加」を並べ替えモードで隠し、ID集合は保つ挙動** | 消すと取り込み後の目印が失われる |
| **`SettingsLoadError` の編集させない判断** | 初期値を利用者の設定として見せない。**文言も維持。色だけ置換** |
| **settings の4箇所同期** | Admin 用アクセントキーを増やすとき、同期漏れが最も起きやすい |
| **未保存離脱の警告** | 並べ替え中の「終了」引き止めと**二重に出さない。片方に寄せる** |
| **ドラッグでの並べ替え** | つまみは残す。**帯はドラッグの代替ではなく併存** |
| **選択の保持** | モードを行き来しても `selectedIds` を消さない。**並べ替え対象と混ぜない** |
| **非公開・ゴミ箱・下書きの区別** | レイアウト変更で表示が落ちやすい。**写真の外に文字で示す方針は維持** |
| **公開サイト側の `--accent-color`** | Admin 用キーの追加で公開サイトの見た目を変えない。既定は共通のまま |
| **カテゴリ・シリーズ・料金の保存中停止と失敗時復帰** | この3画面は保存整合性に問題なし。触らない |
| **撮影日が同じ写真で元の手動順を維持する安定ソート** | 外すと同一時刻の写真が不安定に並ぶ |
| **並べ替え時にスマホを2列へ固定する判断** | 密度を落として操作を通す考え方は正しい |
| **PageShell の 880 / 560 の2幅と4段の文字トークン** | 04・06 で Form 側へ寄せるまでは維持 |

## 13. 不採用（記録として残す）

- **案A（並べ替え操作欄を右に常設）** — 1024px で写真が 612px まで落ち、1行3枚になる。成立しない。
- **案B（選んだ時だけ右欄）** — 押した瞬間に列が組み直され、押した写真を見失う。並べ替えでは致命的。
  overlay 方式なら跳ねは消えるので、「操作は対象の近くに」を優先する場合の次点。
- **案B（左列常設）** — 管理機能を主役にする配置で、目標と逆向き。
- **Finder 型の独立ビュー** — オーナー指示により不採用。
- **アクセントの自由なカラーピッカー** — 必ず読めない設定が生まれる。
- **主動作ボタンのアクセント色化** — 色を変えるたび画面の重心が動き、写真と競合する。
- **「選んだ写真の前／後へ移動」** — 対象を再度探す状態管理が増える。「何番目へ移動」だけにする
  （`library-reorder-safety.md` で確定済み）。
- **絞り込み中の並べ替えを全面禁止すること** — §4-1 のとおり。シリーズ単独例外を維持する。

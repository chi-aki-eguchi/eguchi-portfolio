# 配布を「もっと便利にする」アイデア（優先度表）

配布版（テンプレート／コンシェルジュ）を、受け取る人にも秋さんにも楽にするための
アイデア一覧です。**実装の指示書ではなく、秋さんが「次に何をやると一番効くか」を
選ぶための表**です。上から順におすすめ度が高い並びにしています。

列の意味:

- **効果**: 誰が、どう楽になるか。
- **楽になる度**: ★3 = 体験が大きく変わる / ★1 = あれば嬉しい。
- **重さ**: 実装の手間（軽 / 中 / 重）。
- **着手目安**: P0 = 早めに効く / P1 = 次 / P2 = 余力で。

|---|---|---|---|---|---|

## まず効くと思う3つ（おすすめ）

1. **デモサイトURL** — 販売・紹介の場で「これです」と見せられる効果が大きく、実装は軽い
   （使い捨てではなく、固定の閲覧用デプロイを1つ用意するイメージ）。
2. **テンプレ変数の説明文＋OGP画像** — デプロイ画面と一覧の「初見の分かりやすさ」を、
   軽い手間で底上げできる。post-deploy-guide のつまずきも前倒しで減らせる。
3. **公開URL作成のつまずき対策** — 手順④は実際に一番止まりやすい所。テンプレ側で
   ドメインを自動発行できれば、ガイドの説明そのものを減らせる（要 Railway 側検証）。

## メモ

- 6（ウィザード）と 9（バックアップ）は効果は高いが重い。先に軽い 1〜3 で体験を底上げし、
  反応を見てから着手する方が費用対効果が良い。
- どれも「写真が主役・静けさ」を壊さない範囲で。派手なオンボーディングにはしない
  （`DISTRIBUTION.md` の完成度原則）。
- 着手が決まったものは、個別に仕様を起こしてから実装する。

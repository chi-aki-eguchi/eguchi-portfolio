### B-23. `/gallery` の骨組みが 61px 押し下げられ、たまに版面のズレ検査が落ちる 🟠 出所まで実測済み（2026-08-31）

`public-scroll-stability.spec.ts` の「ギャラリーをゆっくり読む速さで送る」が
通し実行でときどき落ちる（上限 0.1 に対して実測 0.1576）。これまで「たまに
落ちる検査」として retry で流していたが、**出所を名指しできた。**

    div.gallery-skeleton  y 185 → 246（61px 下がる）／高さも縮む

上に居るもの（絞り込みの帯など）が中身を受け取って高くなり、その下の骨組みを
押し下げている。**骨組みは「場所を先に取る」ためのものなのに、自分が押されて
いる**ので、場所取りとして仕事をしていない。

**測り方**（値ではなく犯人を出す）: `PerformanceObserver` で `layout-shift` を
拾い、各エントリの `sources[].node` の tagName と class、`previousRect` →
`currentRect` を並べる。数値だけ見ていると原因に辿り着けない。

**2026-08-31 に「開いた瞬間の順番」を直した際、この検査が1回落ちた。**
その変更のせいではないことを確認済み: 変更を外した状態で3回とも通り、上の
出所にナビは一度も現れない。**混同しないこと。**

**2026-08-31 追記: ズレは1つではなく2つで、23ms違いで連続して起きている。**
手元の開発サーバで、`main` 配下の要素の top と高さを rAF ごとに追った実測:

    1419ms  h1        top=169 h=15 → top=79 h=11   設定が届いて字が小さくなり90px上がる
            骨組み           279 → 185             つられて上へ94px
    1442ms  骨組み           185 → 246             23ms後、今度は下へ61px
            h2             1017 → 1078            同じだけ下がる

- **1419ms のぶん**: `pageTitleStyle` が届いて見出しの型が変わる。既定で描いて
  から本来の設定で描き直しているので、その差が版面に出る。
- **1442ms のぶん**: 61px の何か（絞り込みの帯とみられる）が骨組みの上に入る。

**どちらも「設定・カテゴリが後から届いて、上にあるものの高さが変わる」型。**
2026-08-31 にナビで直したのと同じ（`Layout.tsx` の `chromeReady` /
`.site-chrome-reveal`）。**器は直したが、ページの中身は直していない。**

直すなら、ナビと同じ考え方で「確定するまで描かない・場所だけ取る」。ただし
**場所取りは高さが読めないと効かない**（絞り込みの帯は件数で2段になる）。
`min-height` では効かない——箱は下限を超えて伸びる。

**測り方**（値ではなく犯人を出す）: `main` 配下の要素の `getBoundingClientRect()`
を rAF ごとに拾い、前回と違う `top`/`height` だけを時刻つきで出す。
`layout-shift` の `sources[].node` と併せると、押した側と押された側の両方が分かる。

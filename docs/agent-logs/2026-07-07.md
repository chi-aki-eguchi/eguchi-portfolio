# 決定ログ 2026-07-07 — デザイン統一+質感・使用感の底上げ(Claude Code / Fable5)

タスク: 公開サイトと管理画面のデザイン統一、質感・高級感・使用感の底上げ(Driver = Claude Code)。
成果コミット: `f9af998` / `fda2cd4` / `8aae854`(ローカルのみ。push はオーナーの手で)。

## Phase 0: 既知バグ確認

- **選んだ方針**: コード変更前に該当 smoke 4本で現状確認。
- **結果**: 「スタイル変更が反映されない」(ライブプレビュー競合 #3)は修正済みで
  `admin-live-preview` 通過。「スクロール時のちらつき」は Codex の 2026-07-06 修正が有効。
  関連箇所(`.admin-glass` の GPU 安定化・仮想グリッド計測・`[data-virtualized]`)には
  本タスクで一切触れないことを最初に決めた(Codex の作業と衝突させないため)。

## Phase 2: トークン設計

- **選んだ方針**: 「トークン名を全サイト共通、値は現行維持(ゼロ視覚回帰)」。
  admin が確立済みの語彙(--dur-_/--ease-_/--radius-_/--shadow-_)を :root へ昇格し、
  公開側の editorial なテンポは同じ語彙の拡張トークン
  (--dur-hover/caption/lift/reveal/hero/drift/breathe、--ease-expo/quart/exit)で表現。
  admin は影のみ ink 由来で再スコープ。
- **迷った点**: 公開と admin の motion 値を「同じ値」に統一するか。
  → しない。公開=ゆっくり上品(design-spec §6 の 500-700ms)、admin=操作系の機敏さ
  (100-320ms)はブランドの表と裏として意図的な差。**体系(名前)の統一**を統一と定義した。
- 写真の影はライト/ダーク双方で黒基調を維持(印画紙は光らない)。ダークは深い影+
  ヘアラインで分離する方式をトークン(--shadow-photo)に吸収。

## Phase 3: 適用

- **admin 一掃の範囲判断(最大の迷いどころ)**: 旧ダークテーマの任意値クラスは約1,100箇所。
  ただし CSS の「救済セレクタ」(`[class*="bg-[#333]"]` 等)と button リセットが
  !important で被さる構造のため、機械置換が安全なのは
  「救済でマッピングが確定している素の(バリアント接頭辞なし)クラス」のみと分析。
  - 置換した(約800箇所): bg 12種→paper/-soft、border 4種→line、text 10種→ink/muted
  - 残した: `hover:`/`focus:`/`placeholder:` 付き(現在は救済で実質無効=挙動維持が必要)、
    `bg-[#555]`/`bg-[#888]`(「選択中/プライマリ」のセマンティックマーカー)、
    未救済の生値(ステータス色、写真上のオーバーレイ)
  - 救済セレクタ層は安全網として残置。撤去は「残りの置換+マーカーの класс化」とセットで
    別タスク(下記「要相談/次回候補」)。
  - **検証**: 全9タブ × desktop/mobile の pixelmatch = 0%(mobile のみ 0.01% の誤差)。
- **admin-login**: 第3のスタイル(暗黒+金 #c8a96e)を廃し、atelier の紙とインクへ。
  `.admin-atelier` クラスは smoke のログイン検知に使われているため意図的に使わず、
  共有トークン参照の `.admin-login` として実装(ライト/ダーク自動追従)。
- **公開側ダーク追従漏れの修正**: top.tsx ヒーロー各バリアントの #aaa/#888/#1a1a1a/bg-[#eee]、
  photo-card の LQIP プレースホルダ #ebebeb(→ --photo-placeholder)、ヘッダー hairline、
  ::selection、スクロールバー。写真上の白文字(#fff+text-shadow)と immersive の
  ダークフォールバック #2a3a3a は「写真アンカー」なので意図的に非追従のまま。

## Phase 4: 磨き込み

- Gallery: スケルトン(6枚・写真プレースホルダ調・pulse は reduced-motion で静止)+
  取得失敗時の「写真を読み込めませんでした + Retry」(既知の fail-quiet 課題 #36 の解消)。
- admin Categories/Series/Pricing にスピナー追加(既存 Hero/Service/Settings パターンに統一。
  findings.md P2 課題の解消)。
- Layout の nav/footer ホバーを JS(onMouseEnter/Leave)から CSS へ。:focus-visible にも
  同じフィードバックが付いた。**小さな意図的変更**: footer リンクのホバー不透明度を
  0.48/0.50/0.55 → 0.55 に統一、モバイルメニューのアクティブ色をデスクトップと同じ
  accent-color 参照に統一(アクセント未設定時は従来と同じ 0.70 フォールバック)。

## 要相談 / 次回候補(コードは変更していない)

1. **救済セレクタ層の撤去**: 残りのバリアント付きクラス(約270箇所)を意味のあるトークン
   ホバーに置換し、`bg-[#555]`/`bg-[#888]` マーカーを `admin-btn--primary` 等の
   セマンティッククラスへ移行した後、styles.css の救済ルール約40本と `.admin-atelier`
   4〜5連結の specificity 迷宮を解体できる。挙動確認が1箇所ずつ必要なため今回は見送り。

3. 未救済の生値(bg-[#4a4a4a]・text-[#eee]・ステータス色 #8a9/#6c6/#c66 等)の意味づけと
   トークン化(ほぼ写真上オーバーレイ内なので優先度低)。

# 決定ログ 2026-07-07(第2セッション) — 救済セレクタ撤去+依存更新+公開側磨き

## Part 1-A: 救済セレクタ層の完全撤去(7b829b9)

- **分析**: 残存約340箇所を要素種別で機械分類。button/input 上のクラスは atelier リセット
  (!important・高詳細度)が支配しており「死にクラス」— 削除しても計算値不変、と判定。
- **処理内訳**: 死にクラス削除337、マーカー→.admin-btn-primary 50、生きサイトの
  トークン化約20、写真上リテラル維持3、ring-[#aaa] 維持(smoke が rgb(170,170,170) を
  実値アサートするため。中立グレー選択リングは flicker 修正時の意図的仕様)。
- **意図的差分**(0%基準からの逸脱を原因特定の上で採用):
  1. Profile 等の入力値テキスト: placeholder:text-[#555] の部分一致救済が入力値まで
     muted にしていた → input リセット本来のインク色に(可読性向上)
  2. リンク/ラベルの hover: 救済で ink 固定死していた → rest muted + hover ink に復活
  3. liveSync トグル: ON 状態クラスが死んでいて ON/OFF 不可視 → aria-pressed 化
  4. Library ズームスライダー accent: #888 → var(--admin-muted)
  5. Service タブのチェックボックス accent: 旧青 #4a9eff → var(--admin-accent)
- **見送り(スコープ外として維持)**: red/emerald/amber 系の写像ルールは「旧hexの救済」
  ではなく「Tailwind パレット→テーマの意味写像」であり、tsx 側約40箇所の置換と
  セットでないと消せないため次回候補として記録。
- 検証: check / smoke 23 passed / 全9タブ×2テーマ×2幅 pixelmatch(差分は上記1〜5のみ)。

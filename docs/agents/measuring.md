# 症状の確かめ方

症状を再現してから直す。必要な項目だけ使い、検証の範囲は [AGENTS.md](../../AGENTS.md) に合わせる。

## 画面

- 画面幅、言語、入力、スクロール位置、タッチ端末かを揃える。タッチ判定は幅だけでは再現できない。
- 撮影前に対象要素・フォント・画像の準備完了を待つ。画像は `complete` と `naturalWidth` を見る。常時通信がある画面で `networkidle` や固定の長い待機だけに頼らない。
- CSSの宣言だけでなくcomputed styleと実際の矩形を確認する。`:not()` の特異度、継承、container query、スクロール領域のpaddingも候補にする。
- 横あふれは要素の位置と、対象コンテナの `scrollWidth > clientWidth` の両方で見る。文書全体の幅だけではパネル内部のあふれを見逃す。
- 写真上の文字は実際の写真とのコントラストを確認する。固定色の計算だけで全写真の可読性を保証しない。

## API・本番経路

- Vite開発サーバーと `src/server.ts` の本番経路は異なる。OGP、canonical、圧縮、HTMLへの設定反映は対象の経路で確かめる。
- 設定はDBの保存値、APIのdefault適用後、preview message経由の画面を区別する。
- 書き込みの挙動はモックまたは使い捨てDBで確認する。必要なら [隔離SQLiteの実例](../archive/measuring-examples-2026-09-05.md) の該当節を使い、接続先が隔離されていることを確かめてから起動する。
- 圧縮の検査はGETのヘッダーと生の本文を保存し、宣言された方式で本文を復号できるか調べる。`curl --compressed` は自動復号するため生の圧縮状態の検査と分け、HEADだけで本文の整合を判断しない。

## テストと記録

- プロセス自身の終了コードを確認する。`test | tail` の終了コードで成功を判定しない。
- バグを再現できる入力・操作を残す。正常値、空、長文、失敗応答などは変更内容に合わせて選ぶ。
- 回帰テストは修正前の症状を検出できるものにする。必要なら隔離した比較環境で修正前を試し、共同作業中のファイルを巻き戻さない。
- 確認日時、対象、観測した値、実行した検証と残る不確かさを短く記録する。
- 過去の詳しいコマンドと事例は [保存した測定例](../archive/measuring-examples-2026-09-05.md)。当時の件数・値・運用規則をそのまま現在へ当てはめない。

# 濱田英明サイトから、Adminで使える表現と仕組みを取り入れる

更新: 2026-09-19 / 担当: Codex / コード確認時HEAD: aa0c2f5

## 最優先: オーナーによる方向修正

オーナーの意図は「今の構造を変えすぎず、Adminでコントロールできる自由度を大事にして、システムとして取り入れるものやデザインで取り入れるものを探す」こと。

前版（5ecd01a）は一つの完成デザインへの誘導が強すぎた。**約8枚への選定、トップの再構成、compact署名とsequence鑑賞をセットで実装する指示を撤回する。** 前版の個別仕様・数値・実装順は採用決定ではない。この文書が引き継ぎの最新版。

今回は既存の構造、写真の見せ方、Adminの選択肢を保持し、表現できる幅と調整の質を上げるための調査・設計。以下の候補を一括実装しない。既存機能を実際のプレビューで確かめ、足りない能力だけを具体化する。

2026-09-19にトップ、WorksのGrid/List、Icelandの詳細と写真送りをブラウザーで確認した。

- https://hideakihamada.com/works/?tab=grid : 写真中心の一覧、分類とGrid/Listの切替。

読み込み途中のGridの空きを意図的な配置と取り違えない。参考サイトの素材・ロゴ・文章・コードを流用しない。

## 既存能力と、取り入れ方の候補

「確認済み」は設定・コードの存在。全組み合わせの画面品質まで確認済みという意味ではない。

| 参考になる点 | このサイトに既にあるもの | 検討すべきこと |
|---|---|---|
| 写真を邪魔しない小さな文字 | 名前の日英サイズ・色・太さ・字間、題名位置 | 日英・読み仮名・肩書きの表示を、本文データを消さず個別に選べるとよいか。固定のcompact様式に閉じ込めない |
| 写真の上の軽いナビ | headerBackgroundのsolid/fade/none、ナビ位置・サイズ等 | 今ある選択肢と写真の組み合わせで読めるか。全面的なナビ変更より、適用範囲・文字の読みやすさを確認 |
| 一覧の密度と余白 | gallery/topの列数・サイズ・間隔、editorial等の配置 | 設定が実際の画面にどう効くか。TopとGalleryの分離を保持し、必要なら不足している範囲だけ補う |
| 写真と情報を別々に見る | PhotoGalleryとLightbox、作品の題・statement、viewerStyle | 写真優先/情報併記/必要時に詳細、の表示粒度が足りているか。作品名と相談への到達を失わない |
| Grid/Listの選択 | Series/Workの棚とカード表示設定 | 作品名主体の一覧を追加する価値があるか。写真全件のリストとの違いを明確にする。作品数が少ない現在だけを前提にしない |
| 1枚に集中できる鑑賞 | 既存Lightboxの送り・拡大・スワイプ・履歴 | 既存viewerの余白/情報表示の改善で足りるかを先に確認。ページ自体のsequence化は任意の拡張候補であり必須ではない |

### 優先候補A: 表示要素を選べること

名前のサイズ・位置は既に操作可能。新しいデザイン名を増やす前に、「日本語名 / 英字名 / 読み仮名 / 肩書き」を消去せず表示切替できるかを確認する。これが足りなければ最小の追加候補になる。サイト名・プロフィール・SEOの値を消さず、HEROの表示だけを制御する。

一括で隠してから復帰できない、すべて非表示にして操作やページの意味を失う、といった状態を避ける。画面の見た目と見出し・アクセシビリティの保持を分けて設計する。設定の初期値は現在と同じ。

### 優先候補B: 既存設定を組み合わせた見本

現在の写真、枚数、選び方、順序、URLを変えず、「名前を控えめに」「余白を広めに」「情報を少なく」などの比較を既存プレビューで作る。まず実際に効く設定と必要な変更量を示す。見本は設計資料であり、直ちに新しいプリセット機能を実装する指示ではない。

将来プリセット化するなら、通常の設定値の組として適用後も各項目を編集できる方式を候補とする。写真選択、本文、公開状態、無関係な設定を上書きしない。既存のプレビュー・保存・取り消しを再利用する。別のテーマエンジンや設定階層を増設しない。

### 次の候補C: 情報量と鑑賞方法の選択

Lightbox内の情報の置き方と余白、作品の一覧形式を調べる。足りなければ独立した任意の選択肢として提案する。新しいビューアを先に作らず、既存機能との差分と、Adminのどの項目で制御するかを説明する。

作品別themeConfigに設定を追加する場合は既存値をマージし、全体設定の継承と個別上書きの関係を明示する。旧値と未知値は従来表示へ戻す。1枚ずつ見る形式を追加しても従来のスクロール表示を置き換えない。

## 変えない前提

- ページ構造・公開URL・SeriesとWorkの区別・本番の写真選定・並び順・公開状態を、この参考サイト研究を理由に変更しない。
- 8枚や特定レイアウトを強制せず、既存のrandom/auto/manualや複数HERO形式を保持する。
- 現行デザインを選び続けられる。既存の設定が別の新設定に無言で上書きされない。
- Adminの機能を一つの「濱田風」スイッチにまとめない。新しい項目は用途と適用範囲が説明できるものに限る。
- 写真のクロップ、原本、焦点、回転、問い合わせ、Portfolio Kitの導線を維持する。

- `packages/web/src/web/pages/top.tsx`: ClassicHeroNameBlock / HeroNameBlock、複数のHERO形式、worksPool。モードにより文字位置設定の適用範囲が違う。

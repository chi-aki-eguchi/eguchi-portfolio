## 2. 推測（Phase A。確定事項ではない）

- 「使用感が良くない」の主因は見た目ではなく「1操作ごと即保存なのに画面は先に動かず、保存中表示も無い」こと。
- スマホ3列でボタンが出ないこと、2列で先頭・末尾が出ないことは、496枚での並べ替えを実質不可能にする。
- PCの縦線は処理上は正しいが、複数列Gridでは「この写真の右か、次の行か」が読み取りにくい。
- 複数枚移動は連続した写真を一区画として動かす場合に価値がある。ただし現状の最大問題は1枚の長距離移動。
- 121枚が同一時刻でも撮影日順は安定ソートで同順位内の手動順を維持するため、順序がランダム化する問題ではない。

## 3. 未解決の反論と Claude の処置

**反論1. 現在の公開並び設定** — 「公開ギャラリーの既定は手動」はコード上の既定値としては正しいが、
現在保存されている設定が手動かは DB操作禁止のため未確認。手動以外なら、管理画面で順位を変えても
公開画面には直接見えない。
→ **オーナー判断待ち（確認依頼済み）。** 実装は「設定値が何であっても安全側に倒す」方針にする。
値の確認結果に依存しない設計にすること。

**反論2. 実機スマホのドラッグ** — スマホ用矢印の実装は確認したが、iPhone Safari で写真カードの
ドラッグが動くか、自動スクロールが実用速度かは実機未確認。
→ **採用（未確認として保持）。** 今回はドラッグに依存しない経路（位置指定）を必ず用意する。
実機確認はオーナーに残す。

**反論3. 496枚の現在値** — 496枚・フィルム279枚・同一時刻121枚は依頼で渡された事実として扱った。
DBへ触れていないため再集計していない。
→ **採用（未確認として保持）。** 実装の可否には影響しない。

**反論4. CSSの部分一致上書き** — 部分一致ルールは多数あるが、現行クラス名で並べ替え線や移動ボタンを
消す直接の衝突は確認できなかった。現時点では「問題なし」。
→ **採用。** ただし新しいクラス名を作るときは `styles.css` の `[class*="..."]` を先に確認すること。

- 事実16・17を自分で確認した（`lastClicked` 依存と `handlePhotoClick` の即return）。

## 5. 今回やること（オーナー確定 2026-07-28）

### 必須の安全修正

1. 公開ギャラリーの並び順が手動以外なら、Library の並べ替えを禁止し
   「現在の公開並びは手動順ではないため、ここでは並べ替えできません」と明示する。
   手動へ変更する導線は出してよいが、**自動で設定を変更しない**。
2. 並べ替え開始時に、画面の配列が保存対象の手動順として妥当か確認する。
   APIの並びと Library 内の表示値の食い違いを解消し、
   **撮影日順などを誤って `sort_order` として保存できないようにする**。
3. 保存処理: 保存中は次の操作を禁止／保存中・保存済み・失敗を並べ替え欄の中に表示／
   失敗時は見た目の順序を元へ戻す／古い要求が新しい要求を上書きしない／
   複数タブ・競合について現在のAPIで安全に防げる範囲を確認する。
4. Undo: 直前1回の並べ替えを戻せる。Undo も保存結果まで含めて成功・失敗を明示する。

### 操作改善

5. 文言: 「完了」→「並べ替えを終了」／並べ替え中は「公開ギャラリーの手動順を変更中・
   1操作ごと自動保存」と常時表示／絞り込み中は全体順へ反映されることを必要に応じて説明。
6. ドラッグ: 明確な取っ手を用意／挿入位置を3pxの細線より明確に／
   **上下でドロップ位置の意味を統一**／自動スクロールを調査し、長距離に耐えないなら補完。
7. スマホ: 並べ替えモードで2列へ切り替え／先頭へ・末尾へを必ず表示／
   ドラッグだけに依存しない／390pxで操作が欠けないことを自動テスト。
8. 長距離移動: 「何番目へ移動」か「選んだ写真の前／後へ移動」の**自然な方を採用**。
   先頭／末尾だけで終わらせない。
9. キーボード: 機能していない `⌘/Ctrl + ↑↓` の案内はいったん削除。
   対象写真を明確に選択・表示できる構造まで安全に作れるなら修正してよい。中途半端なら次段階へ。

### 今回入れない

複数枚の並べ替え／保存前の編集セッション方式／Undo・Redo履歴／Finder試作のmain統合／
左ナビ／独立詳細パネル／3ペイン／DB schema変更／本番DB・R2操作。

## 6. 壊してはいけない既存挙動（症状つき）

- **複合絞り込み中の並べ替え禁止**。壊すと、見えていない写真との位置関係が意図せず変わる。
- **シリーズ単独の例外と全体順への差し込み**（`lib/reorder.ts`）。表示中のシリーズだけを
  0番から振り直すと、他の写真と順位が重なる。
- **大一覧の描画範囲を絞る仕組み**（`computeVirtualGridWindow`）。外すと496枚を同時描画して重くなる。
- **「今回追加」を並べるモードで隠し、ID集合は保つ挙動**。消すと取り込み後の目印が失われる。
- **カテゴリ・シリーズ・料金の保存中停止と失敗時復帰**。外すと画面と保存結果が食い違う。
- **Settings と Service の保存・破棄バー**。外すと未保存の順序変更を失いやすい。
- **撮影日が同じ写真で元の手動順を維持する安定ソート**。外すと121枚が不安定に並ぶ。

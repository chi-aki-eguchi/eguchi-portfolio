# 写真に集中できる入口と鑑賞画面 — Claude Code 実装引き継ぎ

作成: 2026-09-19 / 調査: Codex / 調査時 HEAD: `fd071eb`

## 依頼と今回の到達点

オーナー:「濱田英明のwebサイトが良すぎている。どうにか要素というか、うちにも応用できるものを取り入れたい」「具体的にもっと詰めて、claude codeに渡そう」。

以下はその依頼を具体化した実装案。個々の数値・写真セレクトまでオーナーが承認した仕様とは扱わない。Claude Codeは実装と実写真の比較プレビューまで進め、見られるURLと画面を返す。現在の本番表示・保存済み設定を自動でこの案へ切り替える依頼ではない。公開・push方針の正本はAGENTS.md。既存値のままで見た目が変わらない追加機能として実装する。

**一案に絞る: 小さな署名のある表紙 → 選んだ写真の短い連なり → 作品を1枚ずつ見る。**

参考サイトのロゴ・写真・動画・文言・コードは流用しない。写真は秋さんの現在公開中の素材を使用。大量の分類や動画背景は今回追加しない。

## 観察した事実と、こちらの設計判断

2026-09-19、以下をブラウザーで実際に閲覧・操作した。

- https://hideakihamada.com/ : 全画面背景、左上に小さい名前、右上にMenu、下部に作品名のリンク。メニューはWorks / Text / About / Contact。
- https://hideakihamada.com/works/?tab=grid : 小さい文字の分類、写真主体のグリッド。Listへ切替可能。読み込み途中の空き枠は意図的な空白配置ではないので模倣の根拠にしない。
- https://hideakihamada.com/works/?tab=list : 作品名で探す一覧。
- https://hideakihamada.com/works/13721/ : Iceland。1枚ずつ表示、枚数表示、detail、Index、作品間のBack/Next。写真送りで1/25→2/25を確認。
- https://akieguchi.com/ : 名前を複数表記した全画面表紙、8列の写真一覧、Series、相談とPortfolio Kitの導線を確認。

参考サイトから採る原則は、文字と操作を端に寄せる、写真を画面内に収める、作品の説明を必要なときに読むこと。トップを短く編集する方針は、秋さんの作品へのこちらの提案であり、濱田サイトの再現ではない。

## 1. トップの表紙

### 具体的な構図

- 既存のHERO写真を1枚表示。初期案は現在の波の写真。画像を生成・加工せず既存の焦点と回転を使用する。
- 上部は既存の名前とナビ。PCはSeries / Work / About / Contactを見せ、スマホは既存メニューを使用。PCにもMenuだけを置く新しいナビは作らない。
- 中央の4段の名前を、左下の小さい日本語名1行に変更できるようにする。英字名は既存ヘッダーにあるのでHEROに重ねない。
- 日本語名はPC 18〜20px、スマホ16〜18pxを初期値。端からPC32px、スマホ20px＋safe area。既存文字サイズ設定を無視する固定値の乱立は避ける。
- 名前は見出しとして残す。読み仮名・英字名・Photographyの保存値は消さず、この表示だけで省略する。空の名前は既存の有効な名前へフォールバック。
- 初期プレビューは `heroMode=single`、`heroDisplayMode=fullscreen`、`heroTitlePosition=bottom-left`、`heroScrollEffect=none`。自動送り・ズーム・パララックスを追加しない。
- ヘッダーは既存 `headerBackground=none` を第一候補とし、実写真で読めなければ既存 `fade` を使用。`solid` も保持。暗幕は文字の読みやすさに必要な最小範囲に限定し、写真全体を暗くして成立させない。
- 写真本体とヘッダーの高さの二重差し引きに注意。縦写真をcoverする表紙と、全体を切らずに見せる鑑賞画面を区別する。

### 最小限の追加

`heroNameStyle=classic|compact` を追加する案。未設定・未知値はclassic。compactは上記の簡潔な署名。最初はsingle / carouselの既存名前部品で対応し、他HERO形式には設定の適用範囲を明示する。既存のimmersiveを全面改造する必要はない。

## 2. 表紙の次に「選んだ写真」を置く

- 既存 `topWorksMode=manual` と `topWorksIds` を使う。新しい写真選定DBや並び順は作らない。
- 初期比較案は8枚（調整幅6〜10枚）。テーマが繋がる写真を並べる。人数・色・距離・光の変化で選び、作品名や撮影地を推測して付けない。
- 表紙と同じ写真を直後に再掲しない。同じ人物の似た構図を連続させすぎない。作者の最終セレクトとは区別して、候補の写真IDと順序・理由をプレビュー資料に残す。
- 既存 `topWorksLayout=editorial` を第一候補にする。PCは2枚1組の大小、スマホは1枚ずつ。写真全体の比率を維持し、縦写真も原則画面の高さ内に収める。無意味な空きマス・ランダム回転は追加しない。
- 余白の初期目安: PCの組と組64〜96px、スマホ40〜56px。横の余白はPC32〜48px、スマホ20px。巨大な空白や装飾のための罫線を増やさない。
- 選択写真だけで終わり、その下に既存Seriesの入口とWorkへの導線を出す。8枚の指定なのに他の写真が自動追加されないことを確認する。
- `homeGalleryCount` は表示の初期バッチ数であって総枚数制限ではない。短い構成はmanualのID集合で作る。random/autoの既存動作は変えない。
- トップの写真クリックは既存Lightboxを開く。そこから正しい `/series/:slug` または `/work/:slug` に進める既存機能を維持する。
- 相談とPortfolio Kitの導線は保持。今回の鑑賞画面に販促の帯を重ねない。ホーム全体の販売導線再設計は今回の対象外。

## 3. 作品ページに「1枚ずつ見る」形式

### 画面と操作

- 同じ `/series/:slug`、`/work/:slug` のまま、作品単位で選べる新しい鑑賞形式を追加する。ページ読込で既存Lightboxを自動オープンする実装にはしない。
- PCは上48〜56px、下56〜72pxを操作・作品情報に使い、残りの中央へ写真をcontainで置く。スマホも上下に操作領域を確保し、safe areaとブラウザーの伸縮を含めて写真と操作が隠れないことを優先する。
- 上段: 棚へ戻るリンク、About / Contactへの到達手段。下段: 作品名、詳細、現在枚数/総枚数、写真の前後ボタン。文字は12〜14pxでもクリック領域は44px以上。
- 写真上に常時大きい矢印を置かない。操作をホバーだけに隠さない。ボタン・左右キー・横スワイプで送れる。自動送りなし。スワイプ後の合成クリックで2枚進めない。
- 先頭/末尾で写真をループしない。最後の写真はそのまま残し、次の作品（同じ棚にあるとき）、棚へ戻る、Aboutを案内。作品間移動と写真送りのラベルを区別する。
- 棚が1作品だけなら次の作品を捏造しない。WorkとSeriesを勝手に混ぜない。
- 詳細は既存の題・副題・statement・説明を使う。空欄の仮文章・EXIFの大量表示・架空の撮影日を加えない。Workの「この作品について相談する」は詳細内の上部に残し、既存の設定条件と `?work=<slug>` を保持する。
- 詳細パネルはEscapeで閉じ、開いたボタンへフォーカスを戻す。写真送りのキー処理は入力欄や詳細内では発火させない。
- 写真の拡大は既存Lightboxを再利用可能。閉じたら鑑賞中の同じ写真へ戻る。履歴とキーボードの二重制御を避ける。
- 写真送りごとに履歴を増やさない。別ページへ行ってブラウザーで戻った際は、同じ作品の見ていた写真を復元する。添字だけでなく写真IDで保持し、写真が消えた場合は有効な先頭へ戻す。
- 読み込み中・通信失敗・非公開/404・0枚・1枚をそれぞれ扱う。失敗は再試行と棚への出口を用意し、真っ白な全画面にしない。

### 設定と適用範囲

- 既存作品の `themeConfig` に `viewMode=sequence` を足す案。未設定・未知値は従来表示。既存のlayout・photoOrder・bgColorなどをマージして保持する。SQL列の追加は不要。
- 管理画面の作品編集に「見せ方: ページをスクロール / 1枚ずつ見る」を置く。写真の並べ方と鑑賞形式は別の概念として表示し、スクロールに戻すと元のlayoutが復元される。
- 写真順は現行の `themeConfig.photoOrder` → `settings.seriesSortOrder` の解決を共有する。別のソートやランダムを追加しない。
- 背景は作品bgColorがあればその設定を尊重し、未設定時は既存viewerStyleの壁色と文字色の組を再利用する。白壁案を比較の初期値とするがサイト全体を白へ変更しない。
- 初期比較はSICFの実データで行う。Rintaroも長い作品・縦横混在の検証対象にする。保存済みthemeConfigへ勝手に書き込まず、ローカルまたは既存プレビュー経路で見せる。
- 通常ヘッダー/フッターと鑑賞用の操作が二重表示されないようLayout連携を設計。全サイトのナビを隠す変更にしない。作品ページの題名・SEO・共有URLを維持する。

## 5. 実装順と確認資料

1. 現在のgit status・AGENTS.md・task.mdを確認。すでにAdmin関連の未コミット変更がある。所有者の差分を消したり一括stageしたりしない。
2. 表紙のcompactと既存設定による8枚の構成を作り、現行と並べたPC/スマホの画面を残す。写真IDを本番コードへ固定しない。
3. 作品のsequenceを実装。既存データ取得・並び順・エラー処理・相談リンクを共有する。
4. Adminで選択→未保存プレビュー→保存成功/失敗→従来形式へ戻す経路をモックで検証する。themeConfigのプレビューが未対応なら、その経路も実装範囲に含める。
5. 動く比較URLを提示。既存/新案、トップ/作品を容易に比較できるようにする。ソースだけや静止画だけで完了にしない。

### 受け入れ条件

- 1440×900 PC、390×844タッチ、320px幅、横向きで横はみ出しなし。縦横写真・回転写真・長い作品名でも操作と写真が衝突しない。
- トップは中央の4段文字がcompact時だけ消え、manualで選んだ写真だけがその順番で出る。写真原本・公開状態・別ページの設定は変わらない。
- sequenceは実写真が読み込まれ、naturalWidth>0で、画面内に全体が収まる。送り・戻り・最後・詳細・拡大・履歴・フォーカス復帰を確認する。
- 閉じたモーダルや背後のHEROが左右キーで同時に動かない。動きを減らす設定では切替演出を省略。
- 大画像は現在の写真を優先し、先読みは隣接分に限定する。100枚分の大画像を初回に取得しない。初期表示、10枚の連続送り、スクロール復帰で通信と表示を確認。
- 既存設定/未設定のサイトは従来のまま。compactとsequenceのオフで従来表示へ戻せる。未知値でも空画面にならない。
- `bun run check` と、共通UI/設定/保存経路に関わるため隔離済み `bun run smoke` 全体。開始時の基準と比較する。task.mdにある既知13失敗は過去の記録であり、今の失敗を自動的に既知扱いしない。
- 本番へSave/Deleteして検証しない。画像と性能は同条件の前後比較を示し、HTTP 200だけで写真表示成功としない。

# 2026-07-12 決定ログ

## タスク: admin Library 高速スワイプ時のタイルちらつき修正

- **経緯**: codex-reviewer 経由の依頼。高速スワイプで写真タイルが強くチラつく。
  公開ギャラリーも含めて原因を決め打ちせず調査し、最小限で直す。
- **調査方法**: scratch/flicker-repro.mjs / flicker-repro-public.mjs
  (Playwright・読み取りのみ・375x812 と 390x844)で、フリック中〜静止後の
  「可視タイル中の白抜け画像数」を毎フレーム実測。
- **原因(実測根拠つき)**:
  - admin Library は仮想化グリッドで、スクロールでタイルが unmount/remount
    される。タイル画像が `loading="lazy"` だったため、remount 直後の画像は
    ブラウザキャッシュ済みでもスクロール中は読み込みが保留され
    (修正前実測: 戻りスワイプで可視8枚全部が白、静止後475msでも未回復・
    lazyPending=8)、viewport 全面が白抜けする強いチラつきになっていた。
  - 仮想ウィンドウ自体の遅れは無し(全サンプルで emptyViewport=0、
    overscan 8行で足りている)。
  - 公開ギャラリーは非仮想化で remount が無く、戻りスクロールは白抜けゼロ。
    初回表示の blank はフェード演出+初回フェッチで、静止後150msで解消
    (設計どおりの見え方)。今回は非対象と判断。
- **選んだ方針**: Library タイルの `<img>` を `loading="eager"` に固定
  (マウント数は仮想化が既に可視+overscan に絞っており、eager でも読込対象は
  その範囲に留まる)。読込中の下地を `--admin-paper-deep` にして
  「白い穴」ではなく「台紙」に見えるようにした。
- **迷った点**: overscan 増加案・placeholder shimmer 案もあったが、
  実測で仮想ウィンドウは遅れておらず、原因は lazy 保留のみだったため
  最小の2点に絞った(影響範囲: admin.tsx の img 1箇所)。
  Trash グリッドは非仮想化なので lazy のまま(正しい用法)。
- **修正後実測**: 375/390 とも戻りスワイプの白抜け 0 フレーム
  (修正前は最大8枚×複数フレーム)。初回領域への高速フリックは
  フェッチ中の一時 blank のみで、静止後はキャッシュ済みなら即回復。
- **回帰テスト**: pages.render.test.tsx に「Library タイル画像は eager」を追加
  (lazy へ戻すとチラつきが再発するため属性で固定)。
- **検証**: `bun run check` 成功(335 tests / 0 fail)。
  `bun run smoke` 26 passed / 1 failed(既知の admin-trash-signal のみ・今回と無関係)。
- **要相談**: なし

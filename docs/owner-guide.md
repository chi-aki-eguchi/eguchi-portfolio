# 秋さん向け・AI運用手引き

作成: 2026-07-08。これ1枚で「AIへの頼み方 → 報告の読み方 → 公開（push）→ 困った時」が回るようにした短い手引きです。詳しいルールは各リンク先にあります（読まなくても運用できます）。

---

## 1. セッションの始め方

1. `docs/agents/backlog.md` を開く（**未完了の作業だけ**が並んでいます）。
2. やりたい項目の見出し（`B-3` のような番号）を Claude Code に伝えるだけで大丈夫です。
   指示書を丸ごと貼る必要はありません。
3. 各項目に付いた印を見る:
   - 🟡 **確認済み** … コードや実測で未完了と分かっている。そのまま頼んでよい
   - 🔴 **要再確認** … 記録が古く、2026-07-31 の管理画面刷新でもう直っている
     可能性がある。**AI がまず実物を測り直し、残っていなければ項目を消します**
   - 「オーナー判断が要るもの」の節は、AI が案を出して止まります。返事が必要です

backlog に無い依頼をするときは、やってほしいことをそのまま書けば大丈夫です。安全境界と
停止条件は `AGENTS.md` に書いてあり、AI は毎回それを読んでいます。特別な指定は要りません。

## 2. 完了報告で見るべき3点

AIの報告が長くても、この3つだけ確認すれば十分です。

1. **`bun run check` は成功したか**（コードの健康診断。「1028 tests / 0 fail」のように件数と失敗0が出る）。admin を触ったなら **`bun run smoke` も成功したか**（実際のブラウザで管理画面を動かす検査）。
2. **「push したか」を見る。**2026-08-20 から、AIは条件を満たすときだけ自分で push します（条件は `AGENTS.md`）。壊れたときの戻し方は `docs/rollback-guide.md`。AIが push した報告があれば異常です。
3. **「要相談」「オーナー判断待ち」の項目**。ここだけは秋さんの返事がないと先へ進みません。選択肢2〜3個+おすすめ付きで書かれているはずです。

## 3. push（公開）と本番確認

push = 本番サイトの更新です。**2026-08-20 から、AIは条件を満たすときだけ自分で
push します**（`bun run check` 成功 / 製品コードを触ったなら `bun run smoke` も成功 /
本番DB・秘密情報・課金・公開設定に関わらない、の3つ全部）。
条件を満たさないときは push せず、理由を書いて止まります。

自分の手で公開したいときは、いつでもこれで出せます:

```sh
git log origin/main..main --oneline   # これから公開される変更の一覧を見る
git push                              # 公開（Railway が自動でビルド・反映）
```

**壊れたときの戻し方は `docs/rollback-guide.md`。**コピペで実行できる形にしてあります。

push 後、数分待ってから:

1. https://akieguchi.com/ を開き、トップ・ギャラリー・管理ログイン画面が普通に表示されるか見る。
2. 報告の「push後の確認推奨」に書かれた箇所を見る（そのタスクで変わった場所です）。
3. 表示がおかしい時は慌てずスクショを撮り、次のセッションで AI にそのまま貼る。

## 4. 困った時

| 状況                                                       | 対応                                                                                                                                     |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| AIが「三振（同じ失敗3回）で中断」と報告                    | 正常な動きです。その項目は「要相談」リストに入っています。急ぎでなければ放置してよく、急ぎなら「Codex に相談して」と次のセッションで指示 |
| 「要相談」が溜まってきた                                   | 週1回くらい、要相談リストをまとめて眺めて「やる/やらない/後で」を返事すれば十分                                                          |
| AIの報告が理解できない                                     | 「専門用語なしで3行で言い直して」と頼む。それでも不明なら放置してOK（push しなければ本番は変わりません）                                 |
| 本番の表示が壊れた                                         | まず `git log -5 --oneline` を AI に見せて「直前の push が原因か調べて」と指示。原因調査は読み取りだけなので安全                         |
| AIが妙なこと（大量削除・push・設定変更）をしようとしている | 「止めて」と打てば止まります。その内容を `docs/agents/backlog.md` の「オーナー判断が要るもの」へ書き直させる                                               |

## 5. やってはいけないこと（秋さん側）

- check/smoke 成功の報告を確認せずに push しない
- 「要相談」を承認するとき、**復元できない操作**（完全削除・上書き）は一呼吸置く。「これは元に戻せる?」と AI に聞いてから
- リポジトリのルート直下に .md ファイルを増やさない（AI が置いたら指摘してOK。文書は docs/ 配下がルール）
- `.env`（パスワード類）の中身を AI のチャットに貼らない

# 壊れたときの戻し方

> **秋さん向け。コードを書かなくても、ここのコマンドをコピペすれば戻せます。**
> 2026-08-20 作成。AIが自分で push できるようにしたので、その保険として置いた。
>
> **迷ったら、まず 1 と 2 だけやってください。** 3 から先は読まなくて構いません。
> どうにもならないときは、AIに「`docs/rollback-guide.md` を読んで、いまの状況を
> 診断して」と頼めば、ここを見て動きます。

用語（1行ずつ）:

- **push（プッシュ）** — 手元の変更を GitHub に送ること。**送ると本番サイトが更新される。**
- **commit（コミット）** — 変更のひとかたまり。1回の作業＝1コミットが基本。
- **revert（リバート）** — あるコミットを打ち消す新しいコミットを作ること。
  **履歴は消さない**ので安全。
- **Railway** — サイトを動かしているサービス。push を受けて自動で作り直す。

---

## 1. いま本番に出ているものを確認する

「本当に壊れたのか」「いつのものが出ているのか」を先に見ます。

```bash
curl -sI https://akieguchi.com/ | grep -i x-build
```

`x-build: 3e3635cd` のような8文字が返ります。これが**いま公開されている版**です。

次に、手元の最新と見比べます。

```bash
git log -5 --oneline
```

上の8文字が一覧の一番上と同じなら、**最新が本番に出ています**。
一覧に無い・古い方と一致するなら、まだ反映途中です（1〜3分待つ）。

---

## 2. いちばん速い戻し方（Railway の画面。git を触らない）

**サイトが表示されない・明らかに壊れているときは、まずこれ。** 1〜2分で戻ります。

1. [railway.app](https://railway.app) を開いてログイン
2. `eguchi-portfolio-app` のプロジェクトを開く
3. **web** のサービス（四角）をクリック
4. 上の **Deployments** タブを開く
5. 一覧から、**壊れる前の緑チェック（Success / Active）が付いた行**を探す
6. その行の右端「…」→ **Redeploy** を押す

数分で前の状態に戻ります。

> **⚠️ これは応急処置です。** GitHub 側のコードは壊れたままなので、
> **次に誰かが push すると、また壊れた版が出ます。** 落ち着いたら次の 3 をやるか、
> AIに「Railway で前の版に戻した。GitHub 側も戻して」と頼んでください。

---

## 3. きちんと戻す（直前の push を打ち消す）

git 側も直します。**履歴は消しません。**「打ち消すコミット」を1つ足すだけです。

まず、何が送られたかを見ます。

```bash
git log -5 --oneline
```

直前の1件だけを打ち消すなら:

```bash
git revert --no-edit HEAD && git push
```

直前の**2件**を打ち消すなら:

```bash
git revert --no-edit HEAD~1..HEAD && git push
```

3件なら `HEAD~2..HEAD`、4件なら `HEAD~3..HEAD` と、数字を1つずつ増やします。

push すると Railway が自動で作り直します。1〜3分待ってから、**1 のコマンドで
`x-build` が変わったこと**を確認してください。

### うまくいかないとき

`error: could not revert` のようなメッセージが出たら、**そこで手を止めて**
AIにそのまま貼ってください。無理に続けると、かえって直しにくくなります。

---

## 4. 特定の1件だけを打ち消したい

「3日前のあの変更だけ消したい」というときです。まず番号を調べます。

```bash
git log -15 --oneline
```

左端の8文字（例 `f7825df`）が目印です。それを打ち消します:

```bash
git revert --no-edit f7825df && git push
```

> `f7825df` の部分を、実際に見つけた8文字に置き換えてください。

---

## 5. AIに頼むときの言い方

コマンドを打ちたくないときは、そのまま伝えれば動きます。

- 「本番が壊れた。`docs/rollback-guide.md` を読んで、直前の push を戻して」
- 「`git log -5 --oneline` を見て、どれが原因か教えて」
- 「Railway で前の版に戻した。GitHub 側も合わせて」

AIは戻したあと、**`x-build` が変わったことまで確認して報告する**決まりです
（`AGENTS.md`「必須検証」）。「戻しました」だけの報告なら、
「本番で確認した？」と聞き返してください。

---

## 6. やってはいけないこと

| やらないこと | なぜ |
|---|---|
| `git reset --hard` | 変更が**消えます**。revert と違って取り返せません |
| `git push --force` | 他の履歴を**上書き**します。戻す作業でこれは要りません |
| 壊れたまま次の作業を頼む | 原因が混ざって、どちらが悪いか分からなくなります |
| Railway の環境変数をいじる | 表示の不具合とは別の話です。**先に 2 か 3 を試す** |

---

## 7. AIが push してよい条件（2026-08-20 から）

AIは、次を**すべて**満たすときだけ push します。1つでも欠けたら push せず報告して
止まります。正本は `AGENTS.md`「絶対に越えない境界」。

1. `bun run check`（型・文法・自動テスト1000件超・ビルド）が通っている
2. 製品コードに変更があるなら `bun run smoke`（実ブラウザでの管理画面テスト）も通っている
3. 本番DB・秘密情報・課金・外部公開設定に関わる変更を**含まない**

**3に当たるものは、check が通っていても push しません。** そのときは
「これは自分では push しません」と報告が来るので、内容を見て判断してください。

止めたいときは、いつでも「**止めて**」と打てば止まります。

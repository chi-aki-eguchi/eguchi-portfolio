## 2. 提案リスト（優先度順・実施には秋さんの判断が必要）

1. **【高】依存ライブラリの脆弱性3件の更新** — `bun audit`（既知の脆弱性を調べるコマンド）で、DB接続ライブラリ経由の `ws` に「高」評価のDoS（サーバーを過負荷で止める攻撃）脆弱性が見つかりました。実際の危険度は「信頼しているTursoサーバーが乗っ取られた場合のみ」なので緊急ではありませんが、更新推奨です。今夜 `bun update` を試みたところ権限制限で拒否されたため未実施。
   - やり方: ターミナルで `bun update ws js-yaml` → `bun run check` → `bun run smoke` で確認
   - リスク: 低（互換性のある小さい更新のみ）
2. **【高】旧デバッグスクリプトの削除とパスワード確認** — `scratch/legacy-debug-2026-06/` 内の数本に管理画面パスワードが平文で残っています。不要なら削除してください（削除はルール上、秋さんの承認が必要なため夜間は移動まで）。**もしそのパスワードを今も使っている場合は変更を検討**してください。
3. **【中】写真の完全削除時にサムネイルがR2に残り続ける問題** — ゴミ箱から完全削除しても、縮小版画像2種（thumb/medium）はストレージに残り、少しずつ容量課金が増えます。R2の削除処理を書き換える必要があるため、夜間ルール（R2オブジェクトへの変更禁止）に従い提案のみ。
4. **【中】設定保存の高速化** — 管理画面で設定を保存すると、最大80項目を1件ずつDBに書き込んでおり、合計2秒近くかかりえます。一括書き込みにすれば1回で済みます（管理画面の書き込み系のため夜間実施は見送り）。
5. **【中】公開ギャラリーAPIの軽量化** — `/api/photos` が全写真の全情報を返しており、写真が増えるほど初回表示が重くなります。必要な項目だけ返すよう絞ると通信量を約半分にできます。
6. **【低】管理画面セッションの無効化機構** — 現在、ログインCookieが盗まれた場合はパスワードを変えるまで有効です。サーバー側でセッションを記憶する仕組みを足すと、即座に無効化できます。

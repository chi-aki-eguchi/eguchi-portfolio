# トップの展示（日藝祭 2026）

2026-10-31 オーナー依頼。会期は 2026-11-01〜03 だが、名刺やQRから後日来る人にも届くよう、**会期後も続ける。日付で自動的に戻さない**。次に見せたい作品ができたら管理画面で入れ替える。

## 基準は会場の壁

2026-10-31 夜、オーナーが会場の写真を送ってくれた。最初の版は5枚のファイルだけを見て並びを決めていて、壁の順番も詩も見ていなかった。そこからやり直した。**サイトの判断は、まず会場の実物に合わせる。**

- 壁: 上の段の左から 芝生の腕・花と窓・部屋、下の段の左から 背中・髪。右下に詩の紙、その下に名前の札と QR の札。額は銀、写真の周りは白いマット。
- 紙の上下の線は掲示のピン。原稿の PDF に記号は無いので、図案として再現しない。
- 名刺の原稿は `~/01_simple_square_55x55_print.pdf`（55mm 角・2ページ）。表は縦書きの名前、裏は Aki Eguchi・QR・akieguchi.com・WEB / INSTAGRAM / X・メール・電話・TOKYO / FUKUOKA / TAIPEI。
- **名刺の QR の行き先は `https://akieguchi.com/card.html`**（原稿から読み取った）。印刷済みなので変えられない。`06_名刺と掲示物` の `ULTRA_RES_*.pdf` は別の版で、今回の名刺ではない。

## 名刺の QR からの入り方

`/card.html` は 2026-09-07 に作ったリンク集（Website・Instagram・X）。そのままだと、QR を読んだ人は「Website」を押さないと展示に着かない。依頼の「名刺やQRから見に来る人にも届くように」を満たすため、**展示がトップの間は `/card.html` を `/` へ 302 で通す**（`server.ts`、判定は `exhibitionIsTop`）。トップを「いつもの」に戻すと、今のリンク集に戻る。ファイルは消していない。Instagram と X は、ページの最後の名刺とメニューから行ける。

## 見せ方

- 主な読者は、展示を見た直後にスマホで開く人。やりたいことは「写真をもう一度見る」「ほかの作品を見る」「Instagram へ行く」。
- **開いた瞬間（2026-11-01）**: 名刺で始まる。QR を読んだ人の手元にあった名刺の表が画面いっぱいに出て、名前がにじんで定まり、縮みながら壁の右下の定位置へ戻る。戻り始めると紙が引いて壁が見え、写真が左上から順に現像される。手元の物が壁の一部に戻る、という1つの動きで展示につなげる。名前の組みは本物の名刺に合わせた（字の位置の差は名刺の幅の約0.3%以内。実測）。名刺の着地は札の箱と1.5px以内で重なる。触ったらすぐ終わる。札が箱の外なら動かさず薄れて終える。
- **最初の画面は壁の配置**: 5枚・詩の紙・2枚の札を置く。見た人が「さっきの壁だ」と分かることを優先した。PC は銀の額・白いマット・窓の段・壁に落ちる影まで会場に合わせた比のまま（線だけだと図面に見えた）。**スマホは縦の画面に掛け直す**（`EXHIBITION_WALL.phone`）。会場の比のままでは写真の幅が115pxほどしかなく、2枚3段にして170pxほどに、面積で2倍以上にした。順は左から右・上から下のまま、右下が詩の紙と名刺なのも会場と同じ。押すとその写真からビューアが開き、紙を押すと詩へ、名刺を押すと名刺へ移る。
- **札（2026-11-01）**: 名前・題・会期を、会場の作品札と同じ小さな字で左へそろえる。大きさではなく並びと濃さで読ませる。以前の大きな名前・英語名・肩書きはヘッダーと重なり、1画面に名前が3回出ていた。肩書き（写真学生）は Info にある。1枚の表紙のときは今までどおり表紙の名前の部品を使う。
- **続く写真**: 壁と同じ順。切り抜かず、上に文字も陰も重ねない。スマホは端から端まで、PC は1画面に全体が入る大きさで左右へ振る。名前と展示の名前は札として写真の外へ置く。
- **最後が詩**: 添え書きにしない。会場の紙と同じく、1枚の作品として写真の後ろに置く。
- **名刺**: 詩の紙の下に、表と裏の2枚を並べる（会場の壁の右下と同じ）。線で囲まず、上からの光の影で物に見せる。角の丸みは会場の写真から測って13%。表の名前は名刺の比のまま。裏は名刺と同じ並び・同じゴシックで、QR の場所を押せる「INSTAGRAM」「X」に置き換える。スマホの中の QR は読めないため。**電話番号とメールは載せない**（公開すると拾われるため。連絡は Info のフォーム）。
- **詩の紙（スマホ）**: 紙の縁を見せる。下の余白が画面の空きではなく紙の余白だと分かるようにするため。画面全体を紙にする案も比べたが、紙と名刺が物に見えなくなり、壁とのつながりが弱くなるので採らなかった。
- **名刺の後**: 写真の無い言葉の目次（Portrait・Life・Series・Info）と Gallery。白黒と詩の続きに色の写真を大きく並べない（PC は触れたときだけ、扉の写真が切り抜かずに隣に出る。字も今までの目次より小さくした）。**撮影依頼の帯は展示のトップから外した**（「だけど私のものじゃないの」の直後に料金を読ませない）。依頼の入口は Info に今までどおりある。
- 表紙の「送ったときの動き」は使わない（写真が紙の色へ褪せるため）。

## 詩

原稿は `~/Downloads/poem_A4_tate_vector.pdf`（A4 縦、Zen Old Mincho）。本文は `EXHIBITION_POEM`。一字も変えない。

組みは原稿の PDF を描いて測り、同じ比にした。字の大きさは紙の幅の 2.336%、行の間隔は字の 2 倍、1行目の中心が紙の左から 74.65%、行頭が上から 16.4%。PC の表示と原稿の差は、8行とも紙の 0.18% 以内（実測）。スマホだけ、読めるように字の大きさの下限を持つ（15px）。行は折り返さない。4行目だけ長く、5〜7行目が短い段差も詩の形。紙の下の余白は埋めない。紙・名刺・マットは画面の色に関わらず物としての紙で、ダーク表示では明かりを落とした分だけ白を沈める（`--ex-paper`）。行は右から順に現れる。

書体は使う字だけを Google Fonts から読む（`text=`、詩を変えれば字も変わる）。

## 文

「日藝祭 2026 展示作品」「2026年11月1日〜3日」だけ。記録の形なので、会期中でも会期後でも読める。「開催中」「ご来場ありがとうございました」のような時制のある言葉は使わない。場所・点数・技法は確定情報が無いので書いていない。

## 仕組み

- 正本は `packages/web/src/shared/exhibition.ts`（5枚の順・壁の配置 `EXHIBITION_WALL`・詩）。公開の組み立ては `pages/top.tsx` と `components/develop/ExhibitionTop.tsx`・`exhibition.css`。
- 同梱の5枚が全部並びに入っている間は壁の配置を出す（`exhibitionShowsWall`）。1枚でも外すと、先頭の写真が表紙になる（表紙の部品 `HeroSingle` を切り抜かない形で使う）。次の作品へ入れ替えたときは、こちらの形になる。
- 5枚はリポジトリに同梱（`packages/web/assets/exhibition/2026-nichigei/`、原本から作った長辺2800pxのJPEG。原本は `~/Desktop/03_展示・作品/藝祭`）。本番の保存先へ入れなくても push だけで出せる。配信は `/api/images/exhibition/…` で、ほかの写真と同じ変換・控えを通る（`api/exhibition-assets.ts`。読むのは一覧にある名前だけ）。
- 同梱の写真は負の ID。ライブラリの写真（正の ID）と同じ並びに入れられる。公開の写真一覧には入らないので Gallery には出ない。撮影日は持たせない（元の記録はフィルムを複写した日）。
- 設定: `homeExhibition`（on／off）、`exhibitionTitle`、`exhibitionDates`、`exhibitionText`、`exhibitionPhotoIds`、`exhibitionCaptions`。`homeExhibition` の既定は持ち主のサイトだけ on（`exhibitionStatus`）。配布版のサイトには出ず、管理画面のタブも出ない。`server.ts` は生の設定を読むので、同じ関数で判定する。
- `server.ts`: トップだけ、共有の写真と説明を展示の先頭の写真にする。壁の配置の間は大きな表紙が無いので先読みしない。

## 管理画面

`/admin/pages` の「展示」タブ。

- トップ: 展示／いつもの（止めると今までのトップに戻る。写真と文は残る）
- 写真: 足す・外す・並べ替え。新しい写真は、いつもどおりライブラリへ入れてから、ここで足す
- 題・会期・詩（空にした項目は出ない。短い文は紙の縦書き、長い文は横書きで出る）
- 写真ごとの題（畳んである）

## 確かめ方

- 見た目: `TRY_DESIGN=develop bun run try` → http://localhost:4400/ 。本番の設定と写真を読むだけで、展示の設定と同梱写真は手元で補う。開いた瞬間の見せ場だけは、設定が HTML に入る本番の組み立てでしか流れない。本番では `https://akieguchi.com/?intro` でもう一度流せる（同じタブでは2回目から流れない）。
- 回線: 写真は5枚で計約90KB（スマホの幅、AVIF）。Chromium で 0.7Mbps・遅延400ms に絞っても、名刺が動き出す頃に届く。届く前の写真は場所に薄い面を置き、届いてから現像する（`WallPrint`）。
- 検査: `scripts/smoke/public-exhibition.spec.ts`、`scripts/smoke/admin-page-photos.spec.ts`、`packages/web/src/shared/exhibition.test.ts`、`packages/web/src/api/exhibition-assets.test.ts`、開いた瞬間の段取りは `packages/web/src/web/lib/develop-intro.test.ts` と `scripts/regression/hero-intro.test.mjs`。

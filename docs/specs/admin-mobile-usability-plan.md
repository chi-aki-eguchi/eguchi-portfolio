> **調査方法**: 本番と同じDBにつながる開発サーバへ読み取り専用で接続し、

## 0. 結論を先に

Codex が報告した5件は、**5件とも実在した**。記録どおりだった。

そのうえで、報告に無かった**より重い不具合を1件見つけた**。

> **写真編集の「公開／非公開」「S／M／L」で、いま選ばれている方のラベルが読めない。**
> 黒い箱が出るだけで、文字が見えない。スマホでもデスクトップでも同じ。

写真家が毎日いちばん多く触るのは写真1枚の編集であり、その中で「いま公開なのか非公開なのか」
「いまSなのかMなのか」が読めないのは、見た目の問題ではなく**判断できない**問題である。
これを最優先にする。

## 1. 現在の使いにくさ

重要度の意味 — **P0**: 誤操作・誤判断につながる / **P1**: 目的の操作にたどり着けない・時間がかかる /
**P2**: 分かりにくい・整っていない。

### P0-1. 選ばれている項目のラベルが読めない ✅ 確認済み

| | |
|---|---|
| 対象画面 | 写真編集（インスペクタ）の「公開／非公開」「S／M／L」 |
| 幅 | 390px / 900px / 1440px **すべて** |
| 再現方法 | Library で写真を1枚押す →「よく使う」の下の2組を見る |
| 利用者が困ること | いまの状態が読めない。黒い箱を「押せるボタン」と誤解して、公開中の写真をもう一度押してしまう |

**実測**: 選択中のボタンは文字色 `rgb(26,26,26)`（濃い墨）。その真下に敷かれる指示子
（`.admin-segmented__indicator`）の背景は `var(--admin-ink)`（同じ濃い墨）。**墨の上に墨**で書いている。

`styles.css` には「選択中は紙色の文字にする」という指定（`.admin-segmented__option[aria-pressed="true"] { color: var(--admin-paper) !important }`）が
**書かれているのに効いていない**。同じインスペクタの中で、回転（0°/90°…）と「見せる中心」は
白抜き文字が正しく出ている。**同じ「選択中」が2通りの見た目になっている。**

これは `docs/agents/backlog.md` B-1「グローバルCSSの上書きが積み上がっている」の
6例目にあたる。**原因は要素側ではなくCSSの勝ち負けにある**ので、
`getComputedStyle` で実測しながら直すこと（推測で直さない）。

### P0-2. 保存できない状態なのに「並べ替え」を始められる ✅ 確認済み（報告1）

| | |
|---|---|
| 対象画面 | Library の作業バー |
| 幅 | 390px / 900px / 1440px すべて |
| 再現方法 | 検索欄に何か入力する →「並べ替え」を押す → 入れる。入った直後に「保存できません」と出る |
| 利用者が困ること | 始めてから駄目だと分かる。しかも入った先で検索欄が消え、スマホでは下のナビも消える |

**実測**:
- 「並べ替え」ボタンの `disabled` 条件に、検索・絞り込みの状態が入っていない
  （入っているのは「公開ギャラリーが手動順でない」「手動順が壊れている」「取り込み中」「ゴミ箱表示中」だけ）。
- 入った直後の画面文言は「検索・絞り込み中のため、いまは並び替えを保存できません（シリーズ単独の絞り込みなら可）。」
- 並べ替えモード中は検索欄が**消える**（`libraryMode !== "arrange"` の中にあるため）。
- スマホでは**下のナビ（写真／見せ方／サイト）も消える**。
- 戻る手段は「並び替えできる状態に戻す」ボタン1つ。これは絞り込みを解除する操作であって、
  「並べ替えをやめる」操作ではない。

**保存できる条件は3つだけ**（コードで確認）:
1. 表示の並び順が「手動」であること
2. 絞り込み・検索が何も無い、**または**シリーズ1つだけの絞り込みであること
3. 公開ギャラリーの並び順設定が「手動」であること

つまり「シリーズだけの絞り込み」は並べ替えできる。ここは**残す価値がある**ので、
「絞り込み中は一切禁止」にはしない。

### P1-1. 検索しただけで「絞り込み 1」と出る ✅ 確認済み（報告3）

| | |
|---|---|
| 対象画面 | Library の作業バー |
| 幅 | すべて |
| 再現方法 | 検索欄に1文字入れる → 隣の虫めがねボタンに「1」が付く |
| 利用者が困ること | 解除し忘れた条件が残っていると誤解する。実際は検索語そのものを数えている |

**実測**: バッジの数は「適用中の条件」の配列の長さで、その配列の**先頭が検索語**になっている。

さらに悪いことに、この虫めがねボタンは**検索欄の中の虫めがねと同じ絵**である。
スマホでは文字が消える設定（`font-size: 0`）になっているため、
**虫めがねが2つ並んでいて、片方が検索、片方が絞り込み**という状態になる（390pxのスクリーンショットで確認）。

### P1-2. スマホで写真が見えるまでに画面の4割を使う ✅ 確認済み（報告5の実体）

| | |
|---|---|
| 対象画面 | Library |
| 再現方法 | 390px で Library を開く |

**実測（作業バーの高さ）**:

| 画面幅 | 作業バーの高さ | 最初の写真が出るまで |
|---|---:|---|
| 1440px | 57px | 画面の約30% |
| 900px | 109px | — |
| 390px | **162px** | **画面の約39%**（上部バー＋見出し＋作業バーの合計） |

絞り込みを開くと、同じ帯の中に**さらに11個**の操作が増える（合計27個が1本の帯に入る）。
390pxでは写真が**1枚も見えなくなる**。

「特に画面幅が中程度のとき探しにくい」という報告も再現した。900px では作業バーが
2段に折り返して109pxになり、モード切替・検索・絞り込み・表示・Table・Trash・
媒体・取り込むが2段に散る。

### P1-3. 複数選択の操作欄が画面の中ほどに居座り、写真を押し出す ✅ 確認済み

| | |
|---|---|
| 対象画面 | Library の選択モード |
| 再現方法 | 390px で「選択」→ 写真を1枚押す |
| 利用者が困ること | 操作欄が308px（画面の36%）を占め、選んでいる写真が下へ押し出される。何を選んだか見ながら操作できない |

**実測（390px）**: 選択操作の帯は `position: static`（画面下に固定されていない）。
高さ308px、写真グリッドは y=1560/2216（画面の70%）から始まる。
1440px でも104pxを占める。

**枚数表示が2か所にある**。見出しに「1 selected」（英語）、帯の中に「選択中 1枚」（日本語）。

### P1-4. 写真編集が1本の長い巻物になっている ✅ 確認済み

| | |
|---|---|
| 対象画面 | 写真編集（インスペクタ） |
| 再現方法 | 390px で写真を1枚押す |

**実測（390px）**:
- シートの見える高さ **505px**、中身の長さ **1968px**。**見えているのは4分の1**。
- 中の操作は **38個**が区切り無しに縦1列。
- 「保存」は下から4番目。**画面3.5枚分スクロールしないと届かない。**
- Settings / Profile / Portfolio Kit には「未保存／保存中／保存しました／失敗」を出す
  固定バー（`FloatingSaveBar`）があるのに、**写真編集にはない**。同じ「保存」が画面ごとに別物になっている。

1440px でも中身1908pxに対し見える高さ860pxで、やはり保存は下端。

### P1-5. 指で押しにくい大きさが残っている ✅ 確認済み

**実測（390px・実タッチ端末プロファイル）**:

| 操作 | 実測サイズ | 目安（40px）に対して |
|---|---:|---|
| 「表示」メニュー | **26 × 32px** | 不足 |
| 絞り込みの各セレクト（カテゴリ・シリーズ・サイズ・媒体・向き・公開状態・時期） | 高さ **36px** | わずかに不足 |
| 写真編集のタイトル／カメラ／レンズ／撮影日 | 高さ **36px** | わずかに不足 |
| 検索欄そのもの | 高さ **22px**（枠は40px） | 実質は枠が受けている |

いまの実ブラウザテスト（`admin-touch-targets.spec.ts`）は
**Series / Pricing / Categories の一覧行しか見ていない**。Library の作業バーと
写真編集は検査対象外なので、この不足は自動では見つからない。

### P2-1. 日本語表示なのに英語が残っている ✅ 確認済み（報告2）

実測で見えたもの（固有名詞＝タブ名 Library / Hero / Series などは対象外）:

| 場所 | 出ている英語 |
|---|---|
| スマホ上部バー | `Site` / `Logout` |
| Library 見出し | `497 / 497 photos` |
| 作業バー | `Table` / `Trash` |
| 絞り込み | `All (497)` / `All series` / `All sizes` / `All orientations` / `All time` ／ 一方で「媒体: All」「公開状態: All」は**日本語と英語が同じ1つの操作の中で混ざっている** |
| 選択モード | `Set Category` / `Set Series` / `Size` / `Rotate` / `Date` ／ 見出しの `1 selected` |
| 写真編集 | `EDIT PHOTO` / `Size M` / `Copy` / `Paste` |
| 写真編集の入力例 | `Untitled` / `Photo description...` |
| 一覧の空表示・ゴミ箱 | `Trash` / `Purge All` |
| ログイン | `Sign in` / `Portfolio Admin` |

日本語辞書の中に英語のまま残っている項目が、機械的に数えて**60件以上**ある
（`admin-i18n.tsx` の日本語ブロック内で、日本語を1文字も含まない文字列）。
このうち入力例（placeholder）と固有名詞を除いた、**実際にラベルとして出るもの**が上表。

さらに `admin.tsx` / `admin-tabs.tsx` には辞書を通さず**直接書かれた英語**がある
（`Table` `Trash` `Untitled` `Photo description...` `RECOMMENDED` `Replace` など）。
これは言語を切り替えても変わらない。

### P2-2. 日付の入力欄が `mm/dd/yyyy` で出る ✅ 確認済み

選択モードの「Date」欄が、日本語表示のまま**アメリカ式の日付**で出る（390pxのスクリーンショットで確認）。
ブラウザ標準の日付入力をそのまま使っているため。写真家が日付を打つ場所としては読み違えを招く。

### P2-3. Settings に制作者向けの用語が出る ✅ 確認済み（報告4）

**実測**: Settings タブの表示文字列に `ADMIN_PASSWORD` `SITE_URL` `JSON-LD` `Formspree`
`OGP` `canonical` `sitemap` が含まれる（390 / 900 / 1440 すべて）。

ただし**Settings 全体が悪いわけではない**。スマホの Settings は
「現在地：サイト基本情報／切り替え」という**1節ずつ表示する形**になっていて、
ラベルは日本語で、行は下罫線だけの静かな作りになっている。**ここは良い部分なので壊さない。**

問題は語彙だけである。項目は19節・約150個あり、そのうち写真家が日常で触るのは
ごく一部。「よく使う」と「詳しい設定」に分けるだけで、迷いはかなり減る。

### P2-4. 検索結果0枚の表示が「よくあるAIの空画面」になっている ✅ 確認済み

中央にイラスト＋2行の説明＋ボタン。`admin-renewal-goal.md`「AI感の削減」で
**避けると決めた型そのもの**（「空状態が毎回『中央寄せの大きなイラスト＋2行の説明＋ボタン』の型」）。

同じ画面で、検索欄に**✕が2つ並ぶ**（ブラウザ標準の消去と、アプリ自前の消去）。

### P2-5. 「絞り込みを解除」が1か所からしか押せない ✅ 確認済み

0枚のときは空表示の中にボタンが出る。しかし**写真が残っているとき**（例：検索して30枚出ている）は、
条件をまとめて外す入口が作業バーに無い。1つずつ「All」に戻す必要がある。

### 推測（未確認）

- **通信が遅い／失敗したとき**の見え方は今回確認していない。保存の失敗表示は
  Settings 系には `FloatingSaveBar` があるが、**写真編集と一括操作については実測していない**。
  実装前に Codex へ確認させる（下記 依頼4 の完成条件に入れた）。
- **写真0枚のとき**の Library は、本番に497枚あるため確認できていない。
  取り込み前の初期状態はデモ用データで確認するのが安全。
- **長い写真名・長い説明文**は、一覧では影響しない（写真カードに文字を出していないことを実測）。
  影響するのは写真編集と Table 表示。ここは未確認。

## 2. 改善後の画面構成

**大きな作り直しはしない。** 良い部分（静かな配色、細い罫、写真が主役、
Settings の1節ずつ表示、下部3グループのナビ）はそのまま残す。

### 2-1. 共通の約束（デスクトップ・スマホ共通）

1. **「いまの状態」は文字で読めること。** 塗りだけで状態を示さない。塗るなら文字は紙色にする。
2. **保存の位置と言葉を全画面で揃える。** 変更があるときだけ下から出る帯に
   「未保存 → 保存中 → 保存しました → 失敗（やり直す）」を出す。写真編集も同じ帯を使う。
3. **閉じる／戻るは常に左上、実行は常に右（スマホは下端の帯）。**
4. **押せるものは最低40px。**
5. **できない操作は、押させてから断らない。** 押せないなら押せない見た目にし、
   理由を1行そえる。

### 2-2. Library — デスクトップ（1200px以上）

いまの1本の帯を、**役割で2つに割る**。増やさずに整理する。

```
┌─────────────────────────────────────────────────────────┐
│ Library                              [ サイトで確認 ]    │  見出し（現状のまま）
│ 497 / 497 枚                                             │  ← "photos" を「枚」へ
├─────────────────────────────────────────────────────────┤
│ [閲覧|選択|並べ替え]  │ 🔍 写真を検索…  [絞り込み ▾]     │  ← 左＝いま何をするか
│                       │           [表示 ▾] [取り込む]    │  ← 右＝道具
├─────────────────────────────────────────────────────────┤
│ 適用中: 「桜」 ×   カテゴリ:portrait ×      すべて解除    │  ← 条件がある時だけ出る1行
└─────────────────────────────────────────────────────────┘
```

- **絞り込みは「開くと帯が伸びる」のをやめ、押した位置から下に落ちるパネルにする。**
  写真グリッドを押し下げない。
- **適用中の条件は独立した1行**にし、条件が無いときは行ごと消す。
  各条件に ×、右端に「すべて解除」。
  → P1-1（検索が絞り込みに数えられる）と P2-5（まとめて解除できない）が同時に解ける。
  **絞り込みボタンのバッジは「検索を除いた条件の数」にする。** 検索語はこの行に別に出す。
- `Table` → 「表計算のように編集」、`Trash` → 「ゴミ箱」。
- 絞り込みボタンの絵を虫めがね以外にする（検索と見分ける）。

### 2-3. Library — スマホ（767px以下）

```
┌──────────────────────────┐
│ Library      JP|EN サイト 出る│  上部（Site/Logout を日本語へ）
├──────────────────────────┤
│ 497 / 497 枚              │  見出しは1行に圧縮
├──────────────────────────┤
│ 🔍 写真を検索…      [絞り込み]│  ← 1段だけ。虫めがねは1つ
├──────────────────────────┤
│ 「桜」×  portrait ×  解除  │  ← 条件がある時だけ
├──────────────────────────┤
│                          │
│      写真グリッド          │  ← ここが早く始まる
│                          │
├──────────────────────────┤
│ 写真 │ 見せ方 │ サイト      │  下部ナビ（現状維持）
└──────────────────────────┘
```

**変える点**

1. **作業バーを162px→80px程度にする。** 手段:
   - モード切替（閲覧／選択／並べ替え）を帯から外し、**下部ナビの上に出る「選ぶ」ボタン1つ**にする。
     または見出し右の「…」に入れる。スマホで日常的に押すのは「選択」だけで、
     「並べ替え」は稀（後述の理由で、そもそもスマホでの並べ替えは条件が厳しい）。
   - 媒体（デジタル／フィルム）と「取り込む」は**取り込み時だけ必要**なので、
     「取り込む」を押したあとに媒体を聞く形にして、常設をやめる。
   - `Table` と `Trash` は**「表示」メニューの中**へ入れる（常設をやめる）。
2. **絞り込みは全画面のシートで開く。** 帯を伸ばさない。
   中は「カテゴリ／シリーズ／公開状態」を上、
   「サイズ／媒体／向き／時期／未入力／アルバム」を「詳しい条件」として折りたたむ。
   下端に「解除」と「N枚を表示」を固定する。
3. **選択中は、操作を画面下に固定する。**
   ```
   ┌──────────────────────────┐
   │        写真グリッド         │  ← 選んだ写真が見えたまま
   ├──────────────────────────┤
   │ 3枚を選択中          やめる │
   │ [公開] [分類] [並び] [その他]│  ← 4つまで。残りは「その他」シート
   └──────────────────────────┘
   ```
   よく使う4つだけ出し、残り（回転・見せる中心・撮影日・Hero・一括編集・ゴミ箱）は
   「その他」のシートへ。**枚数表示は下の帯1か所だけ**にする（見出しの `1 selected` は消す）。

### 2-4. 写真編集（インスペクタ）— デスクトップ・スマホ共通

**38個を1列に並べるのをやめ、3つに分ける。** 分け方は写真家の作業に合わせる。

| 段 | 入るもの | いつ触るか |
|---|---|---|
| **基本** | 写真／公開・非公開／表示サイズ／向き（回転）／タイトル | 毎回 |
| **分類** | カテゴリ／シリーズ／見せる中心 | 整理するとき |
| **詳細** | カメラ／レンズ／フィルム・デジタル／撮影日／説明／使用状況／ファイル情報 | 必要なとき |

- スマホは**上部の3つの見出しで切り替え**（横スクロールしない）。
- デスクトップは**縦に3つの節**として並べ、「詳細」は折りたたみ。今の1画面性を失わせない。
- **「保存」はシートの下端に固定する。**（現状は下から4番目、3.5画面分下）
  Settings と同じ `FloatingSaveBar` を使い、
  「未保存です」→「保存中」→「保存しました」→「保存できませんでした（やり直す）」を出す。
- **「この写真を複製」「ゴミ箱へ」は保存の帯から離す。**「詳細」の末尾に置く。
- `EDIT PHOTO` → 「写真の編集」。`Copy`/`Paste` → 「機材をコピー」「機材を貼り付け」。
  `Untitled` → 「（無題）」。`Photo description...` → 「この写真の説明」。

### 2-5. 並べ替え

**「保存できない状態では始められない」ようにする。**

- 「並べ替え」ボタンを、次のときは押せない見た目にし、理由を1行そえる:
  - 表示の並び順が「手動」以外
  - 検索語がある／シリーズ以外の絞り込みがある
  - 公開ギャラリーの並び順が「手動」以外
- 理由の文は**やり方まで書く**。例:
  「検索中は並べ替えできません。検索を消すか、シリーズ1つだけの絞り込みにしてください。」
- 押せない理由が「解除すれば消える」ものなら、その1行に
  **「解除して並べ替える」ボタン**を置く（1回で通す）。
- 並べ替え中も**「並べ替えを終了」を常に左上に出す**（現状もあるが、
  スマホでは下部ナビが消えるため、終了以外の逃げ道が無い状態になっている）。
- **シリーズ1つだけの絞り込みは、いままでどおり並べ替えできる。** ここは機能として残す。

### 2-6. Settings

いまの「1節ずつ表示」は良い。**語彙だけ直し、節の並びを2階建てにする。**

- **通常設定**（写真家が意味を判断できるもの）
  サイト基本情報 / Hero / ナビ / 余白 / 質感 / 写真の出方 / ギャラリーの並び /
  シリーズ / note / プリント / ご案内 / 配色 / 書体 / 文字サイズ / 文字色 / 字間 / 文言 / 機材プリセット
- **詳しい設定**（初期値のままで動く。触らなくてよい）
  - `Formspree の URL` → 「お問い合わせの送り先（フォーム連携）」
    説明：「お問い合わせフォームを動かすための連携先。設定した人以外は触らなくて大丈夫です。」
  - `siteUrl`（説明に `sitemap・canonical・OGP・JSON-LD`・`SITE_URL`）
    → 「サイトの正式なURL」
    説明：「検索やSNSに出るときの住所。空欄なら自動で決まります。」
  - `googleSiteVerification` → 「Google の所有権確認コード」
  - `ADMIN_PASSWORD` の案内 → 「管理画面のパスワード」
    説明：「変更はサーバー側の設定で行います。この画面からは変えられません。」

**原則**: 機械の名前（`SITE_URL` など）は消さずに、
**日本語の説明を先に置き、機械の名前は小さく後ろへ**。消すと、いざ困った時に調べられなくなる。

## 4. 既存機能を壊さないための条件

### 4-1. 減らしてはいけない機能（今ある操作は全部残す）

- Library: 検索 / カテゴリ / シリーズ / サイズ / 媒体 / 向き / Hero設定中 / 公開状態 /
  撮影日なし / 機材なし / アップロード時期 / アルバム / 表示の並び替え / サムネイルサイズ /
  列数（2・3） / Table 表示 / ゴミ箱 / 取り込み（デジタル・フィルム） / キーボードショートカット
- 選択モード: 公開 / 非公開 / カテゴリ / シリーズ / サイズ / 回転 / 見せる中心を中央へ /
  撮影日の一括適用 / フィルムの撮影日クリア / Hero に追加・外す / 一括編集 / ゴミ箱へ
- 写真編集: 公開 / サイズ / 回転 / カテゴリ / シリーズ / 見せる中心 / タイトル / カメラ /
  レンズ / 機材コピー・貼り付け / フィルム・デジタル / 撮影日 / 説明 / 保存 / 元に戻す /
  複製 / ゴミ箱へ / 使用状況 / ファイル情報
- **移動させた操作は、必ず「どのモード・どの状態で出るか」を別に確かめる。**
  2026-07-31 に、取り込み一式を移設した結果**選択モード中に取り込めなくなった**事故がある
  （見た目のテストは全部通っていた）。同じ形の事故が今回いちばん起きやすい。

### 4-2. 保存・公開の安全条件（絶対に緩めない）

- **写真の並べ替えの競合検知（`photo-reorder-safety.ts`）を壊さない。**
  「押せなくする」のは入口の条件だけ。保存時の検査（`reorderLockReason` /
  期待ID列の突き合わせ）は**そのまま残す**。入口を締めた代わりに出口を緩めない。
- **シリーズ1つだけの絞り込みでの並べ替えは、いままでどおり通す。**
  `onlySeriesFilter` の条件（シリーズ以外が全部「無し」）を変えない。
- **書き込みの応答は本文を読む前に検証する。** admin 配下は
  `admin-shared.ts` の `assertOk` / `jsonOrThrow`（401 をログイン画面へ送るため）。
- **settings の保存は必ず `postAdminSettings()` を通す。**
  許可リスト外のキーは無視され `ignoredKeys` で返るため、`assertOk` だけでは
  「保存成功」の表示のまま一部が保存されない。
- **新しい保存経路には、応答検証に加えて画面に見えるエラー表示を必ず付ける。**
  写真編集に `FloatingSaveBar` を付けるとき、「失敗」が本当に画面に出ることを確かめる。
- settings キーを増やす場合は4箇所同期（`settings-preview.ts` / API default /
  `provider.tsx` のDB適用 / `handlePreviewMessage`）。**今回は増やさない想定。**
- 表示だけの変更に見えても、`aria-pressed` / `aria-expanded` / `disabled` を触ると
  既存の実ブラウザテストが読む目印が変わる。**目印（`data-library-*`）は消さない。**

### 4-3. いまのテストで足りないところ

| 足りないもの | 今の状態 |
|---|---|
| Library 作業バー・写真編集の**指の当たり判定** | `admin-touch-targets.spec.ts` は Series / Pricing / Categories の一覧行だけ |
| 「選択中」のラベルが**読めるか**（文字色と背景色の差） | 検査が無い。`admin-theme-contrast.test.ts` はテーマ色だけ |
| 「並べ替え」が**押せない状態になるか** | `admin-reorder-safety.spec.ts` は保存時の安全を見ているが、入口の可否は見ていない |
| 絞り込みバッジが**検索を数えないこと** | 検査が無い |
| 写真編集の**保存の見え方**（未保存・保存中・完了・失敗） | `admin-save-state.spec.ts` があるが対象を要確認（Codex に確認させる） |
| スマホでの**作業バーの高さ**（写真が早く出ること） | 検査が無い |
| 日本語表示に**英語が出ていないこと** | `admin-i18n.spec.ts` があるが、上表の英語は素通りしている |

**加えるべき自動確認は、依頼ごとの完成条件に書いた。**

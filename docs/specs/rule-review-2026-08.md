### 2-2. なぜ使われなくなったか（推測を含む）

**確認済み**: 起動経路は `codex exec` で、**担当範囲・禁止操作・停止条件が自動では渡らない**
（`codex-workflow.md`「レーンの選び方」）。依頼のたびに全部プロンプトへ書く必要がある。
これが1回15〜25分の主因である。

**推測**（根拠を伴わないので断定しない）: 作業の主戦場が「実装」から「文書整理・
検証・小さな修正」へ移り、独立した第二意見の費用対効果が下がった。
また Codex の週枠は hook が毎回「少ない」と報告している。

### 2-3. 案（3つ。畳む案を含む）

#### 案A. 畳む — 規則ごと廃止し、必要なら都度呼ぶ

`codex-workflow.md`（180行）と `codex-agents/*.toml` を archive へ。
`AGENTS.md`「現在の役割」と `CLAUDE.md`「Codex へ渡す最小情報」を削除。
`handoff-workflow.md` の Codex 節を残し、**「使いたくなったらここを見る」**だけにする。

- **良くなること**: 守られていない規則が消え、文書が約210行減る。
  A層も12行減る。「規則にあるのに誰もやっていない」状態が解消する
- **捨てること**: **独立した第二意見の仕組み。**上の4件のような「実装前に落とせた
  手戻り」は、今後 Claude の自己点検だけに依存する。
  過去に2回、Codex が正しく Claude が誤っていた実例がある

#### 案B. 1用途に絞って残す — 「反対レビューだけ」

実装委託・モデルのレーン・Phase A〜E・TOML をすべて畳み、
**読み取り専用の反対レビュー（旧 Phase C）1つだけ**を残す。
発動条件も1行にする：**「本番DB・課金・公開・認証に触る変更の前だけ」**。

- **良くなること**: 実測で最も効いた用途（反論を要約せず残す）が残る。
  文書は180行→20行程度。発動条件が1つなので判断に迷わない。
  push を解禁した今、**本番に届く変更の前に第二の目がある**価値は上がっている
- **捨てること**: 定型作業の外注（文言・日本語化・一次スキャン）。
  これは Claude が自分でやるので総時間はやや増える

#### 案C. オーナーの承認待ちを Codex に置き換える

いまオーナー判断待ちが6件溜まっている。Codex を**「オーナーの代わりに反論する役」**
として使い、判断待ちを減らす方向に振る。

- **良くなること**: オーナーが非開発者で判断材料を作るのに時間がかかる問題に効く。
  「AとBどちらか」をオーナーへ出す前に、Codex に両案を潰させて選択肢を減らせる
- **捨てること**: **オーナーの決定権が実質的に薄まる危険。**
  Codex が潰した案はオーナーの目に触れない。
  この案は、上の危険を許容できるかがすべてで、**私は推奨しない**

### 2-4. 推奨

**案B。** 理由は3つ、いずれも実測に基づく。

1. 実際に効いた4件は**すべて反対レビュー由来**であり、実装委託由来ではない。
2. push を解禁した以上、本番へ届く経路が1つ増えた。**そこにだけ第二の目を置く**のは、
   費用（1回15〜25分）に見合う数少ない用途である。
3. 案Aは、いま守られていない規則を消す点では正しいが、**2回実証されている
   「Codex が正しく Claude が誤っていた」**という保険まで同時に捨てる。
   使用実績が0に近いのは規則が重すぎたからで、用途が無いからとは限らない。

**案Aを選ぶのが妥当な条件**: 今後3か月、本番DB・課金・認証に触る予定が無いなら、
案Bの残す理由も消えるので案Aでよい。

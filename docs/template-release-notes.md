### DBマイグレーションについて（この版で「可」と判断した理由）

手順書は「DBマイグレーションがある版は追加だけでも原則『不可』」としています。
この版はその原則の例外ではなく、**原則が求める「版ごとのバックアップ・復旧手順」を
用意したうえで「可」**としています。

中身は `photos` テーブルへの **ADD COLUMN が7本だけ**です。

```
shot_at_source (text, NOT NULL, 既定 'legacy')
shot_at_digitized / source_width / source_height /
source_format / camera_make / camera_model  (すべて空を許す)
```

- 列を消したり、型を変えたり、既存の値を書き換えたりはしません。写真も設定も消えません。
- マイグレーションは**サイト起動時に自動で当たります**。担当者の操作は要りません。
- **前の版へ戻すのは安全です。** 足した7列は古いプログラムが知らない列で、読み書きの
  対象になりません。`shot_at_source` は既定値を持つので、古いプログラムが写真を
  追加しても値が入ります。**ただしDBの形は戻りません**（列は残ります）。実害は
  ありませんが、「完全に元通り」ではないことは知っておいてください。

### 更新前に必ずやること（この版だけの追加手順・約2分）

1. Railway で、その写真家の project の **Postgres サービス**を開く。
2. **Backups**（または Data → Backup）から手動バックアップを1つ作る。
3. 作成時刻をメモしてから、[template-update-guide.md](./template-update-guide.md) の
   「10分更新」へ進む。

バックアップを取らずに進めないでください。列を足すだけとはいえ、DBの形が変わる
更新は、これまでの版には1つもありませんでした。

### 主な改善（177件のうち、配布先で目に見えるもの）

**公開サイト**

- 絞り込んだギャラリーから他のページへ行って戻ると、見ていた位置と枚数が戻る
- 読み込み中に矢印キーを押してもトップの写真が消えない
- JP / EN を押したときに、ページの言語の印が実際の表示に追従する
- 問い合わせの送信に失敗したとき、書いた本文を持ったままメールへ切り替えられる
- ページごとに違っていた左右・上下の余白が揃い、移動のたびに本文が横へずれない
- 長い語や長いシリーズ名で、画面が横に伸びたり文字が枠から出たりしない
- 日本語の本文が文節の切れ目で折り返す
- 写真ビューアの壁を「白い展示壁 / 暗室 / 生成りの紙」から選べる
- シリーズ一覧の札、フッター、Contact の構成、各ページの見出しの型を選べる
- トップに作家自身の言葉を置ける
- サーバー不調を「シリーズがありません」「写真がありません」と言わなくなった
- **写真を1枚も登録していない状態でも、灰色の板や濃い色の面が出ない**

**管理画面**

- 作風プリセットで、4つの佇まいを Settings から選べる
- ゴミ箱に「すべて戻す」がついた（以前は一括操作が「すべて完全削除」だけだった）
- Series と Pricing の書きかけが、タブを移っても閉じても警告なく消えることがなくなった
- 読み込みに失敗したときに「まだありません」と表示しなくなった（ゴミ箱・シリーズ・
  カテゴリ・料金）
- 分類を削除するとき、何枚が未分類になるかと、戻せないことが出る
- 画面に残っていた英語の直書きが日本語になった

**買った人のサイトとして**

- Contact の初期文から、**自分で決めていない約束**（返信日数・納品期間）が消えた。
  件名の選択肢からも制作者向けの項目が消えた

# Claude Code / Codex 実行ワークフロー

> Current. 2026-07-27更新。旧「期間限定の役割反転」「Sonnet/Fable時代」
> 「許可後はAIがpush可能」という記述は廃止した。

## 目的

設計と実装を分けつつ、同じworktreeの同時編集、古いHandoff、過剰な往復を防ぐ。
共通の安全境界は`AGENTS.md`、現在地は`task.md`冒頭Current Stateが正本。

## 基本フロー

1. Claudeがオーナーと目的・完成条件・変更範囲・禁止操作・検証・停止条件を確定する。
2. ClaudeがCurrent Stateを更新し、編集者をCodexへ引き継ぐ。
3. Codexが合意済み範囲だけを実装し、関連するローカル検証と自己確認を行う。
4. CodexがCurrent Stateへ変更、検証、未検証、次の一手、commit/push/production状態を残す。
5. Claudeが前の編集者の停止を確認後、read-onlyで重要差分と高リスク項目を独立検証する。
6. commitが依頼範囲ならCodexが1タスク1commitにまとめる。pushはオーナーだけが行う。

モデル名、関数名、全判断手順は固定しない。安全境界と完了の判定を固定する。

## Codexの使い分け（Phase）

- **A 独立調査**（読み取り専用）: 原因・関連箇所・代案・リスクを、Claudeの仮説と独立に出す。
- **C 反対レビュー**（読み取り専用・別セッション）: 計画への賛同を求めない。破綻条件、
  見落とし、より簡単な代案、Claudeの仮説の誤りを探す。問題が無ければ「無し」でよい。
- **D 実装**: 合意済みの範囲を実装する。
- **E 独立検証**: Claudeが差分と必須検証を確認する。

A・Cの出力は次の4区分で書かせる。

1. 確認済み事実 2. 推測 3. 未解決の反論 4. 推奨

**Claudeは「未解決の反論」を書き換えない。** 各項目へ「採用 / 不採用 / オーナー判断待ち」と
理由を1行だけ追記する。この記録はDへ渡す共通記録とし、短い要約に置き換えない。

## 発動条件（段数は固定しない）

| 状況 | Codex実行 | 内容 |
|---|---:|---|
| 低リスク | 1 | Dのみ |
| 中・原因が明確 | 1 | Dのみ |
| 中・原因不明 | 2 | A → D |
| 高・計画への異論が大きい | 3 | A → C → D |
| 高・計画は確定、実装事故が主な心配 | 2 | D → 実装後レビュー |
| 高・クレジット残量不足 | 0 | 延期または範囲縮小 |

- 原因が明確な中リスク作業に、AやCを機械的に強制しない。
- **高リスクでクレジットが不足するとき、安全工程を省いて進めない。**
  延期するか範囲を縮小する（`docs/agents/credit-status.md`）。
- **CとDの実装後レビューを無条件に両方行わない。**原則どちらか一方。
  ただしDB・本番・公開に影響する差分では、実装後の差分レビューを優先する。
- 代案は、成立する選択肢が複数あるときだけ2〜3案を求める。案の数を目的にしない。

この発動条件は 2026-07-28 から試用中。記録先は `docs/agents/codex-flow-trial.md`。

## モデルの使い分け

2026-07-30 に GPT-5.6 Luna が最大80%値下げされ、Codex の使用量カウントにも反映された。
安いレーンへ定型作業を逃がすと、上位モデルの枠を実装の難所へ回せる。

| レーン | エージェント名 | モデル / effort | 担当 |
|---|---|---|---|
| 設計・受け入れ | Claude Code | — | 目的・完成条件・安全境界・独立検証 |
| 定型 | `eguchi_luna_routine` | Luna / max | 文言、日本語化、定型テスト、リネーム、一次スキャン |
| 主実装 | `eguchi_terra_impl` | Terra / max | 文脈が重い実装、承認済み挙動に触れる変更 |
| 反対レビュー・実装後レビュー | 都度指定（Sol 系） | Sol / high 以上 | Phase C / E |

- **Luna へ回してよいのは、仕様が確定していて判断が要らない作業だけ。**
  外部ベンチでは Luna は effort を max にしてもコンポーネント設計の評価が伸びにくく、
  このリポジトリの主戦場である admin の React UI はその弱点に重なる。
- **settings の4箇所同期、`withRetry`、`assertOk`、DB schema、認証は Luna に投げない。**
  動くが後で壊れる型の事故が出やすい。
- 安いモデルでも effort を上げれば消費は増える。レーンを増やした分は積み上がるので、
  「Luna なら無料」ではない。品質不足で作り直すと逆に高くつく。
- 判断が要る作業を Luna が受け取ったら、実装させず停止させる（TOML に明記済み）。

エージェント定義の正本は `docs/agents/codex-agents/*.toml`。導入先の `.codex/` は
ローカル専用（`.gitignore` 済み）なので、次で同期する。

```sh
sh scripts/ai/install-codex-agents.sh          # 導入（既存が違う内容なら上書きせず失敗）
sh scripts/ai/install-codex-agents.sh --check  # 導入済みと正本の一致を検査
```

導入後は Codex のタスクを新しく開始する。エージェントはタスク作成時に発見される。

**`sol-advisor` プラグインは導入しない。** 構成はこの表とほぼ同じで、得られるのは
モデル割り当てだけであり、第三者のプラグインがインストール時と実行時にシェルスクリプトを
走らせる分だけリスクが増える。同じ効果はこの TOML 2本で足りる。

**ChatGPT / Codex の "Full access" は有効にしない。** 承認なしに任意のファイルを編集し、
ネットワーク付きでコマンドを実行できるモードで、`AGENTS.md` の安全境界と両立しない。
max effort の有効化は Configuration 側の設定であり、Full access とは無関係。

## Codexへの依頼

最低限、次を渡す。

- 目的と背景
- 完成条件
- 変更してよいファイルまたは範囲
- 禁止操作と`AGENTS.md`の該当不変条件
- **今回の変更が触れうる承認済み挙動**（仕様書の場所と、壊れたときの症状を添える）
- 実行する検証
- 不明時・範囲超過時の停止条件
- Current State更新とcommit要否

ファイル本文や巨大diffを貼らず、Codex自身に必要部分を読ませる。
低リスク作業で不要な往復や同じゲートの二重実行を増やさない。

## 実行とresume

正確な現行コマンドは`docs/agents/handoff-workflow.md`が正本。

- 新規実行: `codex exec -s workspace-write ...`
- resume: 先にrepoへ`cd`し、`codex exec resume <session-id> ...`
- **古いセッションを別課題へresumeしない。** 同一実装の継続と、通信切断からの
  復旧ではresumeしてよい。
- 現行CLIの`resume`には`-C`と`-s`が無い。旧
  `codex exec resume --last -C <project>`は使わない。
- `scratch/codex-out-*.log`先頭のsession IDを使う。ログ本文をHandoffへ転載しない。
- 接続切れと実装失敗を区別し、Gitに途中成果があれば新規sessionで重複実装しない。

## 検証の分担

- Codex: 実装に直接必要なローカル検証、失敗時の範囲内修正
- Claude: 実装後の独立レビュー、製品変更の最終`bun run check`、
  admin変更の`bun run smoke`
- AI運用だけの変更: 対象test、JSON/Markdown/script構文、差分範囲を確認

ネットワークや実機が必要で実行できない検証は、成功扱いにせず「未検証」と記録する。

## クレジット低下時

クレジット状態は`docs/agents/credit-status.md`に従う。closing以下では新しい工程を始めず、
Git状態、変更ファイル、検証、未完了、次の一手、禁止範囲、session/logを
Current Stateへ残す。hookは`task.md`を自動編集しない。

## 短い報告

1. 変更ファイル
2. 変更内容
3. 実行した検証と結果
4. 未解決・未検証
5. リスクまたはオーナー判断
6. commit hash
7. local / push / Railway / productionの各状態

全ログ、ファイル全文、巨大diff、認証情報は返さない。

# 秋さん向け・AI運用手引き

2026-09-05更新。AIへの依頼は、やってほしい結果を日本語で伝えれば始められます。
作業の判断基準は [AGENTS.md](../AGENTS.md) が正本です。

## 頼み方

たとえば「スマホで写真を選びやすくして」「今回の変更を公開まで進めて」で十分です。
AIの種類や細かい手順を指定する必要はありません。現在地は [task.md](../task.md)、
候補は [未完了の作業](agents/backlog.md) にあります。古い候補はAIが実物と照合します。

通常の改善は、必要な検証・commit・push・本番確認までAIが進めます。
「調査だけ」「ローカルで見せて」と指定した場合は、その範囲で進めます。
すでに許可した操作について、同じ許可を繰り返し出す必要はありません。

## 報告で見るところ

- **何が良くなったか。** 見られるURLと、変わった画面や操作。
- **どこまで確かめたか。** 変更に合った検証の結果と、まだ確認できていない点。
- **どこまで届いたか。** ローカルの修正、commit、GitHubへのpush、本番の反映。

pushするとRailwayが本番への反映を始めます。push成功だけでは反映完了とは限らないため、
AIが本番のbuildと対象画面を確認します。公開サイトは <https://akieguchi.com/> です。

## 困ったとき

表示がおかしければ「この画面を直して」と状況を伝えてください。AIは原因を調べ、
必要なら [戻し方](rollback-guide.md) を使います。失敗の回数だけで中断せず、
原因や別の方法を調べます。

判断や許可が必要な場合は、AIが対象・影響・必要な理由を具体的に示します。
文書の指示を理由に止まった場合は、そのファイルと該当文も報告に含まれます。
途中で方針を変えたいときは、そのまま伝えてください。「止めて」で中断できます。

パスワードや `.env` の値はチャットへ貼らず、必要な設定名だけを伝えてください。

詳しい資料は [ドキュメント索引](README.md)、分野別の確認は [checklists.md](checklists.md) を参照してください。

# PDF作品集 v0 — 管理者向け初版

2026-09-27。依頼元は `portfolio-kit-web-pdf-v0-spec.md` のA段階。
2026-09-27、オーナーが本番公開を承認。PDFの4コミットだけを最新本番コードへ移し、統合後の全体検証と公開確認を行う。検証中に別作業の写真中心サイトがmainへ公開されたため、公開済みmain（6555e4a）を取り込み直した。PDF機能自体にDB変更はない。

## 使い方

このcheckoutで `bun install --frozen-lockfile` → `bun run try:pdf`。
`http://localhost:5499/admin/pdf` を開き、起動時に表示する一時パスワードでログインする。
既存の隔離サーバーを使い、人工画像・一時SQLite・localhostの偽ストレージのみ。本番DB・`.env`には接続しない。
別途、通常の認証済み管理画面の「PDF作品集」からも入れる。デモの認証を迂回しない。

1. 既存画像を最大20枚選ぶ。本の名前・氏名・任意の表紙写真を指定。
2. ページ一覧から一頁を選び、大きな用紙を見ながら編集。ドラッグ／前後ボタンで順番を変更し、2枚組・分割・交換・90度回転を調整。
3. 「提出用／写真集」を選ぶ。提出用は作品情報、写真集は写真とページの説明を載せる。作品情報は切り替えても保持。本専用のプロフィール・連絡先を任意で入力。
4. A4縦／横を選択。送信用／印刷用を生成し、PDFの全ページを確認して保存。

ブラウザー保存は明示操作。30冊まで。JSONの書き出し／読み戻し（別の本として取り込み）に対応。
ページ構成・文字・参照・回転・テンプレート版を保存し、画像本体は保存しない。
ブラウザー保存は暗号化されない。OSやブラウザープロファイルを共有する人から守る仕組みではない。
端末間同期なし。ブラウザー消去で失われる。同じサイトの写真が必要で、別サイトへ画像を移送する形式ではない。
この本／全冊の保存データを消去できる。ダウンロードしたJSON・PDFは利用者が別途管理する。

## 実装と品質

- `/api/admin/pdf/photos` と `/photos/:id/image` は既存の管理セッション必須、GETだけ。
- 保存画像はDBの現在の参照から取得し、任意URLの取り込みはしない。削除・参照変更を検出して停止。
- 保存元の `photos/...` を利用。元RAW取得を保証しない。既存保存は長辺3200px以内の最適化画像。
- 送信用は長辺1600px・JPEG品質78、印刷用は3200px以内・品質95。アップスケールなし。
- SharpでEXIF等を除去しsRGBへ変換。実際にPDFへ埋め込む画素数と掲載寸法からdpiを計算。200dpi未満を注意表示。
- pdf-lib 1.17.1 / @pdf-lib/fontkit 1.1.1 をWorkerで実行。画像は直列取得、組版中の進捗、中止、タイムアウト、再試行に対応。
- 日本語は静的Noto Sans JP RegularをOFL1.1で同梱しサブセット埋め込み。字形不足・テキスト枠超過はPDFを返さずページを通知。
- ページ数とBlobの実バイト数を表示。編集後は古い生成結果を閉じて誤保存を防ぐ。保存済みPDFは書き換えない。
- 提出用の余白15mm・写真集12mm、本文10.5pt、写真全体表示、ページ番号。表紙は24pt、プロフィール見出し18pt。
- 生成器はReactや管理画面に依存せず、文書モデルとバイト列を受け取る。@react-pdf/rendererは追加しなかった。固定2テンプレートでは実寸・はみ出し検査を同じ組版処理で管理する方式を選んだ。
- 認証・課金設定、公開ナビ、写真の公開状態・sortOrder・seriesId、プロフィール、DBスキーマは変更しない。

### 2026-09-27 本を見ながら編集する画面へ更新

- 大きな一頁・ページ一覧・選択頁の編集欄を用意。写真／作品名を押すと編集欄にフォーカスする。スマホ幅では用紙→横スクロールの一覧→編集欄になる。
- `layout.ts` のpoint単位の配置をSVGとPDFで共用。Noto Sans JPの同一ファイルと字幅計算を使う。画面の写真は送信用、一覧はサムネイル。生成後のPDFで全ページ・実画像の解像度を最終確認する。
- 固定の説明枠を廃止し、改行後の行数から必要高を確保。空欄は枠を取らない。長文が写真枠の40%を超える場合は出力を止める。
- 提出用は作品情報を掲載。写真集はその情報を保持して非表示にし、ページの説明だけを掲載。用紙の向きは用途とは別に変更できる。
- ページのドラッグは移動先への挿入。前後ボタンでも同じ順にできる。40操作までの取り消し／やり直し。保存した本の切り替え・読み込みでは履歴を初期化。
- 複製時は編集中の元の本も同時にブラウザーへ保存し、未保存編集を失わない。文書・頁・項目のIDを振り直し、写真参照だけ共有。容量／冊数／保存障害時は元の編集を保持してエラーを出す。
- テンプレート版2。旧版1は提出用の版2として読み戻す。画像・文章は保持するが再出力時の配置は新しい方式になる。既に書き出したPDFには影響しない。
- 最終検証: 関連単体11件、型・lint・build成功。隔離smokeはPC・スマホ幅・WebKitの各5件、計15成功（45.5秒）。初回はフォントライブラリのブラウザー向けimportを修正。次の実行の3失敗は同じ新テストのtextarea検索で、アクセシブルなtextbox指定に修正後15件すべて成功。全体smokeの再実行はしていない（PDF専用画面・生成器内の変更）。
- 実写真12枚の見本: `portfolio-submission-v2.pdf`（縦A4・13頁・28,235,637 bytes）、`portfolio-photobook-v2.pdf`（横A4・13頁・28,232,725 bytes）。全26頁をPopplerで画像化し、pypdfで日本語と画像のEXIF除去を確認。縦横・正方形・回転の人工画像も再生成して配置を確認。

### 2026-09-27 仕上がりと編集体験の調整（版3）

- オーナーから完成度の指摘を受け、動作確認に加えて見本一冊の編集と画面の仕上げを実施。ローカル範囲を継続。
- 操作は「写真を選ぶ／ページを整える／PDFを書き出す」の3画面。保存は常時表示し、新規・複製・JSON・削除は「本の操作」にまとめた。メニューは外側クリック・操作実行・Escapeで閉じ、320px幅でも画面内に収める。
- 写真集に印刷されない作品情報を折りたたみ、写真を押すと該当する情報欄を開く。2枚組は小さな写真で対象を区別。書き出しの案内は送る／印刷する用途から選べる言葉にした。

- 頁ごとの写真サイズ（100／85／70%）と2枚の左右／上下配置を保存可能。版1・2の文書は版3に読み戻す。画面は配信画像の比率、PDFは実際に埋め込む画像寸法で同じ配置処理を使う。
- 実写真10点を選び直した『ひかりのあと』（仮題）は8ページ。水辺から人物、風景の2枚組へ進み、余白のある人物写真で終える。著者の正式なシリーズ名・発表作品とは扱わない。元の写真・文章を変更せず、編集用JSONも保持。

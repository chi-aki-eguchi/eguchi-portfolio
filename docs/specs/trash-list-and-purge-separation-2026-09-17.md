# ゴミ箱の「一覧」と「期限切れの完全削除」を分ける案（2026-09-17）

> 状態: **提案のみ。未承認・未実装。** 保持期間（30日）は変えない。新しいジョブ基盤は入れない。
> きっかけ: smoke がゴミ箱を開くだけで本番の写真を完全削除し得た件（`docs/agents/backlog.md` B-29）。
> テスト側の遮断は `scripts/smoke/isolated-server.ts` で済ませた。ここは製品側の別問題。

## 1. 現状（2026-09-17 にコードで確認）

- `GET /api/admin/photos/trash`（`packages/web/src/api/index.ts` の trash ルート、コメント「Lazy retention」）は、
  一覧を返す前に `deleted_at` が30日（`TRASH_RETENTION_DAYS`）より古い写真を探し、1枚ずつ
  `purgePhotoFromDb`（DB行・トップ写真の参照・表紙の参照を削除）→ `deleteStorageKeys`（保存先の実体を削除。
  同じ画像を使う行が残っていれば消さない）を実行する。
- 呼び出し元は管理画面の写真一覧でゴミ箱を表示したとき（`admin.tsx` の `["photos-trash"]` クエリ、
  `enabled: showTrash`）。表示中の再取得（`invalidateQueries`）と、60秒を過ぎてから開き直したときも呼ばれる。
- 「一覧を見る」操作が、取り消せない削除を伴う。閲覧・再読み込み・自動テスト・別タブでの表示が、
  そのまま本番の完全削除になる。ジョブ実行基盤が無い（単一プロセス）ため、この形になった。
- 管理ガイドは「30日後に自動パージ」と説明している（実際は「30日を過ぎて最初に開いたとき」）。

## 2. 案（最小）

1. **GET は一覧だけにする。** 削除の処理を取り除き、各写真に `expiresAt`（削除日＋30日）を、応答に
   `expiredCount` を足す。一覧は期限切れも含めて表示する（「期限切れ」の印を付ける）。
2. **期限切れの完全削除は、別の明示操作にする。**
   `POST /api/admin/photos/trash/purge-expired`（本文に `{ before: <一覧を取った時刻> }`）。
   ゴミ箱画面の「期限切れ n件を完全削除」ボタンから、件数と「取り消せない」ことを示す確認の後にだけ呼ぶ。
   `before` より後に復元・再削除された写真は対象外（既存の `purgePhotoFromDb(id, expiredBefore)` の判定を使う）。
3. **一覧取得の直後に画面から自動で POST しない。** それでは「見ただけで消える」が残る。
4. 個別の「完全削除」（`DELETE /api/admin/photos/:id/purge`）とゴミ箱の「すべて完全削除」はそのまま。

## 3. 保持と運用

- 保持期間の意味が「30日を過ぎたら自動で消える」から「**30日を過ぎたら、次に明示的に削除したときに消える**」へ
  変わる。最低30日は必ず残る点は同じ。消し忘れると保存容量がその分残る（写真1枚あたり数MB）。
- 画面の説明と `docs/admin-guide.md` を「30日を過ぎた写真は、ゴミ箱の『期限切れを完全削除』で消えます」に直す。
- 期限切れが溜まっていることは、ゴミ箱の見出しに件数で出す。自動の催促（通知・ジョブ）は作らない。
- オーナーが判断すること: ボタン方式だけにするか、「写真をゴミ箱へ移す」などの既存の書き込み操作の後に、
  同じ要求の中で期限切れの削除も行う（閲覧ではなく、明示した書き込みにだけ付ける）かを選ぶ。

## 4. 移行・戻し方

- スキーマ変更なし。DB・保存先のデータは変えない。
- コードを戻せば従来の「開いたときに削除」に戻る。戻す前後で失われるデータは無い（削除の時期がずれるだけ）。

## 5. 受け入れテスト（実装するとき）

隔離API（`packages/web/src/api/test-support/isolated-api.ts`）で:

1. 期限切れの写真があっても、`GET /api/admin/photos/trash` を2回呼んで DB の行と偽ストレージの削除要求が0件。
   応答の `expiredCount` と各 `expiresAt` が正しい。
2. `POST …/purge-expired` は期限切れだけを消し、期限内・復元済み・`before` 以後に削除された写真は残す。
   同じ画像を使う別の行があれば、保存先の実体は消さない。
3. 未ログインは 401。GET に本文があっても削除しない。

smoke では、ゴミ箱を開く検査が期限切れの人工データを置いても共有データを変えないことを確かめる
（現在の smoke は、期限切れを置かないことで安全を保っている）。

# 写真管理とサイト編集の再設計

2026-09-13。ユーザーは写真管理とサイト編集を同程度使う。過去の画面構造は変更してよく、完成まで実装と検証を続ける依頼。

## 完成条件

- 「写真」「サイト編集」が同じ重さの入口。スマホでも同じ区分を使う。
- 写真一覧は選択が既定。全選択・範囲選択・拡大・情報編集へ直接進め、選択と未保存の情報を失わない。
- Spaceで拡大、矢印で前後、Enter/Eで編集、Gで一覧へ。拡大画面に現在位置と前後の写真を出す。
- サイト編集は21節を目的別に4群へ整理。PCは左の項目一覧を常設し、⌘Kで設定名・目的から直接移動できる。
- 設定の細かな選択にネイティブselectを使い、押す箱を減らす。写真構成は小さな図と名称で比較する。
- 保存前に変更を戻す・やり直す。プリセットはまとめて戻す。⌘/Ctrl+Sで保存でき、失敗時は下書きと再試行を残す。
- プレビューは本番のページを使う。1440×900、390×844、任意の幅・高さを一つの矩形として縮小する。編集中／保存済みを比較し、表示中のページの公開リンクを開ける。
- 明暗、320〜1440px、操作ガード、日時・取り込み・掲載順、公開画面を検証する。

## プレビュー差異の原因

旧PCプレビューは横幅からだけ縮小率を出し、縦を空き欄いっぱいへ伸ばしていた。同じ1440×900のAdminでiframeの内部寸法は1280×1467、1024×900では1280×1919だった。実在するブラウザー画面の比率を比較できていなかった。

固定した内部寸法を縦横同じ倍率で縮小し、欄には余白を残す。画面幅が違えばレスポンシブ表示も変わるので、比較する寸法を表示し、直接指定できるようにする。写真・設定・テーマ・寸法を揃えた公開ページとの比較を検証する。

## データの扱い

写真原本、公開済みの写真・分類・設定は移行や削除を行わない。TIFFのIFD/XMP日時取得、日時なしを末尾へ置く処理、元ファイルからの日付復元は前回の実装を保持する。日付のないファイルに現在日時を代入しない。

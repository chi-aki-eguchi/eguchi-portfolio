## グループU: 管理画面の並び替え機能【管理画面のみ】

### U1. ライブラリの並び替えドロップダウン
管理画面 GalleryTab のツールバーに「並び替え」ドロップダウンを追加。以下のキーで並び替えできる:
- 手動（sortOrder順・既定。現状の挙動）
- アップロード日（新しい順 / 古い順）
- シリーズ
- 表示サイズ（S/M/L）
- カメラ
- カテゴリ
- タイトル（あいうえお/ABC順）
- 公開状態（公開/非公開）

注意点:
- これは**管理画面の表示順を一時的に変える表示用ソート**。実際のsortOrder（公開サイトの並び）は変えない。
- ただし「この並び順をsortOrderとして保存」ボタンも用意し、押したら現在の表示順をsortOrderに書き込めるようにする（例: アップロード日順に並べてから確定→公開サイトもその順に）。
- 並び替え中はドラッグ&ドロップ手動並べ替えを無効化（混乱防止）。手動に戻したら有効化。

### U2. 撮影日（将来対応・今回は項目だけ用意）
- 秋は「撮った日付で並べたい」が、現状データはアップロード日（createdAt）のみ。
- photos に `shotAt`（撮影日, nullable, text/ISO）カラムを追加し、インスペクタに撮影日入力欄を設ける。
- 並び替えに「撮影日」を追加（shotAtがnullの写真は末尾に）。
- 入力は任意。入れた写真だけ撮影日ソートで有効。EXIF自動取得は将来課題（今回は手入力欄のみ）。

### U3. 受け入れ基準
- [ ] 管理画面でアップロード日・シリーズ・サイズ・カメラ・カテゴリ等で表示を並び替えられる
- [ ] 「この順をsortOrderに保存」で公開サイトの並びに反映できる
- [ ] 撮影日カラムと入力欄があり、撮影日でも並び替えられる

## グループV: 設定の永続化【最優先・ストレスの元】

### V1. ページ切替で設定がリセットされる問題を解消
**症状**: ページを移動するたびにグリッドの大きさ等の設定がリセットされてうざい。
**原因の想定**: 公開サイト側で、ユーザーが触れる表示設定（列数・サイズ等）がコンポーネントのローカルstateで、ページ遷移で初期化されている。または管理画面のプレビュー状態が保持されていない。
**対応**:
- まず「どの設定がリセットされて困っているか」を実装者が特定する（管理画面プレビューの話か、公開側の閲覧者が変えられる表示の話か）。
- **管理画面側**: タブ切替・ページ移動をしても、編集中・プレビュー中の設定値が保持されるようにする（保存前の値が消えない）。
- **公開側**: もし閲覧者が変えられる表示オプション（列数スライダー等）があるなら、その選択を sessionStorage 等で保持し、ページ遷移でリセットしないようにする。※ localStorageはartifact制約と無関係（本番サイトなので使用可）。
- いずれにせよ「設定したのに移動したら戻ってる」をゼロにするのが目標。

### V2. 受け入れ基準
- [ ] ページを移動・タブ切替しても、設定した表示状態（グリッドの大きさ・列数等）が維持される
- [ ] 「設定したのにリセットされる」挙動が解消される

## グループW: レスポンシブ列数（最大列数＋幅で自動）

### W1. 最大列数を設定し、画面幅で自動調整
**症状/要望**: 写真の列数の最大を設定できるようにし、スマホ・iPad・PCで幅によって自動で変わるようにしたい。
**対応**:
- 設定は「最大列数」（PCで最大何列出すか）を指定する形にする。
- 実際の列数は画面幅で自動的に決まる（CSS の auto-fill/minmax か、ブレークポイントで段階的に）。
  - 例: 最大列数6なら、広いPC=6列 / 狭いPC=4列 / iPad=3列 / スマホ=2列、のように幅で自動減少。
- 現状の galleryColumns（固定列数）/ galleryColumnsMobile を、この「最大列数＋自動レスポンシブ」方式に統合・置換する。
- タイルの最小幅を決めておき、それ未満にならないよう自動で列を減らす（写真が小さくなりすぎない）。

### W2. 受け入れ基準
- [ ] 管理画面で「最大列数」を設定できる
- [ ] PC/iPad/スマホで画面幅に応じて列数が自動で変わる
- [ ] どの幅でもタイルが極端に小さく/大きくならない

## グループX: トップとギャラリーで表示設定を分離

### X1. トップ下部の写真とギャラリーの写真を別設定に
**要望**: トップページ下に出る写真と、ギャラリーの写真の「大きさ」「列数」を別々に設定したい。
**対応**:
- 現状ページ別レイアウト（topWorksLayout / galleryLayout）はあるが、**列数・サイズ・余白等の細かい設定もトップとギャラリーで独立**させる。
- 新規settingsキー（例）:
  - トップ用: topWorksColumns（最大列数）/ topWorksSizeScale 等
  - ギャラリー用: galleryColumns（最大列数, W1と統合）/ gallerySizeScale 等
- 管理画面の「ギャラリー配置」セクションを、「トップ（Works）」と「ギャラリー」のサブセクションに分け、それぞれで独立に調整できるUIにする。
- ライブプレビューはプレビュー対象ページに応じて反映。

### X2. 受け入れ基準
- [ ] トップ下部の写真とギャラリーの写真で、列数・大きさを別々に設定できる
- [ ] 片方を変えてももう片方に影響しない

## グループY: スライダーの調整幅を広げる

### Y1. 全スライダーの可動範囲・刻みを見直す
**症状/要望**: 大きさ等を変えるスライダー（文字も写真も）の幅をもっと広くしたい。スライダーがあるもの全般。
**対応**:
- 管理画面の各スライダー（タイポグラフィのサイズ/字間/行間、ギャラリーの列数/余白/サイズ変動、ヒーロー高さ、globalFontScale 等）について、**min/maxの範囲を広げる**。
  - 例: フォントスケールが 0.8〜1.2 なら 0.6〜1.6 に。ギャラリー余白が狭ければ上限を上げる。写真サイズ変動も幅を広げる。
- 同時に刻み（step）を細かくし、より自由に調整できるようにする。
- ただし極端な値でレイアウトが完全に破綻しないよう、各スライダーの上下限は「攻めつつ破綻しない」範囲に設定する。
- 現在値が数値でも見えるようにし（スライダー横に数値表示）、微調整しやすくする。

### Y2. 受け入れ基準
- [ ] 主要スライダーの可動範囲が現状より広い
- [ ] 刻みが細かく、思い通りの値にしやすい
- [ ] 現在値が数値で見える
- [ ] 端の値でもレイアウトが大崩れしない

## グループZ: Lightbox/ヒーローの操作性

### Z1. 前後の写真へ移動
**要望**: ヒーローの写真も、ギャラリーで拡大した写真（Lightbox）も、クリックで次/前の写真に行けるようにしたい。
**対応**:
- **Lightbox**: 既に前後ナビがある場合は、左右クリック領域・矢印ボタン・キーボード←→・スワイプを再確認し、すべて効くようにする。画像の左右端をクリックで前後に移動できるようにする（中央クリックは拡大/閉じる等と競合しないよう設計）。
- **ヒーロー**: カルーセルモードなら自動送りに加え、手動で前後に切り替えられる矢印/スワイプを付ける。クリックで次の写真へ進めるようにする。

### Z2. Lightboxを閉じやすく
**要望**: ギャラリーで写真をクリックした後、バツを押しやすく・元の画面に戻りやすくする。
**対応**:
- 閉じる（×）ボタンを**大きく・押しやすい位置**（右上で十分な余白とタップ領域）にする。
- 背景（画像外）をクリック/タップでも閉じられるようにする（既存ならタップ領域を確認）。
- Escキー、スマホの戻る操作、下スワイプでも閉じられるようにする。
- 閉じたときに**元のスクロール位置に戻る**ようにする（一覧の見ていた場所に戻れる）。

### Z3. 受け入れ基準
- [ ] Lightboxで前後の写真に、矢印/クリック/キーボード/スワイプで移動できる
- [ ] ヒーローも手動で前後に切り替えられる
- [ ] Lightboxの×が大きく押しやすく、背景クリック・Esc・スワイプでも閉じられる
- [ ] 閉じたとき元のスクロール位置に戻る

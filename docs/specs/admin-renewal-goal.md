# 管理画面刷新のゴール（2026-07-25 オーナー本人の言葉で確定）

> **このプロジェクトの現在のゴールはこれ。** 個別タスクはすべてこのゴールに従属する。
> それまでゴールがリポジトリのどこにも書かれておらず、2026-07-25 のセッションで
> 担当AIが `growth-monetization-plan.md`（事業計画）をゴールと誤認した。
> 同じ取り違えを防ぐため、`CLAUDE.md` の冒頭からもここへ誘導している。

## ゴール

**管理画面（`/admin`）の刷新。** オーナーの言葉をそのまま置く。

> デザインと使用感と完成度と高級感とAI感の削減。あと可愛さ。

Library だけの話ではない。`/admin` の全タブ（はじめに / Library / Hero / Series /
Categories / Profile / Pricing / Portfolio Kit / Settings）が対象。
`docs/specs/library-redesign-spec.md` はこのゴールの Library 部分にあたる下位仕様。

## なぜ管理画面なのか

管理画面はオーナーが毎日使う道具であり、同時に **Portfolio Kit として販売している商品の
中身そのもの**（購入者も同じ画面を使う）。公開ページは「作品」だが、管理画面は「商品」。
だから見た目と使い心地が、そのまま作業効率であり商品価値になる。

## 6つの軸

### 1. デザイン

見た目そのもの。配色・書体・余白・罫線・階層。既存の `docs/specs/design-spec.md`
（雑誌的佇まい・余白主導）の考え方は公開ページ側の正本であり、管理画面にも通じる。

### 2. 使用感

触ったときの手応え。押した場所で反応が返る、迷わない、操作と対象が競合しない。
`library-redesign-spec.md` §2-3 の「反応の作り方」がこの軸の詳細。

### 3. 完成度

「作りかけに見えない」こと。**この軸は最も裏切られやすい。** 具体的には:

- ブラウザによって崩れる（例: Safari でスワイプすると写真がチラつく — 2026-07-25 オーナー報告）
- 画面幅によって崩れる（例: 1024px で写真が5列→2列に減っていた — Q-11 で解消）
- 半端な状態が見える（読み込み中の白抜け、レイアウトの飛び、二重の枠線）
- 押せそうで押せない、押せなさそうで押せる
- 文言の不統一、片方の言語だけ古い

### 4. 高級感

安く見えないこと。派手さではなく、静かさと精度で出す。余白が効いている、
線が細い、動きが小さく速い、色数が少ない。

### 5. AI感の削減

**「AIが作った画面」に見える特徴を消す。** これは定義がないと実行できないので、
設計側（Claude Code）で下記のとおり定義する。**この定義はオーナー未確認。**
違うと言われたら差し替える。

避けるもの:

- 汎用UIキットそのままの見た目（全部が同じ `rounded-lg` + 同じ影 + 同じ余白）
- 紫〜青のグラデーション、ネオン、光る枠
- 絵文字をアイコン代わりに使う
- どの要素にも説明文が付いている（親切の押し売り。読む量が増えて逆に迷う）
- 意味のない完全な左右対称、完全な等間隔
- 「✨新機能」「🚀はじめよう」のような煽り文言
- 空状態が毎回「中央寄せの大きなイラスト＋2行の説明＋ボタン」の型

代わりに置くもの: **この道具固有の判断が見えること。** 写真家の作業に合わせて
密度・並び・語彙が選ばれていて、汎用テンプレートでは出てこない形になっていること。

### 6. 可愛さ

**高級感と矛盾しない置き方をする。** 装飾を足すのではなく、小さな瞬間に入れる。

- 動きの気持ちよさ（数値の入れ替わり、チェックの付き方、シートの出方）
- 文言の温度（事務的すぎない一言。ただし煽らない）
- 細部の遊び（空状態、完了時、何もしていないときの佇まい）

装飾を増やす方向（丸み・パステル・キャラクター）は高級感を壊すので取らない。
**この解釈もオーナー未確認。**

## この6軸の使い方

タスクを起こすとき・レビューするときに、「どの軸のためか」を1つ以上書く。
軸に紐づかない変更は、このゴールの下では優先度が低い。

## 到達点（2026-07-25 設計側で決定）

6軸は「方向」であって、そのままでは終わりが判定できない。**このゴールの到達点を次のとおり決める。**
以下が全部満たされたら「刷新できた」と言う。

1. **タブを切り替えても内容が横に飛ばない。** 全タブが同じ左端・同じ見出し位置・同じ縦リズムを使う
2. **1画面の説明文は最大1つ。** 見出しで分かることは書かない。同じ内容を2回書かない
3. **UIの言葉は日本語で統一。** 英語はタブ名などの固有名詞（Library / Hero / Series）だけ
4. **同じ操作は同じ見た目。** 追加ボタン・行カード・公開トグルが画面ごとに違わない
5. **1440pxで本文が画面の3割しか使っていない画面が無い**
6. **読み込み中に「意味のない灰色の箱」を見せない**
7. **意味のない仮の表示をしない**（説明が空のときに "…" だけを出す等）

### 現状はこの7つのうち0個を満たしている（実測）

全9タブを 1440px / 390px で撮って確認した（`scratch/survey/`）。

**(1) 本文の左端がタブごとに違う。** 1440px 実測:

| タブ | 本文の左端 | 本文の幅 |
| --- | --- | --- |
| Library | 265px | 全幅 |
| Settings | 280px | 約695px |
| はじめに | 318px | 約1050px |
| Hero | 430px | 約830px |
| Profile / Series / Pricing | 620px | 約448px |

**タブを切り替えると内容が最大355px横に飛ぶ。** 共通のページ枠が存在せず、
見出し・説明・カラム幅・余白がタブごとに作り直されている。**これが「AIが作った画面」に
見える最大の理由。** AIが作った画面は1枚ずつ見ると成立していて、並べると揃っていない。

**(2) 説明の重複。** Hero は「Hero」の下に「トップページのカルーセルに表示する写真を選びます。」、
その下の「Hero Slides」に「トップページのカルーセルに表示する写真。ドラッグで並べ替え…」と
ほぼ同じ文が2回出る。

**(3) 言葉が混ざっている。** `NAME (JP)` `BIO` `TITLE` `SLUG` `NEW SERIES`
`PROFILE PHOTO (ABOUT PAGE)` のような**英語の全大文字ラベル**が日本語画面に並ぶ。
Profile には `3:4 portrait recommended` と英語の但し書きもある。

**(4) 同じ操作が2種類の見た目。** 「追加」が Series では `+ Add`（英語・灰色・押せなさそう）、
Pricing では `+ プランを追加`（日本語・黒の塗り）。

**(5) 1440px で Series / Pricing / Profile は本文が448px。画面の3割。** Pricing は
行が2つで縦にも約500px空いている。「はじめに」は完了後**画面の約9割が空白**で、
ページ見出しすら無い（他タブには "Library" "Hero" があるのに）。

**(6)** 初回読み込み時、Hero スライドとプロフィール写真が**1秒ほど意味のない灰色の四角**になる。
**不具合ではない**（2回目以降は500ms以内に出る）。ただし待たされている説明が何も無い。

**(7)** Series の説明が空のとき、`…` だけが表示される（`admin-tabs.tsx:1658`）。

> **訂正 (2026-07-25)**: 当初ここに「Pricing の `新しいプラン` という仮の行」も挙げていたが、
> **これはオーナーのデータ**（下書き状態の料金プラン。公開APIは下書きを返さないため
> 公開側では見えない）。コードの置き忘れではないので触らない。

### Settings / Series / Pricing が同じ「灰色の丸角＋右向き矢印」の行

用途が違う3画面が同じ汎用リスト部品で作られている。これは軸5「AI感」の中心症状。

## 進め方（この順で行う。決定済み）

**P1. 共通のページ枠を1つ作り、全タブを載せ替える** ← 最優先

軸1〜5に同時に効き、他の作業の土台になる。決めた寸法:

- サイドバー248pxは変えない
- 本文の左端は**全タブ共通で40px**。中央寄せにしない（左端が揃うことが「飛ばない」条件）
- 本文の最大幅は用途で2種類だけ: **一覧・設定=880px / 入力フォーム=560px**
- 見出しは全タブで必ず出す（「はじめに」にも付ける）
- 説明は見出しの直下に1つだけ、最大2行
- セクション間32px、セクション内の要素間12px
- Library は写真グリッドなので幅は全幅のまま。ただし**左端40pxと見出し位置は共通に揃える**

**P2. 言葉と操作の統一** — 「はじめに」へのページ見出し追加（これで
`admin-page-frame.spec.ts` の fixme を解除できる）、Hero の重複説明の解消、
全大文字英語ラベルの日本語化、追加ボタンの統一、空説明の "…" をやめる。

**P3. 行部品の作り分け** — Settings / Series / Pricing が同じ汎用リストを使うのをやめ、
それぞれの用途に合った形にする。ここが「AI感の削減」の本体。

**P4. 可愛さと動き** — 土台が揃ってから。数値の入れ替わり、チェックの付き方、
空状態の佇まい、文言の温度。**先にやると「散らかった画面に飾りを足す」ことになるので後回し。**

**並行して進める完成度の穴**: Q-12（選択モード中も検索を残す）、
読み込み中のプレースホルダ（軸6）。

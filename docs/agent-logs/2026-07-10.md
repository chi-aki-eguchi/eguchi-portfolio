## タスク: 保存先未設定エラーの可視化 (STORAGE_NOT_CONFIGURED)

- **方針**: S3系4変数の不足判定を純関数モジュール `src/api/storage-config.ts`
  に切り出し、(1) `/admin/upload` の入口で sharp/DB 処理前に 503 で返す、
  (2) `uploadToStorage` 経由の他ルート(hero/profile/fonts)は `StorageConfigError`
  を `onError` で同じ503 JSONに変換、(3) 読み取り専用 `GET /api/admin/setup-health`
  を追加、(4) 管理画面は専用日本語バナー + 「はじめに」上部の接続状態表示。
- **迷った点**:
  - HTTP status: 指示の候補どおり 503 を採用。呼び出し側のバグ(4xx)でも
    未知の障害(500)でもなく「サーバ側の設定が未完了で一時的に使えない」
    状態を最もよく表すため。既存設計(400/401/413/415/500)とも衝突しない。
  - 専用エラーの伝搬: /admin/upload だけ入口チェックにするか全ルートに
    入口チェックを足すかで迷い、影響範囲の小さい「入口チェックは
    /admin/upload のみ + onError での変換で全ルートを網羅」を選んだ。
- **秘密情報**: 不足変数は名前のみ扱い、値はエラー・レスポンス・ログ・
  テストのどこにも出していない(テストはダミー値で「値が含まれない」ことを
  検証)。
- **要相談**: なし。
- **`bun run check`**: 成功(291 tests / tsc -b / oxlint / build)。
- **`bun run smoke`**: 22 passed / 19 skipped / 1 failed。失敗は既知の
  `admin-trash-signal.spec.ts`(共有DBのゴミ箱が32件で非空のため)。
  クリーンな main でも3回連続で同じ失敗を再現し、今回の変更とは無関係と

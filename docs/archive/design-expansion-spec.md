# デザイン拡張 仕様書（ヒーロー演出・ナビ・余白・質感・アクセントカラー）

> Claude Code向け。既存仕様書群の続編。§0既存パターン厳守。
> 目的: 「今ある設定の枠を超えて、デザインの幅を持てる設計」にする。すべて管理画面から調整可能・ライブプレビュー対応。

---

## 0. 前提（厳守）
- 新規settingsキーは3箇所同期（admin previewPayload＋deps / provider DB適用 / handlePreviewMessage。CSS変数で表現できるものは applyVar、できないものは JS_PREVIEW_KEYS）
- 全書き込み res.ok / assertOk チェック
- 既定値は「現状の見た目と同じ」にする（デプロイしただけでは何も変わらず、秋が設定して初めて変わる）
- 各グループ完了ごとに tsc -b / テスト / build / スモーク → デプロイZIP更新
- design-spec の「静かなUI・写真主役」の原則は維持。新演出はすべて控えめ・上品の範囲で設計

## グループAA: ヒーロー演出【全部入れる】

### AA1. フルスクリーンモード
- heroDisplayMode: "normal"（現状の高さ設定に従う） | "fullscreen"（100svh、写真が画面を覆う）
- fullscreen時はファーストビューが写真だけになり、スクロールで作品セクションへ
- 既存の heroHeight 設定は normal 時のみ有効（fullscreen時は無視されることをUIヒントに明記）

### AA2. 名前（タイトル）の表示位置
- heroTitlePosition: "center"（既定・現状） | "bottom-left" | "bottom-right" | "top-left" | "top-right"
- 位置に応じて適切なパディング・テキスト整列。モバイルでも破綻しない位置調整
- 既存のヒーロー名サイズスライダー（16〜160px）とオーバーレイ設定はそのまま併用可能

### AA3. スクロール演出
- heroScrollEffect: "none"（既定・現状） | "fade"（スクロールで写真がゆっくり暗転/フェード） | "sink"（写真がゆっくり沈み、作品が上に重なって現れる=パララックス風） | "parallax"（写真がスクロール速度の0.5倍で動く）
- 実装は transform/opacity のみ使用（layoutを動かさない）。requestAnimationFrame か CSS scroll-driven animations で60fps維持
- prefers-reduced-motion 時は自動で none 扱い
- スマホでも動作するが、重い場合はスマホのみ簡略化してよい（その場合は報告）

### AA4. 受け入れ基準
- [ ] フルスクリーンON/OFF、名前位置5種、スクロール演出4種が管理画面から選べてプレビュー即反映
- [ ] 既定値では現状と完全に同じ見た目
- [ ] reduced-motion・スマホで破綻しない

## グループBB: ナビゲーション【位置＋ホバー演出】

### BB1. ナビの位置
- navPosition: "top"（既定・現状） | "left"（左縦置き） | "bottom"（下固定）
- left: 画面左端に縦書きまたは縦並びのナビ。ギャラリーサイト的な佇まい。コンテンツ領域は右にシフト
- bottom: 画面下部に固定。モバイルのタブバー的だが上品に
- モバイルでは left/bottom 選択時も自動でハンバーガー（現状のモバイルメニュー）にフォールバック（狭い画面で縦ナビは苦しいため）

### BB2. ホバー演出
- navHoverEffect: "fade"（既定・現状の色変化） | "underline"（下線が左からすっと伸びる） | "dot"（リンク横に小さな点がふわっと出る） | "blur"（文字がほんの少しにじむ→くっきり）
- すべて0.3〜0.5sの控えめなトランジション。design-specのカーブ（expo系）を使用
- aria-current（現在地）の見た目は維持

### BB3. 受け入れ基準
- [ ] ナビ位置3種・ホバー演出4種が選べてプレビュー即反映
- [ ] モバイルで崩れない（left/bottom時はハンバーガーにフォールバック）
- [ ] キーボードフォーカスでもホバー同等の視覚フィードバック

## グループCC: セクションごとの余白量

### CC1. 個別余白設定
以下をそれぞれスライダーで調整可能に（CSS変数化）:
- spacingHeroBottom: ヒーロー直下〜次セクションの余白
- spacingSectionGap: セクション間の基本余白（作品/CTA/フッター間）
- spacingPageTop: 各ページ（ギャラリー・シリーズ・About等）冒頭の「ため」の余白
- spacingFooterTop: フッター上の余白
- 各スライダーは倍率（0.5〜2.5、step 0.05）または px。現状値が1.0（既定）
- 管理画面「ギャラリー配置」とは別に「余白・スペーシング」セクションを新設（折りたたみ）

### CC2. 受け入れ基準
- [ ] 4箇所の余白が個別に調整でき、プレビュー即反映
- [ ] 既定値で現状と同じ
- [ ] モバイルでは比例縮小（極端な余白でも破綻しない）

## グループDD: 紙っぽい質感（グレイン）

### DD1. 背景テクスチャ
- bgTexture: "none"（既定） | "grain-fine"（細かい粒子・フィルムグレイン風） | "grain-coarse"(粗め・ざらっとした紙) | "paper"（和紙/上質紙っぽい繊維感）
- bgTextureOpacity: 0〜0.15（step 0.01、既定 0.05）— ごく薄く乗せる前提
- 実装: SVG feTurbulence で生成したノイズを data URI 化し、body::before に fixed で重ねる（画像ファイル不要・軽量）。または極小PNGをbase64で。mix-blend-mode: multiply 等で背景色と自然に馴染ませる
- 写真の上には乗せない（背景のみ）。Lightbox表示時は無効（写真鑑賞の邪魔をしない）
- パフォーマンス: 1枚の固定オーバーレイのみ。スクロールで再描画されないこと

### DD2. 受け入れ基準
- [ ] 質感3種＋なし、濃度スライダーが選べてプレビュー即反映
- [ ] 写真・Lightboxには乗らない
- [ ] スクロール時のパフォーマンス劣化なし（60fps維持）

---

## グループEE: アクセントカラー

### EE1. 差し色設定
- accentColor: カラーピッカー（既定: 現状のリンク/ホバー色）
- 適用箇所: リンクホバー、ナビのアクティブ/ホバー、ボタン（View all・CTA）のホバー、フィルタ選択中、フォームのフォーカスリング
- 文字本体の色（テキストカラー）は変えない。あくまで「触れたときに見える差し色」
- アクセシビリティ: 選んだ色のコントラストが低すぎる場合も動作はするが、管理画面に「薄い色は見えにくい場合があります」のヒントを表示

### EE2. 受け入れ基準
- [ ] アクセントカラーが一括で変わり、プレビュー即反映
- [ ] 既定値で現状と同じ
- [ ] 適用箇所が統一されている（一部だけ古い色が残らない）

## 実装順（推奨）

| 順 | グループ | 理由 |
|---|---|---|
| 1 | AA ヒーロー | サイトの顔・効果が一番大きい |

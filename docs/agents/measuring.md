# 測り方 — 存在しない不具合を作らないために

> **backlog の項目に着手する前に、必ずここを読む。**
> 過去に「存在しない不具合」を記録した実例が複数ある。原因は毎回、
> 測り方か記録の retire 漏れだった。

## なぜこの文書があるか

記録された不具合が実在しない、という事故が繰り返し起きている。

| 日付 | 何が起きたか | 原因 |
|---|---|---|
| 2026-07-25 | 「灰色の空箱」「新しいプラン」「汎用リスト」の**偽の不具合3件**を書きかけた | 画面写真を**読み込み完了前**に撮った |
| 2026-07-26 | 「並べ替えボタンが13x13px」と記録。**実機では40x40px** | デスクトップの画面幅を狭めて測った。`@media (pointer: coarse)` が適用されない環境だった |
| 2026-08-04 | backlog の「要再確認」6件のうち**3件が実態と違っていた** | 直したのに元の記録を消していなかった / 記録した数値が古くなっていた |

いずれも、そのまま着手していれば**実在しない問題を直す作業**になっていた。

## 着手前に必ずやること

1. **記録された行番号・数値・症状を信じない。実物を測り直す。**
   記録は書かれた時点の写真であり、コードは動く。
2. **測り直した結果が記録と違ったら、記録のほうを直す。**
   「たぶん記録が正しいのだろう」で進めない。
3. **もう直っていたら、backlog からその項目を消す。**
   消した事実は commit メッセージに残る。

## 測り方の落とし穴

### タッチ端末の挙動は、タッチ端末として測る

`devices["Desktop Chrome"]` の viewport を狭めただけでは `pointer: coarse` にならず、
`@media (pointer: coarse)` の中のルール（`.admin-tap-sm` の 40px 保証など）が適用されない。

**タップ領域・ホバー挙動・スワイプを測るときは `devices["iPhone 13"]` のような
実端末プロファイルを使う。**

### 画面を撮るときは読み込み完了を待つ

**必ず `networkidle` + 数秒待つ。** 待たずに撮ると、まだ描画されていない領域を
「空箱」「汎用リスト」として記録してしまう。

### CSS は computed style で測る

宣言を読むだけでは、どのルールが勝っているか分からない。`getComputedStyle` で
実効値を取る。特に管理画面は特異度の競合が多い（`docs/agents/backlog.md` の B-1）。

### `:not()` を足すと特異度が上がる。`:where()` は上がらない

**2026-08-04 に実際に踏んだ。** 一括リセットから `.ax-btn` を除外しようとして
`:not([class*="ax-btn"])` を足したところ、リセット自身の特異度が (0,7,1) → (0,8,1) へ
上がった。その結果、**リセットに勝つよう調整されていた個別ルール (0,7,1) が負け**、
削除ボタンが hover しても赤くならなくなった（smoke が検出）。

「除外を足す」つもりが「リセットを強くする」になっていた。
**特異度を変えずに条件だけ足したいときは `:where()` を使う。**`:where()` の中身は
特異度に加算されない。

```css
/* 特異度が上がる（他のルールを負けさせる） */
button:not(.absolute):not([class*="ax-btn"])
/* 特異度は変わらない */
button:not(.absolute):where(:not([class*="ax-btn"]))
```

この種の事故は宣言を読んでも見つからない。**必ず smoke を通すこと。**

### dev サーバの HTML は本番と違う（meta / OGP は必ず本番経路で測る）

`bun run dev` の Vite プラグインは **`/api` しか処理しない**。HTML は Vite が
`index.html` をそのまま返すので、`server.ts` の `injectOgp` を通らない。
つまりローカルでは title / description / OGP が**常にテンプレートの初期値のまま**に
見える。これを「meta が反映されないバグ」と読むと偽の課題になる（2026-08-05 に
実際に踏んだ）。

正しい測り方は `injectOgp` を直接呼ぶこと。

```sh
bun run -e 'import {injectOgp} from "./src/api/ogp"; /* settings と index.html を渡して出力を見る */'
```

### ブラウザの computed style は「書いた値」とは限らない

`line-clamp-2` を当てた要素の `display` を Chrome は **`flow-root`** と報告する
（`-webkit-box` と書いてあっても）。「Tailwind のクラスが効いていない」と読むと
偽の課題になる。**効いているかは見た目・寸法で確かめる**（`scrollHeight` と実高さ、
スクリーンショット）。computed style の値だけで結論を出さない。

同様に `Range.getClientRects()` は clamp / ellipsis の**前**の座標を返すので、
「文字が枠から出ている」検出器はそのままだと誤検知する。`-webkit-line-clamp` と
`text-overflow: ellipsis` の要素は除外してから測る。

### 設定が本当に画面へ届くかは、DB を書かずに総当たりできる

`page.route()` で `/api/settings` の応答を差し替えれば、キーを1つずつ変えて
描画差分を見られる。**本番DBに一切書かずに**「このスライダーは効くのか」を
全キー分たしかめられる（2026-08-05 に155キーで実施）。

注意点が2つある。

- **トップとギャラリーは読み込みごとに絵が変わる**（ランダム選択・遅延読み込み）。
  同じ設定で2回撮って「勝手に動いた部分」をマスクしてから比べないと、
  全キーが「効いている」に見える。
- 逆にマスクが効きすぎると、写真グリッドを動かすキーが全部「効かない」に見える。
  レイアウト系は**列数・タイル幅・文書高さ**など安定した幾何で測り直す。

### 本番サーバの挙動は、使い捨ての SQLite を作れば本番DB無しで測れる

`bun run dev` も `bun run smoke` も **vite dev サーバ**を使う。`src/server.ts`
（応答ヘッダ・OGP注入・静的配信・圧縮）は**どちらも通らない**。
smoke が緑でも、server.ts の変更は何も証明されていない。

かといって server.ts を素で起動すると本番 Turso につながる。**その必要は無い。**
`DATABASE_URL` に `file:` を渡せば libSQL はローカルのファイルを使う。

```bash
# 1) 使い捨てDBへスキーマを流す（packages/web/drizzle/*.sql を順に execute）
# 2) 起動する
cd packages/web && env -u DATABASE_AUTH_TOKEN \
  DATABASE_URL="file:/tmp/probe.db" PORT=4399 SITE_URL=http://localhost:4399 \
  ADMIN_PASSWORD=<使い捨ての値> bun src/server.ts
```

**注意:**

- 起動時の `ensureTursoColumns()` は**全部の欠落列を埋めてはくれない**。
  `no such column: camera` のように落ちるので、足りない列は
  `alter table ... add column` で自分で足す。
- これで**管理画面のログインまで通せる**。`POST /api/admin/login` で Cookie を
  取り、`GET /api/admin/me` が `{"authenticated":true}` を返すところまで、
  本番DBに一切触れずに確認できる（2026-08-23 に実施）。
- 終わったらプロセスを落とし、DBファイルを消す。

### 圧縮を測るときは `--compressed` も `-sI` も使わない

2026-08-23 に**この2つで両方とも誤読した**。

- `curl --compressed` の `size_download` は**回線に乗ったバイト数**であって、
  展開後の大きさではない。圧縮されていても素の本文でも同じ欄に出るので、
  数字だけ見ても**圧縮の有無が分からない**。
- `curl -sI`（HEAD）は本体を返さないので、プロキシもサーバも圧縮しない。
  **HEAD に `content-encoding` が無いことは、GET が非圧縮である証拠にならない。**

正しくは GET を2回投げて突き合わせる。

```bash
curl -s -o /dev/null -w '%{size_download}\n' -H 'Accept-Encoding: identity' "$URL"
curl -s -o /dev/null -D - -H 'Accept-Encoding: br, gzip' "$URL" | grep -i content-encoding
```

**`Accept-Encoding: deflate` だけを送る切り分けは効かない。** gzip しか喋らない
プロキシも素の本文を返すので、「プロキシは圧縮していない」の証明にならない。
プロキシがやっているかを見たいなら、**origin が確実に素通しする応答**（この
リポジトリなら 404 の SPA ページ。`compressResponse` が status≠200 を触らない）
へ `Accept-Encoding: gzip` を投げて、それでも `content-encoding` が付くかを見る。

### 定番の測り方

`scratch/` に使い捨てスクリプトを書く（gitignore 済み）。

- 全タブ・全幅のスクリーンショット（**networkidle + 数秒待つ**）
- 文字サイズの分布 / 塗られた要素の割合 / 見出しの左端の一致
- **コントラスト比**（`getComputedStyle` で実効背景を合成して計算）
- 主要ページの読み込み時間・画像の実寸

## 課題を立ててよい条件

測った差分が、次のどれかに当たるときだけ課題にする。**正本に無いことを勝手に課題にしない。**

1. **壊れている**（テストが赤 / 実測で読めない・押せない・見えない）
2. **到達点の未達** — 管理画面は `docs/specs/admin-renewal-goal.md`
3. **公開サイトが `docs/specs/design-spec.md` と違う**
4. 上のどれにも当たらない磨き込み（優先度は最低）

## 回帰テストは「修正を外すと落ちる」ことまで確かめる

**2026-08-04 に実際に書きかけた。** デモのタブ保存キーを直し、回帰テストを足したが、
**修正を外しても通るテスト**だった。`usePersistentState` は mount 時にも書くため、
読んだ値と書いた値が同じになり、検査していた「本番キーが変わっていないこと」に
差が出なかった。

観測できる差（デモが専用キーを使うこと）を検査する形に直したところ、
修正あり=pass / 修正なし=fail となり、初めて回帰テストとして機能した。

**手順:** テストを書いたら、**修正を一時的に戻して落ちることを確認する。**
落ちなければ、そのテストは何も守っていない。

これは1と2より危険である。記録の誤りや実装の誤りは誰かが気づくが、
**通っているテストは誰も疑わない。**

## 直したあと

**backlog から項目を消す。** 記録を残したまま直すと、次に読む者が
「まだある問題」として扱い、実在しないものを直そうとする。
2026-08-04 の B-6 がこの形で残っていた。

## 「他人のデータ」で測る（2026-08-11）

Portfolio Kit は他人が使う。作者のデータ（きれいな日本語の題名、短い名前）では
一度も出ない崩れが、買った人のデータでは普通に出る。**320px の画面で
「空白の無い50文字」を入れて測ると、1日で6箇所見つかった。**

| 場所 | 320pxでの実測 |
|---|---:|
| About（名前・本文） | **1650px** |
| シリーズ詳細 | **1654px** |
| シリーズ一覧 | 706px |
| Contact の料金プラン | 549px |
| ギャラリー large-format | 543px |
| ギャラリー scroll | 382px |
| ビューアの撮影情報 | 枠が433px（ページは溢れないが値が読めない） |

**URL で試すと見逃す。** `https://…/a-very-long-path` はスラッシュとハイフンで
折り返せるので、多くの場所を素通りする。**折り返せない連続英字**（`A` を50個）で
試すこと。写真の題名はファイル名由来が多く、これは現実に起きる。

**`break-words` だけでは足りないことが多い。** 崩れ方は3種類あった。

- **grid / flex の子**は既定で `min-width:auto` なので、中身が折り返せないと
  列そのものが広がる → `min-w-0`（または `shrink-0` を隣へ）
- **中央寄せ flex の子**は幅が内容で決まるので、折り返す先が無い → `w-full`
- **table** は内容で広がる → `width:100%` + `table-layout:fixed`

**分岐が出る条件を満たしてから測る。** シリーズ詳細を1件だけで試したとき、
「次のシリーズ」リンクが描かれず、直ったように見えた。2件にすると再現した。
出ていないものは壊れていないように見える。

### 横あふれは2種類ある。片方は rect で見えない

2026-08-11、**同じ崩れを何度も直したつもりで直っていなかった。** 原因は道具。

- **箱ごと外へ出る** → `getBoundingClientRect().right > innerWidth` で見つかる
- **箱は container の幅のまま、中の文字だけ外へ出る** → **rect では見つからない。**
  ブロック要素の幅は container のままなので、どの要素も「はみ出していない」と出る。
  それでも `document.documentElement.scrollWidth` は伸びる

後者は `e.scrollWidth > e.clientWidth`（自分で `overflow` を切っていない葉だけ）で
測る。この道具に替えた瞬間、5ページぶんが一度に出て、1回で直し切れた。

**症状の切り分け:** 「`scrollWidth` は大きいのに、はみ出している要素が1つも
見つからない」なら、ほぼ確実に後者。要素を探し直すのではなく、道具を替える。

なお `bun run smoke` の横あふれ検査は `document.scrollWidth` を見ているので
**道具としては正しい**。見落としていたのは、オーナーの実データが行儀よく、
折り返せない長い語が一度も入っていなかったから。

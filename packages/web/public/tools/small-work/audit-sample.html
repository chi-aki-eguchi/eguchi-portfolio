写真セレクト便
入口と購入前の点検

すでに説明できていることを残し、体験を選ぶ入口と購入前の相談を整える。

この見本は制作元自身のサイトを点検したものです。顧客案件・販売実績ではありません。公開ページの画面とHTMLを確認し、改善案は検証前の提案として記しています。

今回確認したこと

/tools/photo-select-bin.htmlHTTP 200 / 写真セレクト便｜依頼主の写真選定・コメントを受け取るPCツール
/tools/photo-select-bin/walkthrough.htmlHTTP 200 / 選ぶ・受け取るを体験｜写真セレクト便

PC 1440px・スマートフォン相当390pxの公開画面を確認。390pxではページ幅を超える横はみ出しはありませんでした。実機操作・問い合わせ送信・有料決済は行っていません。

HTMLでは紹介ページに説明文・正規URL・画面幅設定を確認。購入先はBOOTH。写真の見本は制作元の公開作品と明記されています。

解析管理画面の数値や、検索順位・顧客の行動はこの点検に含めていません。画面が表示されることと、申込・売上が増えることは別に確認します。

根拠になる画面

先に直す3つのこと

優先 1

2つの体験の違いを、入口のそばで説明する

確認した事実：冒頭に「選ぶ → 受け取る、を体験する」と「自分の写真で試す」が並ぶ。補足は「写真の用意・登録不要 / 自分の写真は12枚まで無料」。

理由：写真を持たずに見る見本と、自分の写真で往復する体験を選ぶ前に区別できると、目的に合う入口を選びやすい。

具体案：「見本の写真で流れを見る」「自分の写真12枚で、相手との往復を試す」と各ボタンの直下に添える。

確認する数値：入口ごとのクリックと、体験を終えた人の反応。現状の文言が原因で離脱したと断定はできない。

優先 2

「操作見本」と「受取体験」を同じ言葉で整理する

確認した事実：上部ナビは「操作見本」。本文には「この画面を操作する」「受け取るところまで見る」と、異なる体験へのリンクがある。

理由：画面を見るだけなのか、受け取る結果まで確認できるのかが、リンクを押す前に分かるとよい。

具体案：ナビと本文の呼び名を「選ぶ画面」「受取までの体験」の2種類に揃える。機能を増やさず名前を揃える。

別ページへ移動したあと、最初の目的を見失わないかを初めて使う人に確認する。

優先 3

購入前の問い合わせ先を、購入ボタンの近くにも置く

確認した事実：購入先はBOOTH。問い合わせのリンクはページ末尾にあり、BOOTHの会話ページへ進む。購入欄にはPC環境確認の案内がある。

理由：HTMLを開けるか判断がつかない人は、購入前の確認をしたい可能性がある。これは利用者への仮説であり、実際の問い合わせから未検証。

具体案：購入欄の下へ「相手のPCで使えるか迷ったら、購入前に相談してください」を置き、既存の連絡先へつなぐ。

問い合わせには端末・共有方法だけを聞き、写真原本やパスワードを求めない。対応した実相談と購入は別に数える。

納品後に確かめること

  • 変更前後の同じ期間の訪問数と入口クリックを比較する。
  • 初めて使う人が、相手とのファイル往復を完了できるかを見る。
  • クリック数から購入数を推測せず、実注文と受取額を確認する。

この点検には修正作業・広告運用・セキュリティ監査・法令適合の判定は含みません。

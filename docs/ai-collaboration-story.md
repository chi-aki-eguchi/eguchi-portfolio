## 第1章 はじまり — Runable（〜2026年6月16日）

【秋さん】そもそもなぜ自分のサイトを作ろうと思ったのか。それまでのポートフォリオは
どうしていたか。Runable をどこで知ったか。

最初の最初は Runable だった。会話するだけでサイトの形になり、公開までできた。
「写真が主役・余白主導」という今も変わらないサイトの骨格は、この時期に生まれた。

ただし限界もすぐ来た。生成されたサイトには「Made with Runable」の透かしが入り、
細かい調整は思い通りにならない。

## 第2章 引っ越し — コードを自分の手に（6月16日〜17日）

Runable が作ったコードを取り出し、git（変更履歴をぜんぶ残す仕組み）で自分の
リポジトリにして、公開先を Railway に移した。透かしと計測タグを外し、
名実ともに自分のサイトになった。

振り返るとここが全ての分岐点だった。コードが手元にあれば、どの AI とでも
作業できるし、サービスが一つ終わってもサイトは残る。

【秋さん】引っ越しを決めた瞬間のこと。不安はあったか。

## 第3章 Claude Code — 夜中に働く相棒（6月17日〜）

実装役として Claude Code が来た。初日の夜、寝ている間に SEO・表示速度・
使いやすさなど21件を一人で直していた（「夜間自走」の始まり）。ブラウザを
自動操作するテストでサイトを3周させ、バグを掃討した日もこの頃。

この1日だけでコミット（保存された変更のまとまり）が22件。人間の手は
1行もコードを書いていない。

## 第4章 Codex がやってくる — AI が2体に（6月18日〜）

OpenAI の Codex が参加。最初は Codex にも実装をさせていたが、2体が同じ
ファイルを触って壊し合う事故と混乱を経て、役割を分けることになる
（実装=Claude、レビュー=Codex。正式に固定したのは7月8日）。
2体は agmsg という仕組みで人間を介さず直接やり取りする。

人間のチームと同じだった。担当を分けるまで、平和は来なかった。

【秋さん】2体が揉めていた（壊し合っていた）時期に何を見て、どう感じたか。

## 第5章 ルールの発明 — 「完了」を定義する（6月末〜7月5日）

この物語で一番効いた発明は、技術ではなくルールだった。

- 「できました」を信じない。型チェック→テスト→ビルドを全部通す1本の
  コマンドに合格して初めて完了（完了の定義）
- 本番反映のボタン（push）は人間だけが押す（7月5日に確立）
- 作業の終わりに必ず引き継ぎ書（Handoff）を書き残す。AI が代わっても続きから始められる
- 「これだけは絶対守る」の一覧（§0 invariants）を全 AI に毎回読ませる

ルールを会話で伝えるのをやめ、全部ファイルに書いた。AI は会話を忘れるが、
ファイルは毎回読む。事故はここから激減した。

## 第6章 サイトが商品になる — Portfolio Kit（6月20日〜7月16日）

「ボタン1つで同じサイトが立つ」配布版を作り始めたのが6月20日。
非エンジニア向けの手順書、決済リンク、販売ページ、壊しても大丈夫な
体験用デモ管理画面。1ヶ月かけて、自分のサイトが売り物になった。

自分のために作ったものは、手順書とデモを付ければ商品になる。
そして手順書もデモも、AI に作らせれば早い。

最初の購入者・利用者としては Ryo さんのサイトが動いている。

【秋さん】最初に「これは売れるかもしれない」と思った瞬間。

## 第7章 いま、そしてここから（7月16日〜）

この記録を書いている時点で、始まりからちょうど1ヶ月。

- コミット 409件。人間が書いたコードは、ほぼゼロ

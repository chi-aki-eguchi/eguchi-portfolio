## 1. 検索とSNSでの見つかりやすさ（SEO/SNS）

**SEO** = 検索エンジン（Google など）で見つかりやすくするための整備のこと。

### 現状（土台はすでに良い）

- sitemap.xml（検索エンジン向けのページ一覧）は写真画像込みで自動生成済み
- robots.txt / OGP（SNS共有時のプレビュー画像・文言）/ JSON-LD（検索エンジン向けのページ説明ラベル）も実装済み
- つまり「技術的なSEO」はほぼ完了していて、足りないのは **言葉と運用**

### やること（順番どおり）

1. **Google Search Console 登録**（無料。検索での表示回数・検索語が見える管理画面）
   — オーナー作業10分。どの言葉で見つかっているかが分かって初めて次が打てる
2. **シリーズごとのステートメント（2〜3行の説明文）を書く**
   — 検索エンジンは文章を手がかりにする。写真だけのページは見つけてもらいにくい。
   既存の series 説明欄に入れるだけでコード変更不要
3. **狙う言葉3つ（2026-07-16 決定）**:
   - 「写真家 ポートフォリオ」（オーナー指定。※「ポートフォリオ」単体は競合が
     広すぎるため「写真家」を添えて狙う)
   - 「台湾 写真家」（オーナー指定）
   - 「台湾 ポートレート 撮影」（AI 提案。依頼意図のある人が使う言葉）
   これらをプロフィール・シリーズ説明・ページ title に自然に織り込む。
   **補足**: 「台湾」を軸にするなら、英語より **繁体字中国語の一言導線**
   （プロフィールと問い合わせに1〜2行）の方が効く可能性が高い。§2 と合わせて検討
4. **SNS運用の型を作る**: 新シリーズ公開時に「OGP付きリンク + 一言」を投稿する、を習慣化。
   docs/sns-announcement.md の型を流用

### 秋さんが決めること

- ~~狙う言葉3つ~~ → 決定済み（上記）。残りは Search Console 登録の実施のみ

## 4. コンシェルジュの3段価格（全込みコース新設）

> **2026-07-18 決定（この節の3段案は中止）**: プランは **「公開おまかせ」¥30,000 のみ**に
> 一本化。A（自分で立てる ¥10,000）は廃止、C（全込み ¥50,000）は新設しない。
> 新しい B は「ドメイン取得サポート（本人名義・実費別）+ 接続 + 公開した状態で納品。
> 写真は購入者が admin から入れる」。理由: ①設置リンクを購入者に渡す唯一のプランを
> なくし、リンク再利用リスクを断つ（リポジトリはPUBLICでコード自体は元々取得可能。
> 売り物は設置・サポート・更新） ②相談無制限を全プランに付けた結果、サポートが
> 最も重いのはセルフ購入者で ¥10,000 では割に合わない ③販売ページが1プランになり
> 説明が明快になる。実装は 2026-07-18 のLP・/start・docs一括改訂を参照。

### 旧・現状の2コース（〜2026-07-18、記録として保持）

- A. 自分で立てる — ¥10,000（手順書つきテンプレート）
- B. おまかせ設定 — ¥30,000（初期設定の代行）

### 提案: C. 全込みコース を追加して3段にする

**C に含めるもの**: B の内容 + 独自ドメイン（akieguchi.com のような自分の住所となる URL）の
取得サポート + ドメイン接続設定 + 初回の写真アップロード代行 + **相談無制限（当面）**

- 相談: **全プラン（A/B/C）とも当面は期間・回数無制限**（2026-07-16 オーナー決定。
  初期はバグも多い前提のため）。LP・スタートページ・メール文面・運用手順に反映済み。
  将来期間制に変える可能性があるので、販売文では必ず「当面は」を添える
- 写真アップロード代行の範囲: 枚数上限は撤廃せず「目安50枚・**どの写真を載せるかの
  選定は購入者**」を推奨（理由: 時間がかかるのは選定・タイトル付け・並び決めであって、
  アップロード作業自体ではない。選定まで引き受けると1件が重くなりすぎる）→ 要オーナー確認

**価格（2026-07-16 決定）**: **¥50,000 + ドメイン実費（年1,500〜2,000円程度・購入者負担）**。
A:B:C = 1:3:5 の比率で「真ん中(B)を選ばせる」価格設計としても機能する。
ドメイン実費が別である旨は販売ページに必ず明記する。

**運用上の注意（重要）**: ドメインは **購入者本人の名義・本人のアカウントで取得してもらう**。
秋さんのアカウントで代理取得すると、解約・移管・更新料の管理がずっと秋さんに残ってしまう。
「画面共有しながら一緒に取得する（30分）」を C の provided 内容として明記するのが安全。

### 秋さんが決めること

- ~~C の価格~~ → **¥50,000 に決定**。~~相談期間~~ → **当面無制限に決定**（2026-07-16）
- 残り1点: 写真代行の範囲は「目安50枚・選定は購入者」案でよいか
- 決まり次第の実装タスク: 販売ページ・スタートページ・運用手順書
  （docs/portfolio-kit-operations.md）への C コース反映

## 5. プリント販売の土台

### 方針: 小さく検証する。全カタログ販売はしない

1. **第0段階（仕組みなし・今すぐ可能）**: 1シリーズから3〜5点を選び、
   Stripe Payment Link（決済ページを1枚作るだけの仕組み。コード不要）で販売。
   サイト側は該当シリーズページに「Prints available — お問い合わせ」の一文を足すだけ
2. **決めておくこと（販売前に必須）**:
   - サイズと価格（例: A4 / A3 の2種)
   - エディション（限定◯部にするか、オープンにするか）
   - 印刷方法（自宅プリント / ラボ発注）と発送方法・送料
   - 納期の約束（Kit と同じく「◯日以内」の型を流用）
3. **第1段階（反応があったら）**: photos テーブルに「販売中」フラグを足して
   サイト上に購入導線を常設。**ここは DB 変更を伴うので反応を見てから**

### 秋さんが決めること

- 最初に売るシリーズと3〜5点の選定、サイズ・価格・エディション
- 印刷と発送の体制（ここが一番の実務）

# 省トークン型 Codex 連携ワークフロー(2026-07-15 オーナー指示)

対象: 役割反転体制(実装=Codex / Claude=司令塔・リスク別レビュー)の全セッション。
AGENTS.md「期間限定の役割反転」の運用詳細。旧来の「毎回全差分精読・ゲート二重実行」を廃止する。

## 基本フロー

1. Claudeが要望を整理し、**一括指示**を作る(下の依頼形式)
2. Codexが実装→テスト→自己修正→再テスト→**commitまで**自律完了
3. Codexが**短い完了報告**(下の報告形式)を返す
4. Claudeがリスク階層に応じた深さでだけレビューする
5. 問題なければ完了。push前の区切りで**バッチゲート1回**(check+smoke)
6. タスク完了時に task.md へ短い引き継ぎ(完了/現状/残問題/次/制約/commit)

## Codexへの依頼形式(一括・往復しない)

毎回この9項目を含める。軽微な確認のためにClaudeへ戻らず、自己修正して完了まで進むこと。

```
目的 / 背景 / 変更対象 / 実装内容 / 制約(§0他) / 実行するテスト /
失敗時の修正方針(自力で直す範囲) / 完了条件 / 最終報告の形式(下記)
```

- 実装方法・関数名は指定しない(ゴール+境界のみ)
- commitはCodexが行う(メッセージ規約: conventional commits + 実装者明記)
- **pushは含めない**(オーナーのみ。変更する場合はオーナーの明示指示が要る)

## Codexからの報告形式(これ以外を返さない)

```
1. 変更ファイル一覧(パスのみ)
2. 変更内容の要約(5行以内)
3. 実行したテストと結果(数字のみ: 例 check 422 pass / smoke 31 pass)
4. 未解決事項(なければ「なし」)
5. リスクのある変更(該当箇所のパス:行 + 1行説明。なければ「なし」)
6. Claudeに確認してほしい箇所(最大3点)
7. commit hash
```

返さないもの: 全実行ログ / 全ターミナル出力 / ファイル全文 / 巨大diff /
問題ないコードの説明 / 同じ情報の繰り返し。diffが必要な場合は重要部分のみ抜粋。
agmsgへの二重報告は不要(execの最終報告に一本化)。

## Claude側の読み込みルール

- リポジトリ全体を読み直さない。Codexの報告→不明点のあるファイルだけ読む
- 確認済み情報を再取得しない。長いログを読み直さない
- **ゲートを二重実行しない**: Codexの報告数字を信頼する。Claudeが自分で回すのは
  「push前バッチゲート1回」と「高リスク変更の検証実験」だけ
- watchdogは維持(ハング検出)だが、進捗ポーリングでファイルを読まない

## リスク階層とレビュー深さ

**低リスク**(文言/スタイル/軽微UI/説明追加/影響のない整理):
報告+テスト数字の確認のみ。差分は読まない。UI変更はスクショ1枚で目視。

**中リスク**(ルーティング/設定キー追加/公開ページ構造/OGP):
報告+該当ファイルの変更部分だけ読む(git diff --stat → 対象を絞る)。

**高リスク**(認証/決済/DB/削除/スキーマ/環境変数/書き込みAPI/デプロイ設定/
セキュリティ/既存データに影響する処理):
従来どおり詳細レビュー+必要なら反証実験(例: T-6のフォント検証)。

## セッション運用

- 1セッションに積み上げない。タスク群の区切りで task.md に短い引き継ぎを書き、
  新しいセッションで再開する(過去ログを持ち込まない)
- 引き継ぎは6項目のみ: 完了したこと / 現在の状態 / 残っている問題 / 次に行うこと /
  重要な制約 / 必要なcommit情報

## 品質を守るために残す工程(削らない)

- §0 invariants は全依頼文に含め、報告の「リスクのある変更」で自己申告させる
- push前バッチゲート(check+smoke をClaude側で1回)
- 高リスク差分のClaude詳細レビュー(実験による反証を含む)
- UI/文言はスクショによるオーナー目視
- 決定ログ・Handoff(短縮形)

## 既存ルールとの関係

- §0 invariants / autonomy-rules / file-hygiene は全て従来どおり
- push は引き続き**オーナーのみ**(本書はオーナー指示の「commitまでCodex」を採用。
  push委譲はオーナーの明示確認があるまで行わない)

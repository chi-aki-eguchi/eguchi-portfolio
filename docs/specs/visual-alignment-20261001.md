## 写真ビューアの「チカッ」（2026-10-04）

オーナー「写真を押して拡大したときに、一瞬チカッとする。そういうのを全体から探して直したい」。

本番（build 15be493d）で、写真を押して開く・次へ送る・閉じるを動画に撮り、同時に画面の中で1コマごとに
壁の色・各層の濃さ・運んでいる影の位置を記録した（PC 1440×900・スマホ 390×844、Chromium・WebKit、
Gallery・作品ページ・トップ、動きを減らす設定あり／なし、頁の途中から開く場合）。原因は4つあった。

1. **裏の薄い黒い幕。** ブラウザは `<dialog>` の裏に既定で黒の10%の幕（`::backdrop`）を敷く。壁の色は
   ビューア自身が透明から濃くしていくのに、その裏でこの幕だけが開いた瞬間に一気に掛かり、閉じ終わる
   瞬間に一気に外れていた。頁全体の明るさが 134 → 121 と1コマで1割落ち、閉じる最後に 121 → 134 と
   跳ねて戻る（全エンジン）。→ 幕を透明に。
2. **着いた直後に写真が白く抜ける。** 押した写真の影が着くと、0.26秒で影を消して本物と入れ替える。
   ところが本物の側は、高精細の写真が読めても 1.1 秒かけて濃くなる途中（着いた時点で4割弱）で、その下の
   下敷き（「一覧で読み込み済みだから即座に出る」前提の1枚）は一覧と違う大きさの候補を後回しで頼んでいて、
   届くのは開いてから約1.1秒後だった。暗い写真の真ん中の明るさが 54 → 106 → 53 と、着いた直後に
   0.5秒ほど白っぽく抜けていた。→ 下敷きを「頁に出ていた画像そのもの」にした（押した1枚は必ず、送った
   先も頁に出ていれば）。影が消えても下に同じ絵がある。
3. **次の写真へ送ると、一度まっ白になる。** 前の写真をその場で消してから新しい写真を浮かべていたので、
   送った次のコマは画面全体が壁の色（明るさ 255）だけだった。→ 前の写真を1枚の絵に写し取って残し、
   新しい写真の上で 0.22 秒かけて薄れさせる。新しい `<img>` を作り直す方法だと、ブラウザの手元に画像が
   残っていないとき取り寄せ直しになり、その間が白く見える（検査で 0.16 秒）ので、写し取りにした。
   閉じるときの影も同じ作りにした。薄れる時間は、新しい写真が濃くなる時間と揃える（0.3秒にすると、
   溶ける途中の絵で約0.2秒止まってから切り替わって見えた）。
4. **「動きを減らす」設定のとき、開くたびに 0.12 秒まっ白。** この設定では動きの長さを 0.01ms に縮めるが、
   写真の側に付いている 0.12 秒の「遅れ」は縮まらない。壁（白）だけが先に出て写真が無い時間ができていた。
   送るときも「消して次のコマで出す」ので1コマ白くなっていた。→ 壁と写真を一緒に、濃淡だけで出す。
   送るときは入れ替えるだけにした。

合わせて、札（題名・説明）の高さを描く前に測るようにした（札の高さが違う写真へ送ったとき、前の写真の札の
高さのまま1コマ描いてから大きさが変わるのを防ぐ。本番の写真には今は札が無く、実害は出ていなかった）。

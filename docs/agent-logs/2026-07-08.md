# セッション4: オーナー報告の不具合3件+管理画面の密度改善

Driver: Claude Code (Fable5)。出典: オーナーからの本番スクショ付き報告(2026-07-08)。

## Phase 1: トップページのヒーロー文字見切れ(公開側・不具合) — 完了

- **症状**: サイトに入った瞬間、ヒーロー下部の名前・「Photography」等の文字が画面下端で切れる。
- **診断**: 本番 site_settings を読み取り専用で確認 → `heroMode=single` / `heroDisplayMode=fullscreen`
  / `heroScrollEffect=sink` / `heroSubtitle="Photography"`。つまり本番は `.hero-fullscreen .hero-single`
  (styles.css) の経路。このCSSは `height: 100svh` としていたが、`Layout.tsx` の `<main>` に
  `paddingTop: calc(3.5rem + var(--sai-top))`(固定ヘッダー分のオフセット)があるため、
  ヒーローが100svh丸ごと占有しつつ開始位置がヘッダー分下にずれ、結果としてヒーロー下端
  (キャプション文字がある場所)がビューポート下端をヘッダーの高さ分だけ突き抜けていた。
  ヘッダーは半透明オーバーレイではなく常に不透明背景(`bg-[var(--background)]`)なので、
  ヒーローに重ねる設計ではなく「ヘッダー分を差し引いた残りの1画面」が正しい高さ。
- **選んだ方針**: `--header-h: 3.5rem` を styles.css の `:root` に追加し、単一のソースオブトゥルースに。
  `.hero-fullscreen .hero-single, .hero-fullscreen .hero-carousel-contain` の height/min-height を
  `calc(100svh - var(--header-h) - var(--sai-top))` に変更。`Layout.tsx` の paddingTop も同じ変数を
  参照するよう統一(値は変えていないので他ページの見た目に影響なし)。ついでに `heroMode=immersive`

  DateTimeOriginalで書き込むのが一般的なため、パターンBの正しい挙動は壊さない。

## Phase 3: Lightbox「画像を読み込めませんでした」(間欠・不具合) — 完了

- **症状**: 写真を順に見ていると時々読み込みに失敗する(11/48の例)。リロードで直ることがある。
- **診断**: Lightboxの表示画像(Stage3, 実際に見えている本体)は `photo.mediumUrl`

  仕組みがR2読み取りには無かった)。失敗時はサーバが問答無用で404を返し、
  ブラウザの`onError`が発火してエラー文言のまま固定(リロード=再リクエストでしか
  回復しない、というオーナー報告の挙動と一致)。
  Lightboxは1回のナビゲーションで近傍6枚を先読みするため(`preloadNearbyLightboxPhotos`)、
  素早く連続ナビゲーションすると同時多発的にR2フェッチが走り、単発の
  ネットワーク瞬断の影響を受けやすい状況だったと判断。
  補足調査: 別容疑だった「オンザフライ変換の同時実行数(`MAX_ACTIVE_IMAGE_TRANSFORMS`,

     リトライしても直らない)は即座に諦める。それ以外(タイムアウト・接続エラー等)
     のみ1回だけ再試行。
  2. クライアント(`Lightbox.tsx`): Stage3の本体画像`onError`で**自動2回リトライ**
     (500ms→1000msの間隔、キャッシュバスティング用に`?retry=N`をURLへ付与)。
     2回失敗しても直らなければ、従来のエラー文言に加えて**「再読み込み」ボタン**を表示。
     Lightboxの開閉・ズーム・自動退避・先読みロジックには一切触れていない。
- **検証**: `bun run check`成功(tsc -b / lint / test / build)。Playwright実ブラウザで
  2系統確認:
  - 失敗系(`scratch/bugfix-2026-07/lightbox-retry-test.mjs`): 存在しないR2キーを
    持つ写真で本物の404を発生させ、初回+自動リトライ2回=最低3リクエスト発生→
    「再読み込み」ボタン表示→クリックで新規リクエスト発生、を実測(全アサーション合格)。
  - 回帰確認(`scratch/bugfix-2026-07/lightbox-regression-test.mjs`): 本番DB参照・
    読み取り専用devサーバで実写真を使い、開く→エラー文言/再読み込みボタンが出ない

    (全アサーション合格)。本番データへの書き込みは一切なし。
- **要相談**: なし(根本原因はコードから高い確度で特定・修正。完全な再現実験

  断言はできないが、単発失敗を許容するリトライを両層に入れたことで
  少なくとも「リロードでしか直らない」状態は解消している)

# 見つける・見る・作家を知る・相談する（2026-09-19）

初めて来た人が作品を見つけ、十分に見て、気になった作品について相談できるようにする。
同時に、オーナーがその状態を少ない操作で保てるようにする。

この文書は**実装済みの判断**と、**判断しなかったこと**を残す。数字はすべて
2026-09-19 の実測で、測り方も併記する。古い計画として再適用しない。

### この測定で**やらないと決めた**こと

- **Top に「さらに見る」を足さない。** 「写真を見進めるほど次の入口が下へ動く」
  という仮説は、現在の設定では起きていなかった。Top は4画面で終わり、Series の帯も
  Work へのリンクも読み切る前に出る。根拠の無い操作を足さない。
- **Contact のラベル（Name / Email / Send…）を日本語にしない。** サイト全体が
  英語の小見出しで揃えてある意匠で、迷いを生んでいたのはラベルではなかった。
- **件名の選択肢を書き換えない。**「テンプレートについて」は 2026-07-08 に承認
  された需要の計測用で、変えると測っているものが変わる。オーナーの判断事項として残す。

## A. 4つの場所の役割

| 場所 | ここで知ること | 次の自然な行動 |
|---|---|---|
| Top | 作風と作品の幅 | 気になった1枚を開く／棚へ進む |
| Series・Work | ひとまとまりを深く見る | 次の作品・作家・相談 |
| About | 作品と作家が結びつく | 相談・note |
| Contact | 何をどう頼めるか | 書いて送る |

**直した穴**: Top とギャラリーは対応表を `/api/series`（Series 棚だけ）で作り、
ビューアのキャプションは行き先を `/series/<slug>` と決め打ちにしていた。サーバーは
棚の違うURLを404で返す（`/series/rintaro` は 404、`/work/rintaro` は 200）。
結果、**公開写真133枚のうち Work 棚の101枚（76%）が、拡大しても作品名もリンクも
持たなかった**。初見の人が最初に通る道が、ちょうど数の多いほうで途切れていた。
→ `web/lib/series-links.ts` と `hooks/useSeriesLinks.ts`。両方の棚から
id →「名前と行き先」を作る。鍵は既存の `["series"]` / `["works"]` で通信は増えない。

## B. 関係と流れ

- 章立て機能・自動分類・時系列化はしない。順序は既存のまま。
- 作品名だけでは分からない背景（subtitle / statement）は**1件も入力が無い**ので、
  こちらでは作らない。**未確認事項としてオーナーに残す**（下の「残したこと」）。
- About の Journal の抜粋が語の途中で切れていた（3件中2件、「どうしてもﾊｯｾﾙﾌ」）。
  120文字で機械的に切っていたのをやめ、句点で止める。作者の文は書き換えない。
  → `api/note-rss.ts` の `trimExcerpt`。

## C. 写真の編集（Top に出す写真）

以前の `TopWorksPicker` は候補の格子が1つあるだけで、**選んだ写真の並びを順に読む
場所も、並べ替える手段も無かった**。番号の札は候補の中に散らばっていた。

- 上に「選んだ順」（実写真つきの番号順の一覧・前へ／後ろへ／外す）、下に「候補から選ぶ」。
- ドラッグには頼らない。PC・タッチ・キーボードで同じ操作。動かしたあとも同じ操作の
  上にフォーカスが残るので連打で並べ替えられる。タッチでは当たり判定を40pxへ。
- 1操作＝1回の取り消し。`set` は同じキーの連続変更を500msでまとめるので、写真を
  続けて押すと ⌘Z で何枚ぶんも戻っていた（`history.apply` を使う）。
- この節を開くとプレビューは Gallery を映すが、トップにしか出ない3つの設定を触ったら
  プレビューをトップへ向ける。**選んでも何も変わらない画面を見せない。**
- 選択に残った未公開・削除済みの写真を「いま公開されていません」として見せ、外せる
  ようにする（公開側は前からこの ID を黙って飛ばしていた）。
- 並びの読み方は `web/lib/top-works-ids.ts` に1つだけ置き、公開側の `top.tsx` も同じ
  規則を読む。編集するのは `topWorksIds` の並びだけで、写真一覧の掲載順も原本も変えない。

## D. 撮影の相談と Portfolio Kit

- 表示・導線・ガードはそのまま（`StudioBridge` の持ち主判定を含む）。価格・サポート
  条件・顧客向け表示は変更していない。
- 区別したのは**書いてもらう内容だけ**。件名が Portfolio Kit の相談のときは、本文欄の
  案内を「いまのサイト・写真の枚数・公開したい時期」に切り替える。欄も必須項目も
  増やさない（`shared/contact-defaults.ts` の `isPortfolioKitSubject`）。

## E. 迷いの確認（自己検証・実ユーザーテストではない）

隔離環境（一時SQLite・人工データ・127.0.0.1の偽ストレージ）で、変更前後に同じ操作を
した。記録は `scripts/smoke/public-site.spec.ts` と
`scripts/smoke/admin-top-works-picker.spec.ts` に残した（人が読む手順ではなく、
次に壊れたら落ちる形で残す）。

1. 初見の鑑賞者: Top → 写真を開く → その作品へ → 戻る。**Work 棚の写真で行き先が
   無かったのを直した。**
2. 撮影を検討する人: Work → 導入のすぐ下の相談リンク → 参考作品つき Contact →
   参考作品を外す → 送信（モック）。
3. 更新する本人: 12枚を選択 → 8枚目を2番目へ → 1枚を外す → 取り消す →
   PC/スマホのプレビュー → 保存。写真一覧の並びと原本は変わらない。

計測は既存の `contact_submit_start` / `contact_submit_success` のまま。新しいイベントも
ダッシュボードも足していない。クエリ（`?work=<slug>`）はアクセス解析に渡らない
（`shared/analytics-path.ts` が落とす）。**問い合わせが増えたかどうかは未測定。**

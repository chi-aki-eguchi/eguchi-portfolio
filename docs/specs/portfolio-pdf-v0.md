# PDF作品集 v0 — 管理画面内の試作

2026-09-27。依頼元は `portfolio-kit-web-pdf-v0-spec.md` のA段階。
ローカルブランチ `codex/portfolio-pdf`。本番へのpush・デプロイはこの作業に含めない。

## 使い方

このcheckoutで `bun install --frozen-lockfile` → `bun run try:pdf`。
`http://localhost:5499/admin/pdf` を開き、起動時に表示する一時パスワードでログインする。
既存の隔離サーバーを使い、人工画像・一時SQLite・localhostの偽ストレージのみ。本番DB・`.env`には接続しない。
別途、通常の認証済み管理画面の「PDF作品集」からも入れる。デモの認証を迂回しない。

1. 既存画像を最大20枚選ぶ。本の名前・氏名・任意の表紙写真を指定。
2. ページの前後移動、次の1枚との2枚組、分割、2枚の交換、90度回転を編集。
3. 本専用の制作年・技法・説明・プロフィール・連絡先を入力する。
4. A4縦／横を選択。送信用／印刷用を生成し、PDFの全ページを確認して保存。

ブラウザー保存は明示操作。30冊まで。JSONの書き出し／読み戻し（別の本として取り込み）に対応。
ページ構成・文字・参照・回転・テンプレート版を保存し、画像本体は保存しない。
ブラウザー保存は暗号化されない。OSやブラウザープロファイルを共有する人から守る仕組みではない。
端末間同期なし。ブラウザー消去で失われる。同じサイトの写真が必要で、別サイトへ画像を移送する形式ではない。
この本／全冊の保存データを消去できる。ダウンロードしたJSON・PDFは利用者が別途管理する。

## 実装と品質

- `/api/admin/pdf/photos` と `/photos/:id/image` は既存の管理セッション必須、GETだけ。
- 保存画像はDBの現在の参照から取得し、任意URLの取り込みはしない。削除・参照変更を検出して停止。
- 保存元の `photos/...` を利用。元RAW取得を保証しない。既存保存は長辺3200px以内の最適化画像。
- 送信用は長辺1600px・JPEG品質78、印刷用は3200px以内・品質95。アップスケールなし。
- SharpでEXIF等を除去しsRGBへ変換。実際にPDFへ埋め込む画素数と掲載寸法からdpiを計算。200dpi未満を注意表示。
- pdf-lib 1.17.1 / @pdf-lib/fontkit 1.1.1 をWorkerで実行。画像は直列取得、組版中の進捗、中止、タイムアウト、再試行に対応。
- 日本語は静的Noto Sans JP RegularをOFL1.1で同梱しサブセット埋め込み。字形不足・テキスト枠超過はPDFを返さずページを通知。
- ページ数とBlobの実バイト数を表示。編集後は古い生成結果を閉じて誤保存を防ぐ。保存済みPDFは書き換えない。
- 余白15mm、本文10.5pt、写真全体表示、ページ番号。表紙は24pt、プロフィール見出し18pt。
- 生成器はReactや管理画面に依存せず、文書モデルとバイト列を受け取る。@react-pdf/rendererは追加しなかった。固定2テンプレートでは実寸・はみ出し検査を同じ組版処理で管理する方式を選んだ。
- 認証・課金設定、公開ナビ、写真の公開状態・sortOrder・seriesId、プロフィール、DBスキーマは変更しない。

## 検証

単体はモデル往復・分離・不正ファイル・画像比率と回転・実PDFの縦横寸法・文字欠落・長文・欠落画像。
`admin-pdf.spec.ts` は実際の認証、未認証拒否、ブラウザー保存／読み戻し、Worker出力、ダウンロードの容量、Webの前後一致、失敗表示、20枚の応答性を検査。
詳細な実行結果は `task.md` に記録。

ローカル `output/pdf/` の見本は、既存の公開写真12枚を読み取り、13ページとして生成したもの。Gitには含めない。
`portfolio-screen.pdf`、`portfolio-print.pdf`、`portfolio-landscape.pdf`。
縦・横・正方形・回転の人工画像は `portfolio-layout-proof.pdf`。
全ページをPopplerで画像化し、日本語をpypdfで抽出して確認する。

紙に印刷した際の読みやすさ、応募先の個別要件、実機スマートフォン、本番の認証付き実画像出力、PostgreSQL実接続は未確認。

### 2026-09-27 の見本・読み取り境界の実測

- 実写真12枚／13ページ。送信用3,632,669 bytes、印刷用28,235,779 bytes、横A4印刷用28,235,815 bytes。全ページを画像化し、日本語の抽出と画像にEXIFがないことを確認。
- Chromeの画面操作で同じ12枚を送信用PDFに生成：2,439ms（ローカル・単発測定）。一般端末の速度保証ではない。
- 認証前は一覧／画像とも401＋no-store、欠落IDは404。確認用の非公開画像は認証後にPDFへ取得でき、公開写真一覧へは出ない。既存のストレージ公開方式全体の監査を意味しない。
- 日本語ファイル名の画像で、送信用1600×1280／278,304 bytes、印刷用3200×2560／2,404,874 bytes。EXIF・ICCなし。
- `bun run try:pdf` の通常起動は人工画像。今回開いている5499の確認環境だけに、公開写真12枚をコピーして非公開状態で追加している。再起動後は人工画像に戻る。
- 新機能smokeは3環境×4件＝12成功（2026-09-27）。人工画像20枚／22ページ：PC 910ms・スマホ幅407ms・WebKit 942ms。25msタイマーの最大間隔は31〜33ms。約0.40MBの人工画像による測定で、実写真20枚やスマートフォン実機の負荷を保証しない。

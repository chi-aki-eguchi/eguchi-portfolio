# 企画書 #07 — メール購読 / 再訪設計（自前オーディエンス）

状態: **提案（戦略 + 将来コード提案）** ／ 起案 2026-06-14 ／ 区分 C 寄り（要・継続コミット）

## 1. なぜ考えるか（と、向き不向き）
SNS はアルゴリズム依存で、フォロワーに必ず届くわけではない。**メールは「届く・所有できる」唯一のチャネル**で、
プリント発売・受注枠オープン・新シリーズ公開を**確実に再訪に変える**最強の資産。
ただし **本人が継続して送る意思がある場合のみ価値が出る**（月1でも）。送る気がないなら作らない方がよい——
これは正直に最初の判断材料として置く。

## 2. 何を送るか（写真家のニュースレター）
- 新シリーズ公開のお知らせ（サイトの /series へ）
- 制作の裏側・撮影記（note と連動 or 抜粋）
- **プリント発売 / 受注枠オープン**（#04 マネタイズの確実な告知経路）
- 不定期・少数で十分。**量より「届く濃いリスト」**。

## 3. 実装の選択肢（コスト順・提案のみ）
### 案A：外部サービス埋め込み（推奨・最小）
Buttondown / Substack / Mailchimp / ConvertKit 等の登録フォームをサイトに埋め込む。
- **メリット**：配信・到達率・配信停止・法対応(特商法/オプトアウト)を**全部サービス任せ**。バックエンド不要。
- サイト側はメールアドレス1フィールドのフォームを置くだけ（静かな editorial デザインで）。
- **将来コード**：Layout フッター or profile or InquiryCta 付近に控えめな登録欄。小さく安全。

### 案B：自前で取得（DBに保存）＋ 配信は外部
サイトは Turso/Drizfile を持つので `subscribers` テーブルに保存も可能。
- ただし**配信・到達率・解除管理を自前で持つのは負債**。配信は結局外部サービスが要る。
- 案Aで困ってから検討で十分。**初手は案A推奨。**

## 4. 置き場所（佇まいを壊さない）
- **ポップアップは使わない**（design-spec の静けさを毀損）。
- フッター or 各ページ末（InquiryCta の近く）に**1行＋メール入力**を静かに。
- コピー例：「新作・プリント発売のお知らせを、時々お送りします。」

## 5. note 有料メンバーシップとの関係
- **無料メール購読** = 広く薄く再訪を作る入口。
- **有料note**（#04）= 濃いファンの収益化。
- 両立可。メールで告知 → note(無料/有料) や サイトへ送る、という階段にする。

## 6. 計測
- 登録数・開封率（サービス側）。
- GA4 で登録完了イベント（将来コード提案・小）。

2. Yes なら外部サービスの希望（Substack=記事寄り / Buttondown=シンプル / Mailchimp=定番）。

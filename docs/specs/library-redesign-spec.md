## 1. なぜやるか（目的）

Library は、秋さんが**自分の写真を管理するために毎日使う道具**であり、同時に
**Portfolio Kit として販売している商品の一部**でもある（購入者も同じ管理画面を使う。
T-7 で Kit として再構成、T-9 で「はじめに」を購入者向けに作り直した）。
つまり Library の使い心地は、そのまま作者の作業効率であり、商品の価値でもある。

目指すのは、写真を大きく見せることでも、余白で作品性を出すことでもない
（2026-07-23 17:21 に、それらを中心概念から外す方針転換を行った）。目指すのは次の5つ。

1. **長時間やっても疲れない**
2. **迷わない**
3. **整理が速い**
4. **反応が気持ちいい**
5. **自分の道具として愛着が持てる**

### 解決したい今の問題

- 写真クリックが「単独選択」と「詳細表示」を兼ねており、意図しない方が起きる
- 検索が絞り込み欄の中に隠れていて、一番よく使う操作に手数がかかる
- 通常時の写真の上に回転・移動の操作が常に重なり、写真と操作が競合している
- デスクトップでは右の詳細欄と一括操作欄が同時に写真面を圧迫する
- スマートフォンではタッチだけで複数選択に入りにくい

**設計原則**: 「写真を主役にする」とは、写真を大きくすることではなく、
**写真と操作を競合させないこと**。

## 2. 承認済みの設計（2026-07-23）

### 2-1. 操作モードの分離（今回の実装対象）

同じ場所の操作内容を、モードで置き換える。

| モード | 写真をクリックすると | 出るもの |
| --- | --- | --- |
| **通常** | 詳細（インスペクタ）が開く | 詳細のみ。一括操作は出さない |
| **選択** | 選択・解除 | 選択ツールバーと一括操作。詳細は出さない |
| **並べる** | 何も開かない（並べ替えのみ） | 並べ替えツールバー。詳細も選択も出さない |

- 詳細を開いたまま選択へ切り替えた場合、**未編集なら詳細を閉じて0枚から始まる**
  （未保存の編集がある場合は既存の確認フローを維持する）
- **Shift+クリックの範囲選択は維持する**（高密度案から取り入れた高速操作）
- **Ctrl/Cmd+クリックは、詳細ではなく選択モードへの近道として維持する**
- 写真0枚のときは空状態を出し、選択・並べるを開始できないようにする
- 検索・絞り込み中は並べ替えをロックする（既存仕様の維持。ロック理由を `filters` として示す）

### 2-2. 配置と密度

- 検索・絞り込み・並び順・選択・追加・表示密度を、**固定位置から1回で使える**ようにする
  - **選択モード中も検索・絞り込みは残す**（2026-07-25 オーナー判断。「特定のカテゴリの
    写真をまとめて非公開にする」のように、探しながら選択を続ける操作が実際にあるため）。
    未実装。→ `docs/archive/task-queue.md` Q-12
  - 並べるモード中は出さない。絞り込み中の並べ替え禁止（§3）と衝突するため
- デスクトップ: **5列標準**（5〜7列の範囲で切替可能）
  - 2026-07-25 に実機確認し、6列標準から変更した。既定サムネイル220px で 1440px は5列になる。
    1枚が大きく見えるこちらをオーナーが採用。実装を変えるのではなく標準値の定義を実態へ合わせた
- スマートフォン: **2列標準**、3列へ即切替
- 写真詳細の出し方は画面幅で3段（2026-07-25 に境界を明文化）
  - **1280px以上**（1440px想定）: 一覧の**横に並べる**
  - **640〜1279px**（1024px想定）: 右から**重ねて**表示する（横に並べない）
  - **640px未満**（390px想定）: **下側シート**として全幅表示。全状態で2列を維持
  - 下2段はいずれも未実装。→ §5-2、Q-11

### 2-3. 反応の作り方

- 押した場所ですぐ反応を返す
- 成功・失敗は、共通の通知欄ではなく**操作した対象の近く**に返す
  - 絞り込み条件 → 検索付近
  - アップロード進捗 → 写真一覧の上部
  - 保存失敗 → 詳細欄の中
  - Undo → 写真一覧の上の一時通知
- 並べ替え時は移動先の隙間を開けて見せる
- **スクロール中は写真の拡大縮小・影・繰り返し動作を出さない。** 反応は停止後、
  または押した対象だけに限定する（疲れない・酔わないため）

## 3. 壊してはいけないもの

レイアウトを変えても、次は必ず維持する。

- 仮想スクロール（写真が多くても表示を軽く保つ仕組み）
- 絞り込み中の並べ替え禁止
- 未保存編集がある状態での確認ダイアログ
- 表（Table）表示の自動保存
- ゴミ箱の通知
- アップロード領域
- API・データ構造・保存処理は変更しない（情報の配置と反応だけを変える）

## 4. 今回の実装スコープに入れないもの

- スマートフォン3列でのタップ移動、長押しでの選択開始
  （誤操作とスクロール競合の危険があるため、初期実装の中心にしない）
- 「作業余白」を作者固有の構造として見せる案（2026-07-23 17:21 に中心概念から除外。
  必要最小限の区切りとしてのみ扱う）
- 視覚デザインの刷新（配色・書体・罫線）。今回は操作体験のみ

## 5-2. 既知の未達（2026-07-25）

写真詳細の出し方が、承認済み設計（§2-2）の3段構成に対して**1段しか実装されていない**。
現在の実装は `sm:`（640px）を境に「640px未満=右側の全高オーバーレイ / 640px以上=横に並べる」
の2段だけで、`admin.tsx` の該当箇所は次の3クラス文字列に集約されている。

- 背景の暗幕 `fixed inset-0 z-30 bg-black/30 sm:hidden`
- 詳細本体 `fixed inset-y-0 right-0 z-40 w-full max-w-xs shadow-2xl sm:static …`
- 詳細ヘッダ（×ボタン）`flex items-center justify-between px-3 pt-2 sm:hidden`

**未達1（390px・スマートフォン）**: 詳細が「下側シート」ではなく右側の全高オーバーレイになる。
そのため詳細を開くとモード切替ボタンが覆われ、通常/選択/並べるを切り替えられない。

2026-07-25 のオーナー判断で、モード分離（＝操作の分離）と詳細の出し方（＝別の設計項目）を
切り分け、**下側シートは次段の別タスク Q-11** とした。モード分離側は desktop で完成扱い。

smoke では `scripts/smoke/admin-library-modes.spec.ts` に
`test.fixme("スマホ幅で詳細を開いたままモード切替できる…")` を置いて追跡している。
Q-11 の完了条件に「この fixme を通常の test へ戻す」を含めてある。

**未達2（1024px・タブレット幅）**: 2026-07-25 の実ブラウザ確認で新たに判明。
1024px でも詳細が「重ねて表示」ではなく**横に並ぶ**ため、写真が5列から2列へ減る。
オーバーレイ化が `sm:`（640px）境界でしか起きておらず、640px以上はすべて 1440px と
同じ横並びになっている。モード切替は覆われないので機能上の欠陥ではなく、密度の欠陥。

未達1と未達2は同じ3クラス文字列を触るため、**Q-11 に両方を含める**（2026-07-25 オーナー判断）。
1280px以上（1440px を含む）の横並びは変えない。

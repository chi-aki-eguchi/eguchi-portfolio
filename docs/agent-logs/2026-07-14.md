  空値はCSSの既定値へ戻し、DB適用とライブプレビューで別の既定値を作っていない。

## タスク: smokeスイート修理 — admin-trash-signal がDB状態依存で落ちる問題

- **経緯**: push待ち17コミットの区切り確認として `bun run check`（全green・
  370テストpass）と `bun run smoke` を実行したところ、
  `admin-trash-signal.spec.ts` の1件だけが失敗した。
- **原因調査**: origin/main（push済みの本番相当コード）でも同一の失敗を再現。
  つまり**未pushの17コミットの回帰ではない**。失敗時のスナップショットでは
  Trash画面自体は正しく開いていた（「削除済み写真 —」バナー・Purge All・
  復元/完全削除ボタンが表示）。テストの検証文言「ゴミ箱」はTrash画面が
  **空のときの文言**（「ゴミ箱は空です…」）にしか存在せず、smokeが接続する
  本番DBのゴミ箱に現在32枚入っているため文言が出ず落ちていた。
  ＝テスト作成時はゴミ箱が空だった、というデータ依存の検証だった。
- **対応**: 検証を空/非空どちらでも通るマーカー正規表現
  （`/ゴミ箱は空です|削除済み写真 —/`）に変更。あわせて「Libraryへ戻ったら
  Trashが持ち越されない」側の検証も強化（ツールバー「絞り込み」はTrash表示中も
  出るため判別力がなく、マーカーの不在確認を追加）。機能コードは無変更。
  「原因を理解せず期待値を実測値に合わせる」行為ではなく、テストの意図
  （Trashが開くこと・持ち越されないこと）を保ったまま状態非依存にした。
- **検証**: 単体で再実行→pass。`bun run check` exit 0、`bun run smoke` exit 0
  （31 passed / 27 skipped / 0 failed）。
- **push**: していない（オーナーの手で行う）。

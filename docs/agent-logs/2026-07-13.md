- **発見したバグ(実測で確認・要件2「S/M/Lが実際に見て分かる大小差になるか厳しく確認」対応)**:
  行の目標高さが `base * Math.max(現在行の重み)` で決まる実装だったため、
  (a) S(重み0.8)はM/Lと同じ行に混ざると常に無効化される(max が M/L に張り付く)。
  (b) L(重み1.45)は登場位置によって効果が一貫しない — 既にM数枚分のratioを
  消費した後にLが来ると、新しい(高い)目標に対してovershootし、実測で
  「Lが入っているのに高さがM単独行と同じ(183.1px)」というケースを確認。
  ランダム構成500試行でL含有行の実測: 最悪218px/最良362.5px と、位置依存でばらついていた。
- **修正方針**: 「行は同じ表示サイズだけで構成する」よう強制break条件を追加
  (`weight !== current[0].weight` で新しい行を開始)。これにより連続する同一サイズのみが
  1行にまとまり、S/L は前後に何があっても必ず専用の行を得る。
  修正後、ランダム500試行で L含有行1510件すべてが M平均行より確実に大きい

## 追記: Codex push前レビューでP1発見・修正(commit 106f837後)

- **Codexの指摘(実測つき・自己検証済み)**: 上記の「強制break」修正
  (`weight !== current[0].weight` で行を区切る)は、S/M/Lを毎回確実に見せる代わりに
  **強制break後のcloseRowが常にnon-flush(non-stretch)** だったため、
  最終行でない行にも大きな空白が生じていた。containerWidth=976, 3:2写真の
  M,M,S,M,M構成で自己検証: 行0(非最終)がgap=216px、行1(非最終)がgap=676px
  ——`justified`の核となる定義(最終行以外は行幅ぴったり)に反する重大なバグ。
- **設計判断**: Option A(行組みの完全flush優先)を採用。理由:
  「justified」という名称/仕様自体が非最終行flushを前提とするため、これを
  崩すと別レイアウトになってしまう。S/M/Lは「行の目標高さへの強い影響」
  (保証ではない)へソフト化。
- **実装**: 強制break機構を撤去。ループ中はcloseRow(true)(flush)のみを呼び、
  配列末尾の余りだけがcloseRow(false)(非stretch)対象——構造上、非最終行が
  常にflushであることを保証する(個別チェックではなく、ループ中に非flush分岐が
  存在しないことで保証)。
  - lookback(直前アイテムを含める/除外するかを比較して閉じる案)も試作したが、
    2000試行のスイープでSの信頼性を悪化させる(lookback有: 44.8% → lookback無: 70.0%、
    Lは81.7%→87.7%とわずかに改善するのみ)ことが判明したため不採用、単純greedyを採用。
- **修正後の実測(2000試行スイープ)**: 非最終行のflush違反 0/13093件(完全ゼロ)。
  L含有行がM平均行より高い: 81.7%。S含有行がM平均行より低い: 70.0%
  (いずれも「毎回確実」ではなく「統計的に強い傾向」——非最終行flushの原則と
  数学的に両立しないため、これは受け入れた設計上のトレードオフ)。
